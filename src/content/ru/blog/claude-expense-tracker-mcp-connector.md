Самый безопасный первый диалог Claude с трекером расходов выглядит почти скучно. Claude выводит список рабочих пространств, проверяет актуальную схему и выполняет один запрос только для чтения. В журнале ничего не меняется.

Такое осторожное начало важно: позже тому же коннектору можно выдать право изменять финансовые данные. Доступ на чтение и запись лучше разделять, рабочее пространство — явно подтверждать, а результат каждого изменения — проверять сразу после выполнения.

Именно для такого сценария в Expense Budget Tracker есть готовый удаленный MCP-коннектор:

```text
https://mcp.expense-budget-tracker.com/mcp
```

Добавьте этот URL в Claude и пройдите OAuth-авторизацию в браузере. После этого Claude сможет работать с трекером через четыре инструмента с четко заданными возможностями. Терминал, API-ключ и локальный конфигурационный файл MCP не нужны.

## Здесь нужен коннектор, а не API для Claude Code

Expense Budget Tracker поддерживает два способа доступа для программ и ИИ-агентов. У каждого из них свои учетные данные, поэтому их легко перепутать.

| | Удаленный MCP-коннектор | Прямой Agent API |
|---|---|---|
| Лучше всего подходит для | Диалогов в Claude и Claude Desktop | Claude Code, Codex, скриптов и других агентов в терминале |
| Начальный URL | `https://mcp.expense-budget-tracker.com/mcp` | `https://api.expense-budget-tracker.com/v1/` |
| Аутентификация | OAuth в браузере | Долгоживущий `ApiKey` |
| Интерфейс | Инструменты MCP | HTTP-эндпоинты |
| Учетные данные | Токены доступа и обновления OAuth, которые хранит MCP-клиент | `ApiKey`, который хранится вне памяти чата |

Адрес MCP-коннектора не принимает `ApiKey` от прямого API. И наоборот: этот ключ нельзя превратить в пользовательский коннектор Claude. Это две отдельные интеграции с разными способами авторизации.

Это руководство подойдет, если вы хотите подключить трекер расходов к веб-версии Claude или Claude Desktop. Если задача начинается со слов «прочитай этот CSV с моего ноутбука», используйте терминальный сценарий из статьи [Как вести учет расходов и управлять бюджетом с помощью Claude Code](/blog/how-to-track-expenses-and-manage-your-budget-with-claude-code/). Более общее [руководство по настройке трекера расходов для ИИ](/blog/ai-agent-expense-tracker-claude-code-codex-openclaw/) описывает подключение Claude Code, Codex и OpenClaw через прямой API.

## Добавьте коннектор Expense Budget Tracker в Claude

В личном аккаунте Claude нужный раздел находится по пути **Customize > Connectors > Add custom connector**. Актуальный интерфейс и особенности разных типов аккаунтов Anthropic описывает в [руководстве по пользовательским удаленным MCP-коннекторам](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### 1. Добавьте URL удаленного MCP-сервера

Откройте Claude или Claude Desktop, а затем:

1. Перейдите в **Customize > Connectors**.
2. Нажмите кнопку **+** и выберите **Add custom connector**.
3. Назовите его `Expense Budget Tracker`.
4. Введите `https://mcp.expense-budget-tracker.com/mcp` в качестве URL удаленного MCP-сервера.
5. Нажмите **Add**.

Поля OAuth Client ID и Client Secret в дополнительных настройках заполнять не нужно. Сервер авторизации Expense Budget Tracker поддерживает динамическую регистрацию публичного OAuth-клиента, а такому клиенту секрет не требуется.

В аккаунтах Team и Enterprise пользовательский коннектор сначала должен добавить в организацию владелец с ролью Owner или Primary Owner. Затем каждый участник подключается под своей учетной записью и видит только доступные ему рабочие пространства.

### 2. Подключитесь и подтвердите доступ OAuth

Нажмите **Connect** рядом с новым коннектором. Claude автоматически найдет параметры авторизации MCP и откроет в браузере страницу входа в Expense Budget Tracker. Войдите в аккаунт и проверьте запрашиваемые разрешения.

У двух областей доступа разные назначения:

- Обязательная область `expenses:read` позволяет находить рабочие пространства, просматривать схему и выполнять запросы только для чтения.
- Необязательная область `expenses:write` разрешает использовать инструмент `sql_execute`, который изменяет данные.

Для проверки расходов, отчетов, сверки и анализа бюджета достаточно `expenses:read`. Добавляйте `expenses:write`, только когда Claude нужно добавить, обновить или удалить конкретные данные. Выдавать это разрешение «на всякий случай» незачем.

Не вставляйте токен OAuth в промпт. Браузер и хранилище учетных данных коннектора Claude сами работают с токенами доступа и обновления.

### 3. Включите коннектор в диалоге

После добавления коннектор не включается автоматически во всех чатах. В нужном диалоге откройте меню **+**, выберите **Connectors** и включите Expense Budget Tracker.

При работе с финансовыми данными такой переключатель особенно полезен. Оставляйте коннектор выключенным в остальных разговорах и включайте его только на время конкретной сессии по бюджету.

## Что Claude делает во время OAuth

Эти шаги не нужно выполнять вручную, но общее понимание процесса пригодится при поиске неполадок.

Удаленный коннектор публикует метаданные защищенного ресурса по адресу `https://mcp.expense-budget-tracker.com/.well-known/oauth-protected-resource/mcp`. Этот документ указывает Claude на метаданные сервера авторизации по адресу `https://auth.expense-budget-tracker.com/.well-known/oauth-authorization-server`.

Claude регистрируется как публичный OAuth-клиент, запускает в браузере сценарий Authorization Code и использует PKCE с методом проверки `S256`. После подтверждения Claude обменивает код на токены, а затем при необходимости обновляет токен доступа. Процесс соответствует [модели авторизации MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization), включая обнаружение защищенного ресурса и защиту кодов авторизации с помощью PKCE.

Пользователей Claude Desktop может удивить одна деталь: трафик удаленного коннектора идет не через локальный сетевой интерфейс настольного приложения. [По информации Anthropic, подключения к пользовательским удаленным MCP-серверам выполняются из ее облачной инфраструктуры](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), даже если вы работаете в Claude Desktop. Коннектор Expense Budget Tracker уже доступен через интернет. Чтобы Claude подключился к частному MCP-серверу на вашей инфраструктуре, сервер должен принимать соединения из облака Anthropic.

## Четыре инструмента, которые получает Claude

Коннектор предоставляет Claude четыре специализированных инструмента, а не неограниченный доступ к базе данных.

| Инструмент | Что он делает | Разрешение |
|---|---|---|
| `list_workspaces` | Показывает рабочие пространства, доступные текущему пользователю | `expenses:read` |
| `get_schema` | Возвращает доступные объекты базы и их столбцы для выбранного рабочего пространства | `expenses:read` |
| `sql_query` | Выполняет один ограниченный SQL-запрос только для чтения | `expenses:read` |
| `sql_execute` | Выполняет ограниченный SQL, который изменяет данные | `expenses:read` и `expenses:write` |

Для `sql_query` доступ на уровне базы данных ограничен чтением. Результат может содержать не более 100 строк, а на выполнение дается 20 секунд. Однако при наличии `sql_execute` коннектор в целом уже не ограничен чтением. Поэтому разрешение на запись требует отдельного внимания.

Сначала актуальная схема, потом SQL. Имена таблиц, столбцов и доступных объектов базы нужно получать из `get_schema`, а не из старого промпта, скопированного примера или воспоминаний Claude о другом финансовом приложении.

## Начните первую сессию в безопасном порядке

В первом промпте стоит попросить Claude установить контекст, прежде чем начинать анализ:

```text
Используй коннектор Expense Budget Tracker в режиме только для чтения.

Сначала вызови list_workspaces и покажи мне названия и идентификаторы доступных
рабочих пространств. Попроси меня подтвердить, какое пространство использовать,
даже если оно всего одно. Затем вызови get_schema для подтвержденного пространства.
Используй только sql_query. Пока не вызывай sql_execute и не предлагай никаких изменений.

Получив схему, сгруппируй мои расходы по категориям за текущий календарный месяц
и сравни их с предыдущим календарным месяцем. Используй агрегирующие запросы вместо
возврата каждой строки журнала. Покажи запрос и объясни все ограничения,
которые влияют на результат.
```

Порядок важен: сначала выберите рабочее пространство, затем проверьте его текущую схему и только после этого составляйте запрос. Если результат может превысить 100 строк, попросите Claude агрегировать данные в SQL или разбить задачу на несколько осмысленных периодов. Не нужно протаскивать весь журнал через чат. Лучше выполнить расчеты на уровне базы данных и вернуть только полезный результат.

## Что спросить в первой сессии с доступом только для чтения

После подтверждения рабочего пространства и проверки схемы Claude сможет не только показать последние покупки.

### Проведите ежемесячную проверку бюджета

```text
Используя только sql_query, сравни фактические доходы и расходы с бюджетом на этот
месяц. Сгруппируй разницу по категориям, поставь в начало самые большие абсолютные
отклонения и отдели отсутствующие данные бюджета от реального перерасхода. Не меняй
ни одной строки бюджета. Покажи использованный SQL.
```

Это диалоговая версия [ежемесячной проверки бюджета](/blog/how-to-do-a-monthly-budget-review/): сначала найдите расхождения и только затем решайте, что нужно изменить.

### Найдите возможные дубликаты расходов

```text
Используй актуальную схему и sql_query, чтобы найти возможные дубликаты расходов
за последние 45 дней. Сравни даты, суммы, валюты, счета и контрагентов там, где
такие поля существуют. Считай результаты кандидатами, а не подтвержденными
дубликатами. Ничего не удаляй и не обновляй.
```

Формулировка «кандидаты, а не подтвержденные дубликаты» здесь важна. Две одинаковые покупки кофе не обязательно появились из-за случайного повторного импорта.

### Подготовьте проверку для сверки

```text
Используй list_workspaces, подтверди мое личное рабочее пространство, проверь схему
и запроси балансы, доступные через коннектор. Объясни, какие записи журнала формируют
последний баланс. Не вноси исправлений. Я сам сравню результат с банковской выпиской.
```

Если баланс не совпадает с банковской выпиской, остановитесь и разберитесь в расхождении. В [сценарии сверки бюджета](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) объясняется, как отличить пропущенные транзакции и дубликаты от проблем с начальным балансом и переводами — еще до любых изменений в журнале.

## Каждое изменение данных — отдельная задача

Доступ для записи полезен, когда цель и ожидаемый результат понятны: у одной транзакции нужно исправить категорию, одобренный расход — добавить в журнал, а строку бюджета — обновить. Ограничьтесь небольшим изменением, которое легко проверить. Не давайте расплывчатую команду «приведи в порядок всё».

Вот безопасный промпт для изменения категории одной транзакции:

```text
Мне нужно исправить категорию одной записи журнала.

1. Вызови list_workspaces и подтверди со мной целевое рабочее пространство.
2. Вызови get_schema вместо того, чтобы предполагать имена столбцов.
3. С помощью sql_query найди точную запись по дате, сумме, валюте, счету
   и данным контрагента, которые я предоставлю.
4. Если не найдется ровно одного однозначного совпадения, остановись и спроси,
   что мне делать.
5. Покажи точную SQL-инструкцию, которую предлагаешь передать sql_execute,
   идентификатор рабочего пространства, найденную запись и ожидаемый результат.
   Пока не выполняй ее.
6. Дождись моего явного подтверждения.
7. После подтверждения один раз вызови sql_execute. Затем выполни новый sql_query,
   чтобы проверить сохраненное значение, и сообщи мне результат.
```

Так вы явно контролируете три решения: какое рабочее пространство использовать, какую запись изменить и каким именно образом. Проверять результат нужно новым запросом на чтение после изменения, а не полагаться на слова Claude о том, что запись, вероятно, прошла успешно.

Та же последовательность подходит для импорта. Попросите Claude проверить существующие категории и возможные дубликаты, заранее показать, какие записи он собирается добавить, и дождаться явного одобрения. После одобренных изменений проверьте добавленные строки и сверьте итоговый баланс. Если вы начинаете с файла, выгруженного из банка, статья [Как импортировать банковские выписки в трекер расходов](/blog/how-to-import-bank-statements-into-an-expense-tracker/) поможет проверить исходные данные.

## Ограничивайте доступ коннектора к финансовым данным

MCP избавляет от необходимости копировать ключ в чат, но не отменяет здравый смысл. В [рекомендациях по безопасности коннекторов](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) Anthropic советует подключаться только к доверенным серверам, проверять запрашиваемые разрешения и следить за входными и выходными данными инструментов.

Для этого коннектора достаточно нескольких правил:

1. Убедитесь, что указан именно URL `https://mcp.expense-budget-tracker.com/mcp`.
2. Начинайте с `expenses:read`, если запланированная задача не требует изменять данные.
3. Подтверждайте рабочее пространство перед каждой сессией, в которой Claude будет записывать данные.
4. Проверяйте актуальную схему перед генерацией SQL.
5. Просматривайте точную SQL-инструкцию и ожидаемый результат перед `sql_execute`.
6. Сразу после записи проверяйте результат с помощью `sql_query`.
7. Когда инструмент больше не нужен, отключите `sql_execute` в настройках инструментов Claude или отключите коннектор для этого диалога.

Не выбирайте **Always allow** для `sql_execute`. Отдельное подтверждение каждого запроса дает вам полезную паузу перед изменением финансовых данных.

Финансовые примечания и импортированные описания должны оставаться данными, а не инструкциями. Если текст транзакции предлагает Claude проигнорировать ваши правила или вызвать другой инструмент, не следуйте этому указанию. В том числе поэтому доступ для записи лучше выключать во время общего исследования или анализа данных.

Перед подключением ознакомьтесь с [Политикой конфиденциальности Expense Budget Tracker](/privacy/) и условиями обработки данных Anthropic. Авторизованная сессия Claude может читать финансовые данные, доступные вашему аккаунту, а с `expenses:write` — изменять их. Удаленное подключение проходит через облако Anthropic и сервис Expense Budget Tracker. Claude Desktop не делает этот канал передачи данных локальным.

## Как устранить неполадки без догадок

### Пользовательский коннектор не подключается

Сначала проверьте адрес подключения. Он должен быть таким:

```text
https://mcp.expense-budget-tracker.com/mcp
```

Не подставляйте вместо него URL сайта или прямого API. Оставьте поля OAuth Client ID и Client Secret в разделе Advanced пустыми. Убедитесь, что у вас есть активный аккаунт Expense Budget Tracker. Если войти по-прежнему не удается, отключите и снова подключите сервис в разделе **Customize > Connectors**.

В аккаунте Claude Team или Enterprise уточните у пользователя с ролью Owner или Primary Owner, добавлен ли пользовательский коннектор в организацию и разрешен ли он. Обычные участники не могут выполнить эту настройку самостоятельно.

### Claude видит коннектор, но не использует его

Включите Expense Budget Tracker для текущего чата в меню **+ > Connectors**. Затем укажите название коннектора в промпте и попросите Claude начать с `list_workspaces`. Даже настроенный коннектор может быть выключен в конкретном диалоге.

### `sql_execute` недоступен или в разрешении отказано

Скорее всего, вы выдали OAuth-разрешение `expenses:read`, но не добавили необязательную область `expenses:write`. Если задача связана с анализом, так и должно быть. Если для конкретной согласованной задачи нужно изменить данные, подключитесь заново и внимательно проверьте запрошенное разрешение на запись.

### Запрос завершается ошибкой или возвращает слишком много данных

Снова вызовите `get_schema` и составьте SQL на основе возвращенных объектов базы и столбцов. Используйте только те SQL-операции, которые разрешает коннектор. Для больших журналов рассчитывайте итоги, количество записей и сгруппированные результаты в SQL, а не запрашивайте больше 100 строк. Если запрос не укладывается в лимит 20 секунд, сузьте вопрос.

### Claude смотрит не на те финансовые данные

Остановитесь и ничего не записывайте. Вызовите `list_workspaces`, сравните полученные названия и идентификаторы и явно подтвердите нужное рабочее пространство. Затем вызовите для него `get_schema` и повторите запрос на чтение. Claude видит только рабочие пространства, доступные вошедшему пользователю, но среди них все равно нужно выбрать правильное.

### Claude просит `ApiKey`

Claude пытается работать по сценарию прямой HTTP-интеграции, а не через удаленный MCP-коннектор. Для описанной здесь настройки вернитесь к URL коннектора и OAuth-авторизации в браузере. Если вам действительно нужна автоматизация из терминала или прямые HTTP-запросы, обратитесь к [справочнику Agent API](/docs/api/).

## Настройка проста, но важнее цикл проверки

Чтобы подключить Claude к Expense Budget Tracker, достаточно одного URL и входа через браузер. Дальше важна постоянная последовательность действий: получить список рабочих пространств, проверить схему, сначала прочитать данные, выдать минимально необходимые разрешения и сформулировать каждое изменение так, чтобы его можно было проверить построчно.

Начните с полной [документации MCP-коннектора](/docs/mcp-connector/), добавьте `https://mcp.expense-budget-tracker.com/mcp` в разделе **Customize > Connectors** и проведите ежемесячную проверку в режиме только для чтения. Когда понадобится изменить данные, попросите Claude до вашего подтверждения показать рабочее пространство, запись, SQL и ожидаемый результат. Так трекер расходов для Claude превращается из удобной демонстрации в финансовый процесс, которому можно доверять.
