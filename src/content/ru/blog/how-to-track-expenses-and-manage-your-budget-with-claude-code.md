Выписка всего из четырёх строк может сойтись с разницей `€0.00`, хотя бюджет останется неверным. Если покупку в супермаркете на €54.20 отнести к путешествиям, а не к продуктам, остаток на счёте точно совпадёт с банковским. Но отчёт по категориям разойдётся на €54.20.

Поэтому при учёте расходов с Claude Code нужны две отдельные проверки: сохранённые движения должны объяснять остаток в банке, а категории — соответствовать проверенной выписке. Claude Code разберёт файл, выполнит расчёты и вызовет API. Вы выберете счёт и категории, проверите предложенные записи и подтвердите, что именно можно записать.

В этом сценарии Expense Budget Tracker не подключается к банку напрямую и не предлагает загрузить выписку через интерфейс. Экспортируйте выписку сами, положите её в каталог, который Claude Code может прочитать, и передайте через управляемый Agent API только подтверждённые записи. Если главное требование — обойтись без постоянного доступа к банку, статья [«Приложение для бюджета без подключения к банку»](/blog/budget-app-without-bank-linking/) подробнее разбирает связанные с этим компромиссы.

## Подключите Claude Code по одной ссылке

Установите Claude Code и войдите в аккаунт по [официальной инструкции Anthropic](https://code.claude.com/docs/en/quickstart). В [справочнике по CLI](https://code.claude.com/docs/en/cli-reference) описано, как Claude Code работает с текущим каталогом и дополнительным доступом к файлам.

Запустите `claude` в каталоге с выпиской или откройте ему доступ к этому каталогу способом, который поддерживает ваша конфигурация. Затем вставьте такой промпт:

```text
Подключись к Expense Budget Tracker по этой discovery-ссылке:
https://app.expense-budget-tracker.com/api/agent

Выполни GET-запрос по этой ссылке, прочитай полученный JSON и следуй актуальным URL
для действий. Не пытайся угадать последовательность API и не прописывай её вручную.
Спроси у меня email для Expense Budget Tracker и запусти вход с одноразовым кодом
из письма.
Когда запрос завершится успешно, скажи мне проверить папки «Спам» и «Нежелательная
почта», если письма не видно. Затем попроси восьмизначный код и выполни действие
проверки по URL из ответа.

После проверки попроси меня выбрать постоянное место для хранения полученного ApiKey —
вне памяти чата и вне системы контроля версий. Загрузи контекст моей учётной записи,
покажи список рабочих пространств, попроси подтвердить нужное, сохрани его как рабочее
пространство по умолчанию для этого ключа и изучи актуальную схему. Выполни один
небольшой запрос только для чтения, чтобы проверить выбранное рабочее пространство.
Не записывай финансовые данные.
```

[Ссылка агента на домене приложения](https://app.expense-budget-tracker.com/api/agent) возвращает актуальный discovery-документ. Сейчас в нём указаны базовый адрес API `https://api.expense-budget-tracker.com/v1/`, а также URL действий для аутентификации и работы с SQL. Вставляйте именно ссылку на домене приложения: Claude Code должен следовать адресам из ответа сервиса, а не запоминать внутреннюю последовательность вызовов.

Один и тот же вход по email используется и для регистрации, и для авторизации. После ввода восьмизначного кода Claude Code получает `ApiKey` с длительным сроком действия. Подтвердите конкретное место для его хранения — например, файл с секретами, исключённый из системы контроля версий. Никогда не добавляйте ключ в `CLAUDE.md` и не коммитьте его в репозиторий. В разделе [«Настройка ИИ-агента»](/docs/agent-setup/) подробно описаны аутентификация и выбор рабочего пространства.

## Не смешивайте Agent API и MCP

Под «трекером расходов с Claude» могут иметь в виду две разные интеграции. В этой статье Claude Code работает в терминале через Agent API. В Claude в браузере и Claude Desktop вместо этого можно подключить размещённый в облаке удалённый MCP-коннектор.

| | Claude Code с Agent API | Claude или Claude Desktop с MCP |
|---|---|---|
| Лучше всего подходит для | Работы в терминале с доступом к локальным файлам и прямыми HTTP-запросами | Диалогов в клиенте Claude с поддержкой MCP |
| Стартовый адрес | `https://app.expense-budget-tracker.com/api/agent` | `https://mcp.expense-budget-tracker.com/mcp` |
| Аутентификация | Одноразовый код из письма, затем `ApiKey` с длительным сроком действия | OAuth в браузере |
| Интерфейс работы с данными | URL из discovery-документа, ведущие к эндпоинтам чтения и записи | Инструменты `sql_query` и необязательный `sql_execute` |
| Доступ к выписке | Файлы и каталоги, доступные текущему сеансу Claude Code | Удалённый коннектор не даёт доступа к локальным файлам |

Учётные данные одной интеграции не подойдут для другой. Для Claude в браузере или Claude Desktop используйте [руководство по MCP-трекеру расходов с Claude](/blog/claude-expense-tracker-mcp-connector/). Процесс через Agent API ниже нужен, когда работа начинается с файла, доступного Claude Code.

Есть ещё две границы, которые лучше обозначить явно:

- Обработка данных на стороне поставщика модели не относится к API и хранилищу Expense Budget Tracker. Прежде чем передавать данные выписки, прочитайте [документацию Claude Code об использовании данных](https://code.claude.com/docs/en/data-usage) и условия поставщика модели, настроенного в вашей установке.
- Локальная конфигурация Docker Compose из [руководства по самостоятельному развёртыванию](/docs/self-hosting/) запускает веб-приложение, сервис аутентификации, базу данных и обработчик валютных курсов. Управляемого Agent API из этой статьи в ней нет. Развёртывание репозитория в AWS — отдельная конфигурация, в которую входит публичный API для машинных клиентов.

## Чётко ограничьте импорт

Для первого запуска возьмите один счёт, одну валюту и один закрытый период выписки. Удобнее всего начать с CSV: его строки легко проверить. Если формат другой, сначала попросите Claude Code убедиться, что он может прочитать файл в вашей среде, и показать результат разбора. Не считайте формат поддерживаемым по одному лишь имени файла.

Передайте Claude Code шесть фактов:

1. Локальный путь к выписке.
2. Банковский счёт и соответствующий ему счёт в трекере.
3. Валюту счёта.
4. Первую и последнюю даты проводки.
5. Начальный остаток или последний достоверно сверенный остаток.
6. Конечный остаток из выписки.

Не включайте операции, которые банк ещё не провёл. Оставьте исходный файл без изменений, а Claude Code попросите подготовить отдельный предпросмотр.

Для локального `CLAUDE.md` в каталоге с финансовыми файлами подойдёт такой набор правил:

```markdown
# Процесс работы с Expense Budget Tracker

- Начинай с https://app.expense-budget-tracker.com/api/agent и следуй discovery-документу.
- Подтверждай целевое рабочее пространство и изучай актуальную схему, прежде чем составлять SQL-запрос.
- Для всех проверок и сверок используй действие чтения.
- Перед записью показывай итоги по исходным данным, возможные дубликаты, точный SQL и ожидаемое число затронутых строк.
- Жди моего явного подтверждения всего набора изменений.
- Используй действие записи только для подтверждённого INSERT, UPDATE или DELETE.
- После каждой записи заново читай данные и проверяй результат.
- Никогда не создавай балансирующую операцию для подгонки остатка и не выбирай молча неоднозначную категорию.
- Храни ApiKey вне этого файла и вне системы контроля версий.
```

Добавьте постоянные детали: реальные названия счетов, правила категорий, принятую схему учёта переводов и валюту отчётов. Не копируйте категории из этой статьи, если они не совпадают с вашим журналом операций.

## Импортируйте выписку через полный предпросмотр

Когда подключение заработает, вставьте следующий промпт и замените значения в квадратных скобках:

```text
Импортируй [локальный путь к выписке] в [счёт в трекере] за период с [первая дата
проводки] по [последняя дата проводки] в [валюта]. Начальный остаток — [сумма],
а конечный остаток по данным банка — [сумма].

Сначала подтверди выбранное рабочее пространство и изучи актуальную схему. Используй
только действие чтения, чтобы проверить целевой счёт, существующие категории и строки
журнала операций за даты, пересекающиеся с периодом выписки. Подтверди, что можешь
прочитать локальный файл, разобрать его и подготовить полный предпросмотр без записи
данных.

Для каждой исходной строки покажи её идентификатор или номер, дату проводки, сумму со
знаком, валюту, целевой счёт, предлагаемый тип операции, предлагаемую категорию и
статус дубликата. Отметь переводы, возвраты средств, компенсации расходов, комиссии,
операции в иностранной валюте, незнакомых контрагентов и неоднозначные классификации.

Затем покажи количество исходных строк и их общую сумму со знаком, все предлагаемые
записи в журнале, возможные дубликаты, точный SQL, который собираешься отправить,
и ожидаемое число затронутых строк. Остановись и дождись моего явного подтверждения
всего набора изменений.
```

До вашего подтверждения работа с базой данных остаётся в режиме только для чтения. Claude Code должен изучить актуальную схему, а не копировать названия столбцов из статьи, найти нужный счёт и запросить существующие строки за тот же интервал дат. Совпадение по дате и сумме — лишь признак возможного дубликата, а не доказательство. У двух разных реальных покупок могут совпасть оба поля.

### Пример на четырёх строках

Предположим, начальный остаток в выписке по текущему счёту равен €1,250.00, а дальше идут четыре проведённые операции:

| Строка | Дата проводки | Описание | Сумма со знаком | Предлагаемый тип | Предлагаемая категория | Что проверить |
|---|---|---|---:|---|---|---|
| 1 | 2026-08-31 | Зарплата | +€2,000.00 | Доход | Зарплата | Без вопросов |
| 2 | 2026-09-02 | Супермаркет | −€54.20 | Расход | Продукты | Проверить магазин, если он незнаком |
| 3 | 2026-09-03 | Перевод на сберегательный счёт | −€300.00 | Перевод | — | Подтвердить второй счёт |
| 4 | 2026-09-04 | Кафе | −€8.40 | Расход | Кафе и рестораны | Без вопросов |

Сумма четырёх операций с учётом знака равна `+€1,637.40`. Прибавляем её к начальному остатку `€1,250.00` и получаем ожидаемый конечный остаток `€2,887.40`. Этот пример помещается на одном экране. Если строк больше, в предпросмотр всё равно должна попасть каждая строка исходной выписки, а любая неоднозначность должна быть явно отмечена.

Для перевода нужно подтвердить счёт на другой стороне: перемещение денег между своими счетами не является расходом. Для возвратов средств и компенсаций расходов тоже важно сохранить правильный тип операции. Если классификация неоднозначна, отметьте её как требующую решения, а не выбирайте наиболее вероятную категорию.

### Подтвердите конкретный набор изменений

Проверьте рабочее пространство, счёт, границы дат, количество строк, итоговую сумму со знаком, возможные дубликаты и классификации. Утверждайте именно показанный предпросмотр и SQL, а не давайте общее указание «импортировать всё».

В Agent API чтение и запись разделены. Claude Code использует найденное действие чтения для одного `SELECT` или `WITH ... SELECT`, а действие записи — только для явно подтверждённого `INSERT`, `UPDATE` или `DELETE`. Таблицы и столбцы Claude Code берёт из актуальной схемы; SQL-контракт и ограничения описаны в [справочнике по API](/docs/api/).

### Перед пакетной записью сделайте пробный запрос для длинных INSERT и UPDATE

Перед длинным `INSERT` или `UPDATE` актуальные инструкции в discovery-документе предписывают агенту отправить пробный запрос той же структуры SQL: 1–3 строки с литеральными значениями для `INSERT` или одну конкретную строку для `UPDATE`. Ваше подтверждение распространяется и на эту пробу, и на оставшиеся строки проверенного набора изменений.

Если проба прошла успешно, Claude Code должен сразу продолжить запись последовательными пакетами не более чем по 100 записей, проверяя каждый пакет по ходу работы. После пробы из трёх строк от подтверждённого импорта на 247 строк останутся пакеты по 100, 100 и 44 строки. Изменение границ задачи, новая неоднозначность или ошибка выполнения создают новую точку подтверждения. Для обычных следующих пакетов в уже подтверждённом наборе отдельное подтверждение не нужно.

Ограниченный SQL-интерфейс не поддерживает `ON CONFLICT`, поэтому дубликаты нужно обрабатывать явно. Ответ на чтение содержит не более 100 строк. Claude Code должен проверять метаданные ответа с количеством строк и признаком усечения, считать агрегированные итоги средствами SQL, а подробную проверку разбивать на узкие упорядоченные запросы чтения. Усечённый ответ не подтверждает полный импорт.

### Повторно запросите сохранённые строки

Успешный ответ API подтверждает, что запрос выполнился. Он не гарантирует, что каждое сохранённое значение совпадает с предпросмотром. Повторно запросите данные по счёту и периоду, которых касались изменения, затем сравните:

- количество вставленных строк
- даты, суммы со знаком и валюты
- привязку к счёту
- типы операций и категории
- возможные дубликаты
- итоги по пакетам и общий итог выписки

Если что-то не совпадает, вернитесь к диагностике без записи данных. Перед следующей записью сначала проверьте и подтвердите одно конкретное исправление. В [руководстве по импорту банковских выписок](/blog/how-to-import-bank-statements-into-an-expense-tracker/) подробнее разобраны пересекающиеся периоды, возвраты и переводы.

## Сверяйте остаток и категории по отдельности

Сверка остатка отвечает на вопрос, объясняют ли сохранённые движения конечный банковский остаток в границах тех же дат проводки.

Для обычного банковского счёта:

**ожидаемый конечный остаток = начальный остаток + проведённые поступления − проведённые списания**

Если движения хранятся со знаком:

**ожидаемый конечный остаток = начальный остаток + сумма проведённых движений со знаком**

Для долговых счетов, например кредитных карт, правило знаков может быть другим. Перед расчётом Claude Code должен указать, какое правило используется в данных.

Продолжите таким промптом:

```text
Используй только действие чтения. Сверь [счёт] за период с [первая дата проводки]
по [последняя дата проводки] с конечным банковским остатком [сумма и валюта]. Укажи
начальную границу, правило знаков, количество сохранённых строк и общую сумму движений
со знаком.

Покажи ожидаемый конечный остаток, конечный остаток банка и точную разницу. Если
разница не равна нулю, перечисли возможные пропущенные и дублирующиеся строки, строки,
не попавшие в расчёт, строки с неверной датой или знаком. Не добавляй балансирующую
операцию и не меняй данные.

После сверки остатка отдельно проверь итоги по категориям. Перечисли операции без
категории, переводы, учтённые как расходы, и категории, которые отличаются от
подтверждённого предпросмотра.
```

В примере из четырёх строк `€1,250.00 + €1,637.40 = €2,887.40`. Если конечный остаток банка тоже равен €2,887.40, разница составит `€0.00`.

Нулевая разница подтверждает, что арифметика по счёту сходится в выбранных границах. Категории она не подтверждает. Если у операции «Супермаркет» на €54.20 заменить категорию «Продукты» на «Путешествия», разница остатков останется нулевой, но €54.20 перейдут из одной категории в другую. Поэтому проверка категорий — отдельный критерий приёмки.

Если разница не равна нулю, проверьте начальный остаток, пропущенные и дублирующиеся строки, переводы, ещё не проведённые операции, знаки, даты и валюты. Никогда не добавляйте искусственную балансирующую операцию только для того, чтобы разница исчезла. Диагностический цикл подробнее описан в [руководстве по сверке](/blog/how-to-reconcile-your-budget-with-your-bank-balance/).

## Обновляйте бюджет только после сверки

Переходите к бюджету только после того, как повторное чтение подтвердит сохранённые строки, остаток по счёту сойдётся, а итоги по категориям не будут вызывать вопросов. Трекер бюджета с Claude Code может сравнить фактические операции со строками `budget_lines` и подготовить изменения. Один нетипичный месяц не должен автоматически становиться планом на следующий.

```text
Подтверди рабочее пространство и изучи актуальную схему. Используй действие чтения,
чтобы сравнить фактические доходы и расходы за [полный период] с соответствующими
строками бюджета. Исключи переводы по сохранённому типу операции и отдельно покажи
операции без категории.

Для каждого предлагаемого изменения бюджета покажи категорию, текущую сумму,
фактическую сумму, предлагаемую сумму, разницу и причину. Затем покажи точный SQL
и ожидаемое число затронутых строк. Ничего не записывай, пока я не подтвержу
конкретные строки.

После подтверждения используй действие записи только для этих строк и проверь их
новым чтением. Сообщи о каждом сохранённом значении, которое отличается от
подтверждённого предложения.
```

Крупный расход может быть разовым. То, что выглядит перерасходом, иногда оказывается неверно классифицированным переводом или возвратом. Claude Code рассчитает разницу и подготовит SQL, но конкретные суммы на следующий месяц всё равно выбираете вы.

## Для каждой выписки придерживайтесь одного порядка

Для каждой выписки сохраняйте один и тот же порядок:

1. Начните с `https://app.expense-budget-tracker.com/api/agent` и следуйте discovery-документу.
2. Загрузите контекст учётной записи, подтвердите рабочее пространство и изучите актуальную схему.
3. Передайте Claude Code один доступный файл выписки, явно указав начальный и конечный остатки.
4. Прочитайте данные журнала за пересекающийся период и подготовьте полный предпросмотр импорта.
5. Подтвердите один конкретный набор изменений.
6. Для длинного `INSERT` выполните пробу на 1–3 строках, затем записывайте последовательными пакетами не более чем по 100 строк.
7. После записи заново прочитайте каждый пакет и сравните его с предпросмотром.
8. Сверьте счёт с конечным банковским остатком без балансирующей операции.
9. Проверьте итоги по категориям, даже если разница остатков равна нулю.
10. Отдельно подготовьте, подтвердите и проверьте все изменения строк бюджета.

Начните с одного счёта и одного завершённого периода. Когда выписка сойдётся с журналом операций, а бюджет будет проверен, повторите процесс для следующего счёта. Рутинную работу с файлами и API возьмёт на себя Claude Code, а каждое финансовое решение останется видимым до того, как изменятся ваши записи.
