Expense Budget Tracker предоставляет единый адрес удалённого MCP-сервера:

```text
https://mcp.expense-budget-tracker.com/mcp
```

Используйте этот адрес во всех совместимых клиентах. Облачный сервер работает по Streamable HTTP и OAuth 2.1; API-ключи на этом адресе не принимаются.

## Поддерживаемые клиенты

Адрес работает с ChatGPT и другими MCP-клиентами, которые поддерживают всё перечисленное:

- удалённые MCP-серверы по Streamable HTTP;
- OAuth 2.1 Authorization Code с PKCE;
- динамическую регистрацию OAuth-клиентов.

Claude, Codex, OpenClaw и другие клиенты могут использовать тот же адрес, если их текущая версия поддерживает этот удалённый транспорт и способ аутентификации. Клиент, который умеет работать только с локальными серверами через `stdio`, не сможет напрямую подключиться к облачному адресу.

## Подключение и авторизация

1. Добавьте `https://mcp.expense-budget-tracker.com/mcp` как пользовательский удалённый MCP-сервер в своём клиенте.
2. Клиент обнаружит защищённый ресурс и сервер авторизации, затем зарегистрирует своё имя и адреса перенаправления через Dynamic Client Registration.
3. В браузере откроется вход и экран согласия Expense Budget Tracker. Войдите, проверьте имя клиента и запрошенные права и разрешите только нужный доступ.
4. Клиент обменяет код авторизации с помощью PKCE и подключится с краткосрочными учётными данными. Копировать токен в клиент не нужно.
5. До чтения или изменения финансовых данных попросите клиента вызвать `list_workspaces`.

Сервер авторизации может выдать следующие права:

| Право | Доступ |
| --- | --- |
| `expenses:read` | Список рабочих пространств, просмотр разрешённой схемы и запрос финансовых данных. |
| `expenses:write` | Выполнение разрешённого `INSERT`, `UPDATE` или `DELETE` через `sql_execute`. Право записи отделено от права чтения. |

Подключение только для чтения получает `expenses:read`. Подключение с записью получает оба права: `expenses:read` и `expenses:write`.

## Инструменты

| Инструмент | Назначение | Граница |
| --- | --- | --- |
| `list_workspaces` | Возвращает все рабочие пространства, доступные вошедшему пользователю. | Только чтение; требует `expenses:read`. |
| `get_schema` | Возвращает разрешённые отношения, столбцы, ограничения, лимиты и подсказки для одного пространства. | Только чтение; требует `expenses:read`. |
| `sql_query` | Выполняет ровно один разрешённый политикой `SELECT` или `WITH ... SELECT`. | Транзакция только для чтения под ограниченной ролью; требует `expenses:read`. |
| `sql_execute` | Выполняет ровно один разрешённый политикой `INSERT`, `UPDATE` или `DELETE`. | Изменяет финансовые данные и не является идемпотентным; требует `expenses:write`. |

Инструменты работают только с данными Expense Budget Tracker. Они не могут просматривать интернет, обращаться к другому сервису, выполнять DDL или обходить список отношений и столбцов из `get_schema`.

## Выбор рабочего пространства

Сначала вызовите `list_workspaces`. Если возвращено ровно одно пространство, в остальных вызовах можно не указывать `workspaceId`. Если пространств несколько, выберите один из возвращённых идентификаторов и явно передавайте этот `workspaceId` в каждый вызов `get_schema`, `sql_query` и `sql_execute`. Сервер отклонит неоднозначное или недоступное пространство, а не станет выбирать сам.

После выбора пространства и до составления SQL вызовите `get_schema`. Подробный контракт отношений и SQL находится в [справочнике API](/ru/docs/api/); здесь описаны только подключение MCP и модель безопасности.

## Границы чтения и записи

Используйте `sql_query` для просмотра данных и отчётов. Вызывайте `sql_execute`, только когда требуемое изменение однозначно и пользователь его подтвердил. Изменения не идемпотентны, поэтому не повторяйте неясный запрос записи вслепую: сначала запросите итоговое состояние и повторяйте запись только после подтверждения, что изменение не применилось.

Изоляция рабочих пространств обеспечивается на сервере через Postgres Row Level Security и ограниченные роли базы данных. Сервис сам проверяет OAuth-права, членство в пространстве, SQL-политику, сроки выполнения и лимит строк ответа.

## Конфиденциальность, отзыв доступа и помощь

ИИ-клиент является отдельной третьей стороной. Он может обрабатывать или хранить запросы и результаты инструментов по собственным условиям и политике конфиденциальности. Ознакомьтесь с ней до подключения финансовых данных. В [политике конфиденциальности](/ru/privacy/) описано, что обрабатывает и хранит облачный сервис.

Отозвать доступ подключённого MCP-клиента можно в облачном приложении: **Настройки > Доступ агентов**. После отзыва учётные данные доступа и обновления этого подключения становятся недействительными. При проблемах с подключением используйте [страницу поддержки](/ru/support/).
