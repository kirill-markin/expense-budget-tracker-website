لجعل أول محادثة بين Claude ومتتبّع مصروفاتك آمنة، ابدأ بشيء يكاد يكون مملًا. يسرد Claude مساحات العمل المتاحة، ويفحص مخطط قاعدة البيانات الحالي، وينفّذ استعلامًا واحدًا للقراءة فقط. لا يتغير شيء في دفتر الأستاذ.

تكمن أهمية هذه البداية الهادئة في أن الموصّل نفسه قد يحصل لاحقًا على إذن بتغيير البيانات المالية. لذلك افصل بين صلاحيتي القراءة والكتابة، وحدّد مساحة العمل صراحةً، وتحقّق من كل تغيير بعد تنفيذه.

يوفّر Expense Budget Tracker موصّل MCP بعيدًا يعمل كخدمة مستضافة ويدعم هذا التسلسل تحديدًا:

```text
https://mcp.expense-budget-tracker.com/mcp
```

أضف هذا العنوان إلى Claude، وأكمل تسجيل الدخول والتفويض عبر OAuth في المتصفح، وسيتمكن Claude من العمل مع المتتبّع من خلال أربع أدوات محددة بوضوح. لا تحتاج إلى طرفية أو مفتاح API أو ملف إعداد MCP محلي.

## هذا مسار الموصّل، لا مسار API الخاص بـ Claude Code

يدعم Expense Budget Tracker مسارين للوصول البرمجي، ومن السهل الخلط بين بيانات اعتمادهما.

| | موصّل MCP البعيد | واجهة Agent API المباشرة |
|---|---|---|
| الأنسب لـ | المحادثات في Claude وClaude Desktop | Claude Code وCodex والسكربتات ووكلاء الطرفية الآخرين |
| عنوان البداية | `https://mcp.expense-budget-tracker.com/mcp` | `https://api.expense-budget-tracker.com/v1/` |
| المصادقة | OAuth عبر المتصفح | `ApiKey` طويل الأمد |
| الواجهة | أدوات MCP | نقاط نهاية HTTP |
| بيانات الاعتماد | رموز وصول وتحديث OAuth يحفظها عميل MCP | مفتاح `ApiKey` محفوظ خارج ذاكرة الدردشة |

لا تقبل نقطة نهاية MCP مفتاح `ApiKey` المستخدم مع API المباشر، ولا يحوّل API هذا المفتاح إلى موصّل مخصص في Claude. هذان تكاملان منفصلان، ولكل منهما طريقة مستقلة للحصول على بيانات الاعتماد.

استخدم هذا الدليل عندما تريد ربط Claude بمتتبّع المصروفات من تطبيق Claude على الويب أو من Claude Desktop. أما إذا كانت مهمتك تبدأ بعبارة «اقرأ ملف CSV هذا من حاسوبي المحمول»، فاتبع سير العمل عبر الطرفية في دليل [كيف تتابع مصروفاتك وتدير ميزانيتك باستخدام Claude Code](/blog/how-to-track-expenses-and-manage-your-budget-with-claude-code/). ويغطي [الدليل الأشمل لإعداد متتبّع المصروفات بالذكاء الاصطناعي](/blog/ai-agent-expense-tracker-claude-code-codex-openclaw/) ربط Claude Code وCodex وOpenClaw عبر API المباشر.

## أضف موصّل Expense Budget Tracker إلى Claude

المسار الحالي للحسابات الفردية في Claude هو **Customize > Connectors > Add custom connector**. توثّق Anthropic أحدث تفاصيل الواجهة وأنواع الحسابات في [دليل موصّلات MCP البعيدة المخصصة](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### 1. أضف عنوان MCP البعيد

افتح Claude أو Claude Desktop، ثم:

1. انتقل إلى **Customize > Connectors**.
2. انقر زر **+** واختر **Add custom connector**.
3. سمّه `Expense Budget Tracker`.
4. أدخل `https://mcp.expense-budget-tracker.com/mcp` بوصفه عنوان خادم MCP البعيد.
5. انقر **Add**.

لا تحتاج إلى إدخال OAuth Client ID أو Client Secret في الإعدادات المتقدمة. يدعم خادم التفويض في Expense Budget Tracker التسجيل الديناميكي لعميل OAuth عام، ولا يحتاج العميل العام إلى Client Secret.

في حسابات Team وEnterprise، يجب أن يضيف Owner أو Primary Owner الموصّل المخصص إلى المؤسسة أولًا. بعد ذلك يتصل كل عضو بحسابه، ولا يمكنه الوصول إلا إلى مساحات العمل المتاحة للمستخدم المسجّل دخوله.

### 2. اتصل ووافق على صلاحيات OAuth

انقر **Connect** بجانب الموصّل الجديد. يتبع Claude خطوات اكتشاف تفويض MCP، ثم يفتح صفحة مصادقة Expense Budget Tracker في متصفحك. سجّل الدخول وراجع الصلاحيات المطلوبة.

للنطاقين وظيفتان مختلفتان:

- النطاق `expenses:read` إلزامي. يتيح اكتشاف مساحات العمل وفحص مخطط قاعدة البيانات وتنفيذ استعلامات للقراءة فقط.
- النطاق `expenses:write` اختياري. يتيح استخدام أداة `sql_execute` التي تغيّر البيانات.

لمراجعة الإنفاق وإعداد التقارير والتسوية وتحليل الميزانية، امنح النطاق `expenses:read` فقط. لا تضف `expenses:write` إلا عندما يحتاج Claude إلى إدخال بيانات محددة أو تحديثها أو حذفها. لا داعي لمنحه «تحسبًا للحاجة».

لا تلصق رمز OAuth داخل مطالبة. يتولى المتصفح ومخزن بيانات اعتماد الموصّل في Claude حفظ رموز الوصول والتحديث واستخدامها.

### 3. فعّل الموصّل في المحادثة

إضافة موصّل لا تعني أن Claude سيستخدمه في كل دردشة. افتح قائمة **+** داخل المحادثة، واختر **Connectors**، ثم فعّل Expense Budget Tracker لهذه الدردشة.

يفيد خيار التفعيل المنفصل لكل محادثة عند التعامل مع البيانات المالية. اترك الموصّل معطّلًا عندما لا تحتاج إليه، وفعّله لجلسة مركّزة على الميزانية.

## ما الذي يفعله Claude أثناء OAuth

لا تحتاج إلى تنفيذ هذه الخطوات يدويًا، لكن معرفة مراحلها تجعل استكشاف مشكلات الاتصال أوضح.

ينشر الموصّل المستضاف بيانات تعريف المورد المحمي على العنوان `https://mcp.expense-budget-tracker.com/.well-known/oauth-protected-resource/mcp`. ويوجّه هذا المستند Claude إلى بيانات تعريف خادم التفويض على العنوان `https://auth.expense-budget-tracker.com/.well-known/oauth-authorization-server`.

يسجّل Claude نفسه كعميل OAuth عام، ويفتح تدفّق Authorization Code في المتصفح، ويستخدم PKCE مع طريقة التحدي `S256`. بعد الموافقة، يستبدل رمز التفويض برموز الوصول ويجدّد رمز الوصول عند الحاجة. يتوافق ذلك مع [نموذج تفويض MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)، بما فيه اكتشاف المورد المحمي وحماية رموز التفويض باستخدام PKCE.

قد يفاجئ مستخدمي Claude Desktop أن طلبات الموصّل البعيد لا تنطلق من واجهة الشبكة المحلية لتطبيق سطح المكتب. [توضح Anthropic أن اتصالات MCP البعيدة المخصصة تنطلق من بنيتها التحتية السحابية](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)، حتى عند استخدام Claude Desktop. الموصّل المستضاف هنا متاح للعامة بالفعل. أما خادم MCP خاص تستضيفه بنفسك، فيجب أن يقبل الاتصالات من بنية Anthropic التحتية حتى يتمكن Claude من الوصول إليه.

## الأدوات الأربع التي يحصل عليها Claude

يمنح الموصّل Claude مجموعة صغيرة ومتسلسلة من الأدوات بدلًا من أن يمنحه اتصالًا غير مقيّد بقاعدة البيانات.

| الأداة | ما الذي تفعله | الصلاحية |
|---|---|---|
| `list_workspaces` | تسرد مساحات العمل المتاحة للمستخدم المسجّل دخوله | `expenses:read` |
| `get_schema` | تعيد العلاقات والأعمدة المتاحة في مساحة العمل المحددة | `expenses:read` |
| `sql_query` | تنفّذ استعلام SQL واحدًا مقيّدًا للقراءة فقط | `expenses:read` |
| `sql_execute` | تنفّذ أوامر SQL مقيّدة تغيّر البيانات | `expenses:read` و`expenses:write` |

تعمل `sql_query` ضمن قيد للقراءة فقط مفروض على مستوى قاعدة البيانات. وتقتصر نتائجها على 100 صف، بمهلة تنفيذ قدرها 20 ثانية. لكن الموصّل ككل لا يظل للقراءة فقط عند توفر `sql_execute`، ولهذا تحتاج صلاحية الكتابة الاختيارية إلى عناية منفصلة.

افحص مخطط قاعدة البيانات الحالي قبل كتابة SQL. يجب أن تأتي أسماء الجداول والأعمدة والعلاقات المسموح بها من `get_schema`، لا من مطالبة قديمة أو مثال منسوخ أو ذاكرة Claude عن تطبيق مالي آخر.

## رتّب خطوات الجلسة الأولى بأمان

ينبغي أن تُلزم المطالبة الأولى Claude بتحديد السياق قبل أن يحلّل أي شيء:

```text
استخدم موصّل Expense Budget Tracker في وضع القراءة فقط.

استدعِ list_workspaces أولًا واعرض لي أسماء مساحات العمل المتاحة ومعرّفاتها.
اطلب مني تأكيد مساحة العمل التي ستستخدمها، حتى لو كانت هناك مساحة واحدة فقط. ثم استدعِ
get_schema لمساحة العمل المؤكدة. استخدم sql_query فقط. لا تستدعِ sql_execute
ولا تقترح أي تغيير بعد.

بعد الحصول على المخطط الحالي، لخّص إنفاقي حسب الفئة للشهر التقويمي الحالي، وقارنه
بالشهر التقويمي السابق. استخدم استعلامات تجميعية بدلًا من إعادة كل صفوف دفتر الأستاذ.
اعرض الاستعلام واشرح أي حدود تؤثر في النتيجة.
```

الترتيب مهم: اختر مساحة العمل، وافحص مخططها الحالي، ثم اكتب الاستعلام. إذا كان الاستعلام سيعيد أكثر من 100 سجل، فاطلب من Claude تجميع النتائج داخل SQL أو تقسيم السؤال إلى فترات منطقية. الهدف ليس حشر دفتر أستاذ كامل داخل الدردشة، بل إجراء الحسابات داخل قاعدة البيانات وإعادة النتيجة المفيدة فقط.

## مطالبات عملية لأول جلسة للقراءة فقط

بعد أن يؤكد Claude مساحة العمل ويفحص مخطط قاعدة البيانات، يمكنه فعل أكثر من سرد المشتريات الأخيرة.

### نفّذ مراجعة شهرية للميزانية

```text
باستخدام sql_query فقط، قارن الدخل والإنفاق الفعليين بميزانية هذا الشهر.
اجمع الفروق حسب الفئة، وضع أكبر الفروق المطلقة أولًا، وافصل بيانات الميزانية
المفقودة عن التجاوز الحقيقي للميزانية. لا تغيّر أي بند في الميزانية. اعرض SQL الذي استخدمته.
```

هذه هي النسخة الحوارية من [مراجعة شهرية للميزانية](/blog/how-to-do-a-monthly-budget-review/): حدّد الفرق أولًا، ثم قرر ما الذي ينبغي تغييره.

### ابحث عن مصروفات مكررة محتملة

```text
استخدم مخطط قاعدة البيانات الحالي وsql_query للعثور على قيود مصروفات يُحتمل تكرارها خلال
آخر 45 يومًا. قارن التواريخ والمبالغ والعملات والحسابات والأطراف المقابلة
حيثما توفرت هذه الحقول. تعامل مع النتائج كعناصر مرشحة، لا كتكرارات مؤكدة.
لا تحذف أو تحدّث أي شيء.
```

عبارة «عناصر مرشحة، لا تكرارات مؤكدة» مهمة. فعمليتا شراء قهوة متطابقتان لا تعنيان بالضرورة أن إحداهما ناتجة عن استيراد مكرر بالخطأ.

### جهّز فحصًا للتسوية

```text
استخدم list_workspaces، وأكّد مساحة عملي الشخصية، وافحص المخطط، واستعلم عن
الأرصدة المتاحة عبر الموصّل. اشرح قيود دفتر الأستاذ التي تفسّر أحدث رصيد.
لا تُجرِ أي تصحيحات. سأقارن النتيجة بكشفي البنكي بنفسي.
```

عندما لا يطابق الرصيد كشف الحساب الأصلي، توقف عند الفرق وابحث عن سببه. يشرح [مسار تسوية الميزانية](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) كيفية الفصل بين المعاملات المفقودة والتكرارات ومشكلات الرصيد الافتتاحي والتحويلات قبل تغيير دفتر الأستاذ.

## تعامل مع كل عملية تعديل كمهمة منفصلة

تكون صلاحية الكتابة مفيدة عندما يكون السجل المستهدف والنتيجة المقصودة واضحين: تحتاج معاملة واحدة إلى تصحيح فئتها، أو يجب تسجيل مصروف معتمد، أو يحتاج بند في الميزانية إلى تحديث متفق عليه. أبقِ التغيير صغيرًا وقابلًا للمراجعة، بدلًا من إعطاء أمر مبهم مثل «نظّف كل شيء».

إليك مطالبة دقيقة لإعادة تصنيف معاملة واحدة:

```text
أحتاج إلى تصحيح فئة قيد واحد في دفتر الأستاذ.

1. استدعِ list_workspaces وأكّد معي مساحة العمل المستهدفة.
2. استدعِ get_schema بدلًا من افتراض أسماء الأعمدة.
3. استخدم sql_query للعثور على القيد المحدد اعتمادًا على تفاصيل التاريخ والمبلغ والعملة والحساب
   والطرف المقابل التي سأعطيك إياها.
4. إذا لم تجد تطابقًا واحدًا واضحًا تمامًا، فتوقف واسألني عما يجب فعله.
5. اعرض عبارة SQL الدقيقة التي تقترحها لـ sql_execute، ومعرّف مساحة العمل،
   والقيد المطابق، والأثر المتوقع. لا تنفّذها بعد.
6. انتظر تأكيدي الصريح.
7. بعد التأكيد، استدعِ sql_execute مرة واحدة. ثم استدعِ sql_query من جديد للتحقق
   من القيمة المخزّنة وأبلغني بها.
```

يُبقي هذا الأسلوب ثلاثة قرارات واضحة أمامك: أي مساحة عمل، وأي سجل، وما التغيير المحدد. والتحقق هنا يعني تنفيذ قراءة جديدة بعد التعديل، لا الاكتفاء بقول Claude إن عملية الكتابة نجحت على الأرجح.

ينجح الأسلوب نفسه مع الاستيراد. اطلب من Claude فحص الفئات الحالية والتكرارات المحتملة، وعرض معاينة للسجلات التي ينوي إدخالها، وانتظار الموافقة الصريحة. وبعد عمليات الكتابة المعتمدة، تحقّق من السجلات التي أُضيفت وتأكّد من تطابق الرصيد الناتج مع كشف الحساب. إذا كانت مدخلاتك تبدأ بملف تصدير بنكي، فيشرح دليل [كيفية استيراد كشوف الحساب البنكية إلى متتبّع المصروفات](/blog/how-to-import-bank-statements-into-an-expense-tracker/) خطوات مراجعة الملف الأصلي.

## قيّد صلاحيات الموصّل عند التعامل مع البيانات المالية

يلغي MCP الحاجة إلى لصق مفتاح API داخل الدردشة، لكنه لا يلغي الحاجة إلى التقدير البشري. توصي [إرشادات Anthropic لأمان الموصّلات](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) بالاتصال بالخوادم الموثوقة فقط، ومراجعة الصلاحيات المطلوبة، والانتباه إلى مدخلات الأدوات ومخرجاتها.

بالنسبة إلى هذا الموصّل، تتلخص طريقة الاستخدام الآمن في الخطوات التالية:

1. تحقق من أن العنوان هو بالضبط `https://mcp.expense-budget-tracker.com/mcp`.
2. ابدأ بالنطاق `expenses:read` ما لم تكن لديك مهمة محددة تتطلب تغيير البيانات.
3. أكّد مساحة العمل قبل كل جلسة ستجري فيها تعديلات.
4. افحص مخطط قاعدة البيانات الحالي قبل إنشاء SQL.
5. راجع عبارة SQL الدقيقة وأثرها المتوقع قبل `sql_execute`.
6. تحقّق من النتيجة باستخدام `sql_query` بعدها مباشرةً.
7. عطّل `sql_execute` في عناصر التحكم بأدوات Claude، أو عطّل الموصّل لهذه المحادثة، عندما تنتهي حاجتك إليه.

لا تختر **Always allow** لأداة `sql_execute`. تمنحك مراجعة كل طلب كتابة على حدة فرصة مفيدة للتوقف قبل أن تغيّر الأداة السجلات المالية.

يجب أيضًا أن تظل الملاحظات المالية والأوصاف المستوردة بيانات، لا تعليمات. إذا احتوى نص محفوظ داخل معاملة على طلب من Claude لتجاهل قواعدك أو استدعاء أداة أخرى، فلا تتبعه. وهذا سبب إضافي لإبقاء صلاحية الكتابة معطّلة أثناء جلسات البحث أو التحليل الواسعة.

راجع [سياسة خصوصية Expense Budget Tracker](/privacy/) وشروط Anthropic لمعالجة البيانات قبل الاتصال. تستطيع جلسة Claude المصرّح لها قراءة البيانات المالية المتاحة لحسابك، ويمكنها تغييرها عند منح النطاق `expenses:write`. يمر الاتصال البعيد عبر سحابة Anthropic وخدمة Expense Budget Tracker المستضافة؛ ولا يعني استخدام Claude Desktop أن مسار البيانات محلي فقط.

## استكشاف مشكلات الاتصال من دون تخمين

### يتعذر على الموصّل المخصص الاتصال

تحقق من نقطة الاتصال أولًا. يجب أن تكون:

```text
https://mcp.expense-budget-tracker.com/mcp
```

لا تستبدلها بعنوان الموقع أو عنوان API المباشر. اترك حقلي Advanced OAuth Client ID وClient Secret فارغين لهذا الموصّل، وتأكد من أن لديك حسابًا نشطًا في Expense Budget Tracker. إذا استمرت مشكلة المصادقة، فافصل الموصّل وأعد توصيله من **Customize > Connectors**.

في حسابات Claude من نوع Team أو Enterprise، اسأل Owner أو Primary Owner عما إذا كان الموصّل المخصص قد أُضيف إلى المؤسسة وسُمح باستخدامه. لا يستطيع الأعضاء تنفيذ هذا الإعداد على مستوى المؤسسة بأنفسهم.

### يظهر الموصّل لدى Claude لكنه لا يستخدمه

فعّل Expense Budget Tracker للدردشة الحالية من قائمة **+ > Connectors**. ثم اذكر اسم الموصّل في المطالبة واطلب من Claude البدء بـ `list_workspaces`. يمكن أن يظل الموصّل المُعد مسبقًا معطلًا داخل محادثة بعينها.

### أداة `sql_execute` غير متاحة أو تم رفض الإذن

يقتصر تفويض OAuth على الأرجح على `expenses:read` من دون النطاق الاختياري `expenses:write`. اتركه كذلك إذا كانت المهمة تحليلية. وإذا تطلبت مهمة محددة ومعتمدة تغييرًا في البيانات، فأعد الاتصال وراجع صلاحية الكتابة المطلوبة قبل منحها.

### يفشل الاستعلام أو يعيد بيانات أكثر من اللازم

استدعِ `get_schema` مرة أخرى وأنشئ SQL من العلاقات والأعمدة التي يعيدها. أبقِ الطلب ضمن نطاق SQL المقيّد الذي يتيحه الموصّل. في دفاتر الأستاذ الكبيرة، احسب الإجماليات والأعداد والنتائج المجمّعة داخل SQL بدلًا من محاولة تجاوز سقف النتائج البالغ 100 صف. وإذا تجاوز الاستعلام مهلة الـ20 ثانية، فاطرح سؤالًا أضيق نطاقًا.

### يستخدم Claude بيانات مالية غير مقصودة

توقف قبل أي عملية كتابة. استدعِ `list_workspaces`، وقارن الأسماء والمعرّفات المُعادة، وأكّد مساحة العمل المطلوبة صراحةً. ثم استدعِ `get_schema` لتلك المساحة وكرر القراءة. يقتصر الوصول على مساحات العمل المتاحة للمستخدم المسجّل دخوله، لكن يظل على Claude اختيار المساحة التي قصدتها.

### يطلب Claude مفتاح `ApiKey`

إنه يتبع مسار تكامل HTTP المباشر بدلًا من موصّل MCP البعيد. لهذا الإعداد، عُد إلى عنوان الموصّل وتدفّق OAuth في المتصفح. وإذا كنت تقصد استخدام أتمتة في الطرفية أو طلبات HTTP مباشرة، فاستخدم بدلًا من ذلك [مرجع Agent API](/docs/api/).

## الإعداد سريع، لكن حلقة المراجعة هي الأهم

لا يتطلب ربط Claude بخدمة Expense Budget Tracker سوى عنوان واحد وتسجيل الدخول عبر المتصفح. لكن ما يحافظ على أمان العمل بعد الإعداد هو هذا الروتين: اعرض قائمة مساحات العمل، وافحص مخطط قاعدة البيانات، واقرأ أولًا، وامنح أضيق نطاق ممكن، واجعل عمليات الكتابة محددة بما يكفي لمراجعتها سطرًا بسطر.

ابدأ من [توثيق موصّل MCP الكامل](/docs/mcp-connector/)، وأضف `https://mcp.expense-budget-tracker.com/mcp` ضمن **Customize > Connectors**، ثم نفّذ مراجعة شهرية للقراءة فقط. وعندما تحتاج لاحقًا إلى إجراء تغيير، اطلب من Claude عرض مساحة العمل والسجل وعبارة SQL والأثر المتوقع قبل أن توافق. هذه الحلقة هي ما يحوّل ربط متتبّع المصروفات بـ Claude من عرض تجريبي مريح إلى سير عمل مالي يمكنك الوثوق به فعلًا.
