ينبغي لمتتبع مصروفات مفيد يعمل مع Claude Code أن يبدأ بالقراءة لا بالكتابة. قبل تسجيل أي معاملة بنكية في دفتر الأستاذ، يستطيع Claude Code تحديد مساحة العمل، وفحص المخطط الحالي، والتحقق من الحساب المستهدف والنطاق الزمني، ثم عرض التغييرات التي ينوي إجراءها.

وهنا تكمن فائدة استخدام وكيل يعمل من الطرفية لهذه المهمة. يتولى Claude Code التعامل مع الملف وطلبات HTTP، بينما يبقى الحكم المالي بيدك: ما الحساب الصحيح، وهل يمثّل الصف تحويلًا ماليًا، وما الفئة المناسبة، وهل ينبغي تنفيذ التغيير المقترح أصلًا.

وهكذا تحصل على متتبع مصروفات بالذكاء الاصطناعي يتضمن نقطة موافقة واضحة، لا مجرد روبوت محادثة مالي عام.

يدعم Expense Budget Tracker سير العمل هذا عبر واجهة Agent API المباشرة. ونقطة البداية هي رابط اكتشاف عام واحد:

```text
https://api.expense-budget-tracker.com/v1/
```

من هناك، يمكن لـ Claude Code إكمال الإعداد باستخدام رمز OTP عبر البريد الإلكتروني، وحفظ `ApiKey` طويل الأجل الذي يعيده النظام خارج ذاكرة المحادثة، وفحص المخطط المسموح به، واستخدام نقاط نهاية منفصلة للقراءة وعمليات الكتابة التي وافقت عليها.

![خياط وعميلة يراجعان نموذجًا ورقيًا وقطعة قماش تجريبية قبل قص لفة القماش كاملة](/blog/how-to-track-expenses-and-manage-your-budget-with-claude-code.png)

## ما الذي يفعله هذا الإعداد، وإلى أين تذهب البيانات؟

يعمل Claude Code في طرفيتك ويمكنه التعامل مع ملف كشف حساب تضعه في متناوله على جهازك. لكن ذلك لا يجعل سير العمل كله بلا اتصال بالإنترنت أو محليًا بالكامل.

توضح [متطلبات Claude Code الحالية من Anthropic](https://docs.anthropic.com/en/docs/claude-code/getting-started) أن الاتصال بالإنترنت مطلوب. وتتم المصادقة ومعالجة الذكاء الاصطناعي عبر Anthropic أو مزود النموذج الذي ضبطته في تثبيت Claude Code لديك. لذلك قد تُعالَج محتويات كشف الحساب ذات الصلة، والمطالبات، ونتائج API خارج جهازك وفق شروط ذلك المزود.

أما بقية مراحل المسار فمستقلة:

| المرحلة | ما الذي يحدث فيها |
|---|---|
| جهازك | يكون كشف الحساب في البداية ملفًا محليًا. ولا يحصل Claude Code إلا على صلاحية الوصول إلى الملفات التي تسمح بها. |
| Claude Code ومزود النموذج | يفسر Claude Code الملف، ويجهز الاستعلامات، ويشرح النتائج. يلزم الاتصال بالإنترنت للمصادقة ومعالجة الذكاء الاصطناعي. |
| Agent API المباشر | يرسل Claude Code طلبات القراءة المحددة وعمليات الكتابة الموافق عليها والمطلوبة للمهمة. ولا تستطيع واجهة API تصفح ملفات عشوائية على جهازك. |
| مساحة تخزين Expense Budget Tracker | تُحفظ السجلات المالية الموافق عليها في قاعدة البيانات المستضافة، أو في بنية تحتية تديرها إذا كنت تستضيف التطبيق بنفسك. |

ويختلف هذا أيضًا عن موصل MCP البعيد الخاص بـ Claude وClaude Desktop. تستخدم واجهة API المباشرة `ApiKey` طويل الأجل، وهذا هو المسار الذي يغطيه هذا الدليل. أما MCP فيستخدم OAuth عبر المتصفح على رابط مختلف، ولا يحصل على صلاحية الوصول إلى الملفات المحلية لمجرد توصيله.

إذا كان مطلبك الأساسي هو عدم وجود اتصال دائم بالبنك، فيشرح [تطبيق ميزانية من دون ربط الحساب البنكي](/blog/budget-app-without-bank-linking/) حدود البيانات هذه بمزيد من التفصيل.

## وصّل Claude Code عبر رابط الاكتشاف

ثبّت Claude Code وسجّل الدخول إليه باتباع [دليل الإعداد الرسمي](https://docs.anthropic.com/en/docs/claude-code/getting-started) من Anthropic. ويغطي [مرجع واجهة سطر الأوامر](https://docs.anthropic.com/en/docs/claude-code/cli-usage) استخدام الأوامر التفاعلية وغير التفاعلية.

بعد أن يعمل `claude` في طرفيتك، شغّله من داخل مجلد تحفظ فيه ملفاتك المالية وأعطه هذه المطالبة:

```text
اتصل بـ Expense Budget Tracker عبر https://api.expense-budget-tracker.com/v1/.
اتبع استجابة الاكتشاف بدل افتراض تفاصيل نقاط النهاية. اطلب مني البريد الإلكتروني
لحسابي، ثم الرمز المكوّن من 8 أرقام من صندوق الوارد. احفظ ApiKey الذي يعيده النظام
خارج ذاكرة المحادثة، وفقط بعد أن أوافق على موقع التخزين.

بعد تسجيل الدخول، استدعِ /me، واعرض مساحات العمل، واطلب مني تأكيد مساحة العمل
المستهدفة، واحفظها لهذا المفتاح، وافحص /schema. لا تكتب أي بيانات مالية بعد.
```

تسلسل الإعداد الأولي الحالي هو:

1. أرسل `GET https://api.expense-budget-tracker.com/v1/` واتبع الإجراءات الواردة في استجابة الاكتشاف.
2. أدخل البريد الإلكتروني للحساب عندما يطلبه Claude Code.
3. أدخل رمز البريد الإلكتروني المكوّن من 8 أرقام. عند نجاح التحقق، يعيد النظام `ApiKey` طويل الأجل.
4. احفظ المفتاح خارج ذاكرة المحادثة، ويفضل في متغير باسم `EXPENSE_BUDGET_TRACKER_API_KEY` داخل موقع وافقت عليه. لا تودعه في مستودع.
5. استدعِ `/v1/me` و`/v1/workspaces` مع `Authorization: ApiKey <key>`.
6. اختر مساحة العمل المقصودة عبر `POST /v1/workspaces/{workspaceId}/select`.
7. استدعِ `/v1/schema` قبل توليد SQL.

تُحفظ مساحة العمل المختارة لهذا المفتاح. ويمكن لطلبات SQL اللاحقة الاستغناء عن `X-Workspace-Id`، مع بقاء خيار إرسال هذا الترويس متاحًا لـ Claude Code إذا أردت تجاوز الاختيار المحفوظ لطلب واحد. وإذا كان الحساب يحتوي على مساحة عمل واحدة فقط ولم يُحفظ للمفتاح أي اختيار بعد، فيمكن لـ API حفظها واستخدامها تلقائيًا. ومع ذلك، يظل من الأفضل ذكر اسم مساحة العمل في كل مراجعة تسبق عملية كتابة.

ستجد تدفق المصادقة المفصل وإرشادات التخزين في [إعداد وكيل الذكاء الاصطناعي](/docs/agent-setup/).

## حدّد قاعدة المراجعة قبل أول عملية استيراد

يمكن لملف `CLAUDE.md` محلي أن يحفظ قواعد التشغيل لهذا المجلد المالي من دون تخزين المفتاح نفسه. اجعل التعليمات قصيرة ومحددة:

```markdown
# سير عمل Expense Budget Tracker

- ابدأ من https://api.expense-budget-tracker.com/v1/ وافحص /schema.
- استخدم POST /v1/sql/query لكل عملية قراءة.
- قبل أي كتابة، اعرض مساحة العمل المستهدفة، وعبارة SQL الدقيقة، وعدد الصفوف
  المتوقع تأثرها، وإجماليات المصدر، والتكرارات المحتملة. انتظر موافقتي الصريحة.
- استخدم POST /v1/sql/execute فقط لعبارة INSERT أو UPDATE أو DELETE التي وافقت عليها بالضبط.
- تحقق من كل عملية كتابة بطلب /v1/sql/query جديد.
- لا تخترع معاملة موازنة ولا تغيّر فئة غير مؤكدة بصمت.
- احتفظ بـ ApiKey خارج هذا الملف وخارج ذاكرة المحادثة.
```

أضف أسماء حساباتك الفعلية، وقواعد التصنيف، وقواعد التحويلات، وعملة التقارير إذا كانت ثابتة. لا تنسخ فئات الأمثلة إلى المتتبع لمجرد أن مقالًا استخدمها. ينبغي لـ Claude Code الاستعلام عن بياناتك الحالية واستخدام المخطط الفعلي.

## استورد كشف حساب بنكي واحدًا باستخدام Claude Code

أفضل بداية آمنة هي عملية استيراد صغيرة عمدًا: حساب واحد، وعملة واحدة، وفترة كشف حساب مغلقة، وملف تستطيع مراجعة كل صف فيه. ويُعد ملف CSV نقطة بداية جيدة لأن بنيته واضحة. أما التنسيقات الأخرى فتحتاج إلى فحص لاستخراج البيانات بحسب نوع الملف قبل أن تتمكن من الوثوق بالصفوف الناتجة.

### 1. ثبّت حدود بيانات المصدر

قبل أن يحلل Claude Code أي شيء، حدّد:

- الحساب البنكي والحساب المطابق له في المتتبع
- عملة الحساب
- تاريخ أول وآخر معاملة مُرحّلة في كشف الحساب
- الرصيد الافتتاحي أو آخر رصيد سابق موثوق
- الرصيد الختامي في كشف الحساب
- ما إذا كانت المعاملات المعلقة تظهر في الملف

استخدم المعاملات المُرحّلة في الاستيراد والتسوية، واترك النشاط المعلق خارج الدفعة الموافق عليها إلى أن يُرحّل.

### 2. افحص الوجهة قبل إعداد صفوف الاستيراد

اطلب من Claude Code استخدام نقطة نهاية القراءة أولًا:

```text
أريد استيراد ~/finances/checking-2026-07.csv.

استخدم /v1/sql/query فقط. أكّد مساحة العمل المختارة، وافحص /v1/schema، واعرض
الحسابات المتاحة، وحدد الحساب الوحيد المطابق لكشف الحساب هذا. استعلم في
ledger_entries عن الفترة التي يغطيها كشف الحساب وابحث عن أي تداخل. اعرض الحساب،
والعملة، والحدود الزمنية، وعدد الصفوف الموجودة، وأي تكرارات محتملة. لا تكتب شيئًا.
```

نقطة نهاية القراءة الأساسية هي:

```text
POST https://api.expense-budget-tracker.com/v1/sql/query
```

وهي تقبل عبارة `SELECT` واحدة مخصصة للقراءة فقط، أو عبارة `WITH ... SELECT`. ويحتوي جسم الطلب على SQL مكتوب وفق المخطط الحالي الذي يعيده `/schema`:

```json
{
  "sql": "SELECT * FROM accounts LIMIT 100"
}
```

ينبغي لـ Claude Code حساب الإجماليات وتجميع النتائج داخل SQL بدل سحب دفتر الأستاذ بأكمله إلى المحادثة. ويقتصر ناتج الاستعلام على 100 صف.

### 3. راجع معاينة، لا وعدًا

اجعل Claude Code يحلل كشف الحساب ويحوّله إلى جدول معاينة قبل أن ينشئ عبارة `INSERT`. ينبغي أن تشمل المعاينة، كحد أدنى، الصف الأصلي في الملف، والتاريخ، والمبلغ، والعملة، والحساب المستهدف، ونوع المعاملة المقترح، والفئة المقترحة، وحالة الاشتباه في التكرار.

راجع هذه الصفوف بعناية:

- التحويلات بين حساباتك
- المبالغ المستردة والتعويضات
- السحوبات النقدية والرسوم البنكية
- الأطراف المقابلة غير المألوفة
- المعاملات بالعملات الأجنبية
- الصفوف القريبة من بداية فترة كشف الحساب ونهايتها
- أي صف مرشح يشبه قيدًا موجودًا بالفعل في دفتر الأستاذ

قد يشير تطابق التاريخ والمبلغ إلى وجود تكرار، لكنه ليس دليلًا قاطعًا؛ فقد تتطابق معاملتان صحيحتان في كليهما. إذا كان الملف المصدر يتضمن معرّفًا بنكيًا ثابتًا وكان المخطط الفعلي يحتوي على حقل مناسب، فاستخدمه كدليل. وإلا فاحتفظ به في المعاينة بدل فرضه على قاعدة البيانات.

بعد ذلك، اطلب ملخص موافقة موجزًا:

```text
جهّز معاينة الاستيراد من دون كتابة. اعرض:

1. مساحة العمل والحساب المؤكدين
2. النطاق الزمني للمصدر وعملته
3. عدد صفوف المصدر ومجموع مبالغها مع مراعاة الإشارة
4. كل صف مقترح للسجل
5. التكرارات المحتملة والتصنيفات غير المؤكدة
6. عبارة `INSERT` الدقيقة أو العبارات الدقيقة من النوع نفسه التي سترسلها
7. العدد المتوقع للصفوف المتأثرة

توقف وانتظر موافقتي.
```

### 4. نفّذ مجموعة التغييرات الموافق عليها فقط

نقطة نهاية الكتابة الأساسية هي:

```text
POST https://api.expense-budget-tracker.com/v1/sql/execute
```

وهي تقبل عبارة `INSERT` أو `UPDATE` أو `DELETE` واحدة تمت الموافقة عليها، بما فيها صيغ `WITH` المدعومة. وقد فُصلت عمدًا عن نقطة نهاية القراءة.

لا يجوز أن يؤثر أي تغيير في أكثر من 100 صف. عند استيراد ملف طويل، وافق على مجموعة التغييرات المقترحة كاملة قبل التنفيذ. ينبغي لـ Claude Code إرسال عينة اختبارية من 1–3 صفوف تستخدم بنية عبارة SQL نفسها أولًا. إذا نجح هذا الاختبار، فعليه المتابعة فورًا بالصفوف الموافق عليها المتبقية في دفعات متتالية لا تزيد كل منها على 100 صف. يجب أن يتتبع كل دفعة ويتحقق منها، لكن من دون التوقف لمجرد مطالبتك بالمتابعة أو إعادة التأكيد. تنشأ نقطة مراجعة جديدة إذا تغيّر النطاق، أو ظهر غموض جديد، أو فشل التنفيذ.

لا تدعم واجهة SQL عبارة `ON CONFLICT`، لذلك يجب التعامل مع التكرارات بوضوح بدل إخفائها خلف عملية إدراج أو تحديث (upsert).

لا تزال `POST /v1/sql` موجودة للتوافق وللبرامج النصية الذرية المقيدة التي تتضمن عبارات متعددة. لكنها ليست نقطة النهاية المعتادة لقراءة كشوف الحساب أو عمليات الكتابة الروتينية.

### 5. أعد قراءة الصفوف بعد التنفيذ

لا تعني استجابة النجاح من API أن عملية الاستيراد انتهت. اطلب من Claude Code إعادة الاستعلام عن الحساب والفترة المعنيين عبر `/v1/sql/query`، ثم مقارنة النتيجة المخزنة بالمعاينة التي وافقت عليها:

- عدد الصفوف المتأثرة
- التواريخ والمبالغ
- العملة الأصلية
- إسناد الصفوف إلى الحساب
- أنواع المعاملات والفئات
- عدد التكرارات

لا تطلب من Claude Code «إصلاح كل ما يبدو خطأ». إذا كشف التحقق عن اختلاف، فعد إلى تشخيص للقراءة فقط، وجهّز تصحيحًا محددًا واحدًا، ثم وافق على ذلك التصحيح بصورة منفصلة.

يتناول [الدليل الأشمل لاستيراد كشوف الحساب البنكية](/blog/how-to-import-bank-statements-into-an-expense-tracker/) التحويلات، والمبالغ المستردة، والفترات المتداخلة، وغيرها من الصفوف التي قد تجعل استيرادًا يبدو منظمًا رغم أنه مضلل.

## سوِّ حسابًا واحدًا قبل استيراد حساب آخر

تُثبت التسوية أن حركات دفتر الأستاذ تفسّر كشف الحساب البنكي. قارن حسابًا بنكيًا واحدًا بحسابه المطابق في المتتبع، بالعملة نفسها وعلى الحدود الزمنية نفسها للمعاملات المُرحّلة.

بالنسبة إلى حساب إيداع عادي، تكون المعادلة الأساسية:

**الرصيد الختامي المتوقع = الرصيد الافتتاحي + التدفقات الداخلة المُرحّلة − التدفقات الخارجة المُرحّلة**

إذا كان المتتبع يستخدم حركات مالية بإشارات موجبة وسالبة، فالصيغة المكافئة هي:

**الرصيد الختامي المتوقع = الرصيد الافتتاحي + مجموع الحركات المُرحّلة بإشاراتها**

قد تستخدم حسابات الخصوم، مثل بطاقات الائتمان، قواعد مختلفة للإشارات. اجعل Claude Code يذكر القاعدة التي وجدها قبل مقارنة الأرقام.

استخدم مطالبة تُبقي التشخيص للقراءة فقط:

```text
استخدم /v1/sql/query فقط. سوِّ الحساب الجاري المستورد مع الرصيد الختامي في كشف الحساب
البالغ [المبلغ والعملة]. اذكر حد البداية وقاعدة الإشارات. إذا اختلف الرصيدان، فاعرض
الفرق الدقيق واسرد الصفوف المحتمل أن تكون مفقودة، أو مكررة، أو ذات إشارة خاطئة.
لا تُدرج قيد موازنة ولا تغيّر البيانات الموجودة.
```

إذا لم يكن الفرق صفرًا، فافحص الرصيد الافتتاحي، والمعاملات المفقودة أو المكررة، والتحويلات، والعناصر المعلقة، والإشارات، والتواريخ، والعملات. يجعل قيد الموازنة المصطنع الأرقام على الشاشة متطابقة، لكنه يخفي السبب.

يثبت الفرق الصفري أن حركات الحساب متوازنة حسابيًا، لكنه لا يثبت صحة الفئات. راجع إجماليات الفئات بصورة منفصلة قبل الانتقال إلى الحساب التالي. ويتعمق [دليل تسوية الميزانية مع الرصيد البنكي](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) في هذا الفرق.

## حلّل الإنفاق عبر نقطة نهاية القراءة

بعد التحقق من الاستيراد، يمكن لـ Claude Code استخدام `ledger_entries` لإجراء تحليل إنفاق للقراءة فقط. اجعل سؤالك محددًا واطلب SQL حتى تتمكن من مراجعة التعريف الذي بُنيت عليه الإجابة.

```text
افحص /v1/schema، ثم استخدم /v1/sql/query لمقارنة الإنفاق حسب الفئة خلال آخر
ثلاثة أشهر تقويمية مكتملة. حدّد تاريخي البداية والنهاية صراحة قبل كتابة SQL.
استبعد التحويلات وفق نوع المعاملة المخزن. نفّذ التجميع في SQL، واعرض الاستعلام،
واشرح أي صفوف مستبعدة أو غير مؤكدة. لا تغيّر البيانات.
```

هذا مهم لأن «الإنفاق» ليس عمودًا موحدًا في كل مكان. فالإجابة المفيدة تعتمد على المخطط الحالي، وأنواع المعاملات، وعملة الحساب، والمبالغ المستردة، والحد الزمني الدقيق. يمكن لـ Claude Code كتابة الاستعلام، لكن يجب أن يظل بإمكانك رؤية ما أدخله في الحساب.

ولإجراء استقصاء محدد لمرة واحدة، اطرح أسئلة مثل:

- ما الفئات التي تغيّرت أكثر بين شهرين مكتملين؟
- ما الأطراف المقابلة التي تشكّل إجمالي فئة معينة؟
- هل توجد تكرارات محتملة في أحدث فترة مستوردة؟
- ما فئات الإنفاق الفعلية التي لا يقابلها بند في الميزانية؟

عادة ما يكفي حد النتائج البالغ 100 صف عندما يجمع Claude Code البيانات ويرشحها على مستوى قاعدة البيانات.

## حدّث ميزانيتك باستخدام Claude Code من دون التنازل عن القرار

تستخدم تغييرات الميزانية دورة المراجعة نفسها المستخدمة في استيراد كشوف الحساب. يمكن لـ Claude Code قراءة `budget_lines`، ومقارنة الخطة بالنشاط الفعلي في السجل، وتجهيز عبارة `INSERT` أو `UPDATE` أو `DELETE` مقترحة. وأنت تقرر ما إذا كانت المبالغ الجديدة تعكس خططك.

```text
استخدم /v1/sql/query لمقارنة دخل هذا الشهر وإنفاقه الفعليين مع budget_lines.
ثم جهّز مسودة ميزانية الشهر المقبل باستخدام الفئات الموجودة والمخطط الحالي.

اعرض المبلغ الحالي، والمبلغ المقترح، والفرق، وسبب تغيير كل بند. اعرض SQL الدقيق
وعدد الصفوف المتوقع تأثرها. لا تستدعِ /v1/sql/execute حتى أوافق على بنود محددة.
بعد عملية كتابة موافق عليها، استعلم عن تلك البنود مرة أخرى للتحقق منها.
```

لا تدع شهرًا مرتفع الإنفاق يتحول بصمت إلى الخطة الجديدة. فقد يكون المصروف الكبير استثنائيًا، وقد تكون الفئة المفقودة مشكلة في البيانات، وقد يكون تحويل مالي قد صُنّف خطأ. يستطيع Claude Code إظهار الفروق، لكن الميزانية التي تديرها من خلاله تظل بحاجة إلى حكمك على ما ينبغي فعله بعد ذلك.

## افهم الحدود الحالية لـ Agent API

يعرض API مجموعة محدودة من العلاقات. تعامل دائمًا مع `/v1/schema` بوصفه المرجع المعتمد للحالة الحالية، لكن الفصل الراهن بين القراءة والكتابة هو:

| العلاقة | الصلاحية |
|---|---|
| `ledger_entries` | قراءة وكتابة بعد الموافقة |
| `budget_lines` | قراءة وكتابة بعد الموافقة |
| `workspace_settings` | قراءة وكتابة بعد الموافقة |
| `account_metadata` | قراءة وكتابة بعد الموافقة |
| `accounts` | قراءة فقط |
| `fx_rates_raw` | قراءة فقط |
| `fx_rates_daily` | قراءة فقط |

الحدود الحالية لـ Agent API هي:

- 100 صف مُعاد لكل استعلام
- 100 صف متأثر لكل عبارة تغيير ولكل طلب
- مهلة إجمالية قدرها 25 ثانية لطلب SQL
- 10 طلبات في الثانية و10,000 طلب يوميًا لكل مفتاح

تحظر سياسة SQL أوامر DDL مثل `CREATE` و`DROP` و`ALTER`، وأوامر التحكم في المعاملات، وتعليقات SQL، والمعرّفات المقتبسة، والسلاسل النصية المقتبسة بعلامة الدولار، و`set_config()`، والدوال المقيدة. والدوال المسموح بها حاليًا هي `SUM` و`COUNT` و`MIN` و`MAX` و`AVG` و`COALESCE`. استخدم `ILIKE` بدل `LOWER(...)` للبحث النصي غير الحساس لحالة الأحرف، ونطاقات تاريخ صريحة بدل `NOW()` أو `DATE_TRUNC()`. تقبل نقاط النهاية الأساسية عبارة واحدة لكل طلب، ولا تدعم `ON CONFLICT`.

تحصر هذه الضوابط نطاق SQL، لكنها لا تقرر ما إذا كانت الفئة صحيحة أو ما إذا كان صف في كشف الحساب يمثل تحويلًا بالفعل. وتعزل Row Level Security مساحات العمل على مستوى قاعدة البيانات. وتُخزّن مفاتيح ApiKey في صورة تجزئات SHA-256، ويمكن إلغاؤها من المنتج. ومع ذلك، ينبغي لك حماية المفتاح بصيغته النصية على جهازك ومراجعة كل تغيير مالي.

راجع [مرجع API](/docs/api/) للاطلاع على عقد نقاط النهاية وحدودها الحالية.

## Agent API في Claude Code ومسار MCP في Claude منفصلان

غالبًا ما تخلط نتائج البحث عن متتبع مصروفات متوافق مع Claude بين الاستخدام من الطرفية وموصلات Claude أو Claude Desktop. يدعم Expense Budget Tracker المسارين، لكن إعداد كل منهما وبيانات اعتماده غير قابلة للتبادل.

| | Claude Code مع Agent API | Claude أو Claude Desktop مع MCP |
|---|---|---|
| الأنسب لـ | الملفات المحلية، وسير العمل من الطرفية، والنصوص البرمجية، وHTTP المباشر | المحادثات داخل عميل Claude يدعم MCP |
| ابدأ من هنا | `https://api.expense-budget-tracker.com/v1/` | `https://mcp.expense-budget-tracker.com/mcp` |
| المصادقة | رمز OTP عبر البريد الإلكتروني، ثم `ApiKey` طويل الأجل | OAuth عبر المتصفح |
| واجهة القراءة والكتابة | `/v1/sql/query` و`/v1/sql/execute` | أداة `sql_query` وأداة `sql_execute` الاختيارية |
| الوصول إلى الملفات المحلية | يعتمد على الملفات والصلاحيات المتاحة لـ Claude Code | لا يوفره الموصل البعيد نفسه |

استخدم [توثيق موصل MCP](/docs/mcp-connector/) أو [الدليل الكامل لموصل MCP الخاص بمتتبع مصروفات Claude](/blog/claude-expense-tracker-mcp-connector/) إذا كان هدفك توصيل Claude أو Claude Desktop. واستمر في استخدام سير عمل Agent API هذا عندما تبدأ المهمة من كشف حساب محلي ومن الطرفية.

## مطالبة واحدة قابلة لإعادة الاستخدام لسير العمل بأكمله

تحافظ هذه المطالبة على الاكتشاف، والمعاينة، والموافقة، والتحقق ضمن تسلسل واحد:

```text
اتصل بـ Expense Budget Tracker عبر https://api.expense-budget-tracker.com/v1/
واتبع استجابة الاكتشاف. استخدم ApiKey المحفوظ خارج ذاكرة المحادثة. استدعِ /me،
واعرض مساحات العمل، وأكّد معي مساحة العمل المستهدفة، واخترها، ثم افحص /schema.

أريد استيراد [مسار ملف CSV المحلي] إلى [الحساب] خلال [نطاق زمني مغلق] بعملة [العملة].
استخدم /v1/sql/query أولًا لفحص الحساب، والفئات الموجودة، وقيود دفتر الأستاذ
المتداخلة زمنيًا. حلل الملف وجهّز معاينة كاملة. علّم التكرارات المحتملة، والتحويلات،
والمبالغ المستردة، والتعويضات، والرسوم، والأطراف المقابلة غير المعتادة، والفئات غير المؤكدة.

اعرض إجماليات المصدر، والصفوف المقترحة، وSQL الدقيق، وعدد الصفوف المتوقع تأثرها. لا
تكتب حتى أوافق على مجموعة التغييرات كاملة. استخدم /v1/sql/execute فقط لعملية الكتابة
الموافق عليها. عند استيراد ملف طويل، أرسل أولًا اختبارًا تمثيليًا من 1–3 صفوف. إذا نجح،
فتابع فورًا بالصفوف الموافق عليها المتبقية في دفعات متتالية لا تزيد على 100 صف.
تحقق من كل دفعة عبر /v1/sql/query، لكن لا تطلب مني إعادة التأكيد إلا إذا تغيّر النطاق،
أو ظهر غموض جديد، أو فشل التنفيذ.

وأخيرًا، سوِّ هذا الحساب الواحد مع الرصيد الختامي في كشف الحساب. إذا لم يتطابق الرصيدان،
فاشرح الفرق من دون إنشاء معاملة موازنة أو تغيير البيانات.
```

ابدأ بحساب واحد وفترة مغلقة واحدة. إذا كانت المعاينة مفهومة، وعادت الصفوف الموافق عليها صحيحة عند قراءتها، وتطابق الرصيد الختامي في التسوية، فقد أصبح لديك سير عمل قابل للمراجعة لإدارة شؤونك المالية الشخصية عبر Claude — لا روبوت محادثة يملك صلاحية مبهمة لتغيير دفاترك.
