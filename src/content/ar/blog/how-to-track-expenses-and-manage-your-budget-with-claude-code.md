قد تنتهي تسوية كشف حساب من أربعة صفوف إلى فرق قدره `€0.00`، ومع ذلك تظل ميزانيتك خاطئة. فإذا صنّفت مشتريات سوبرماركت بقيمة €54.20 ضمن السفر بدلًا من البقالة، سيظل رصيد الحساب صحيحًا تمامًا، لكن تقرير الفئات سينحرف بمقدار €54.20.

لذلك يحتاج أي متتبع مصروفات عملي مع Claude Code إلى فحصين لا فحص واحد: يجب أن تفسّر الحركات المسجلة رصيد البنك، وأن تطابق فئاتها كشف الحساب الذي راجعته. يستطيع Claude Code تحليل الملف وإجراء الحسابات واستدعاء API. أما أنت فتختار الحساب والفئات، وتراجع السجلات المقترحة، ثم توافق على عمليات الكتابة نفسها.

لا يتصل Expense Budget Tracker بالبنك اتصالًا مباشرًا، ولا يتيح رفع كشف الحساب ضمن هذا الإعداد. عليك تصدير الكشف بنفسك، ووضعه في مكان يستطيع Claude Code قراءته، ثم إرسال السجلات التي وافقت عليها فقط عبر واجهة Agent API المُدارة. وإذا كان هدفك الأساسي تجنّب منح وصول دائم إلى البنك، فراجع [تطبيق ميزانية من دون ربط حساب بنكي](/blog/budget-app-without-bank-linking/) لفهم المفاضلات الأوسع.

## اربط Claude Code برابط اكتشاف واحد

ثبّت Claude Code وسجّل الدخول باتباع [دليل البدء السريع الرسمي](https://code.claude.com/docs/en/quickstart) من Anthropic. ويوضح [مرجع CLI](https://code.claude.com/docs/en/cli-reference) آلية عمل مجلدات العمل ومنح حق الوصول إلى ملفات إضافية.

شغّل `claude` من المجلد الذي يحتوي على كشف الحساب، أو امنحه حق الوصول إلى مجلد الكشف بطريقة يدعمها إعدادك. ثم الصق هذه المطالبة:

```text
اتصل بـ Expense Budget Tracker عبر رابط الاكتشاف التالي:
https://app.expense-budget-tracker.com/api/agent

اجلب الرابط بطلب GET، واقرأ JSON الذي يعيده، واتبع عناوين URL الحالية للإجراءات.
لا تخمّن مسار API ولا تضمّنه مباشرة في الشيفرة. اطلب مني عنوان بريدي الإلكتروني في
Expense Budget Tracker، ثم ابدأ مسار رمز OTP عبر البريد الإلكتروني.
بعد نجاح الطلب، اطلب مني التحقق من مجلد الرسائل المزعجة أو غير المرغوب فيها إذا لم
تظهر الرسالة، ثم اطلب الرمز المكوّن من 8 أرقام واتبع إجراء التحقق الذي أعادته الخدمة.

بعد التحقق، اطلب موافقتي على موقع دائم لتخزين ApiKey الذي أعادته الخدمة، على أن يكون
خارج ذاكرة المحادثة ونظام التحكم في المصدر. حمّل سياق حسابي واعرض مساحات العمل، ثم
اطلب مني تأكيد مساحة العمل المستهدفة، واحفظها بوصفها المساحة الافتراضية لهذا المفتاح،
وافحص المخطط المباشر. نفّذ استعلامًا صغيرًا واحدًا للقراءة فقط لتأكيد مساحة العمل
المختارة. لا تكتب أي بيانات مالية.
```

يعيد [رابط الوكيل الخاص بالتطبيق](https://app.expense-budget-tracker.com/api/agent) مستند الاكتشاف المباشر. وهو يوفّر حاليًا `https://api.expense-budget-tracker.com/v1/` بوصفه عنوان API الأساسي، إلى جانب عناوين URL الخاصة بإجراءات المصادقة وSQL. الصق رابط نطاق التطبيق، ودع Claude Code يتبع العناوين التي تعيدها الخدمة بدلًا من حفظ التسلسل الداخلي.

يُستخدم مسار البريد الإلكتروني نفسه للتسجيل وتسجيل الدخول. بعد أن تزوّد Claude Code بالرمز المكوّن من 8 أرقام، سيحصل على `ApiKey` طويل الأجل. وافق على موقع محدد لتخزينه، مثل ملف أسرار مستبعد من نظام التحكم في المصدر. لا تضع المفتاح أبدًا في `CLAUDE.md` ولا تضِفه إلى أي مستودع. يشرح [إعداد وكيل الذكاء الاصطناعي](/docs/agent-setup/) تسلسل المصادقة ومساحة العمل بالتفصيل.

## ميّز بين إعداد Agent API وإعداد MCP

قد يُقصد بعبارة «متتبع مصروفات Claude» أحد تكاملين مختلفين. يشرح هذا المقال استخدام Claude Code من الطرفية مع Agent API. أما Claude وClaude Desktop فيمكنهما استخدام موصل MCP البعيد والمستضاف.

| | Claude Code مع Agent API | Claude أو Claude Desktop مع MCP |
|---|---|---|
| الأنسب | العمل من الطرفية مع ملفات محلية متاحة واتصال HTTP مباشر | المحادثات في عميل Claude يدعم MCP |
| نقطة البداية | `https://app.expense-budget-tracker.com/api/agent` | `https://mcp.expense-budget-tracker.com/mcp` |
| المصادقة | رمز OTP عبر البريد الإلكتروني، ثم `ApiKey` طويل الأجل | OAuth عبر المتصفح |
| واجهة البيانات | عناوين URL للاكتشاف تقود إلى نقطتي الاستعلام والتنفيذ | أداة `sql_query` وأداة `sql_execute` الاختيارية |
| الوصول إلى كشف الحساب | الملفات والمجلدات المتاحة لجلسة Claude Code الحالية | لا يتيح الموصل البعيد الوصول إلى الملفات المحلية |

بيانات الاعتماد في الإعدادين غير قابلة للتبادل. إذا كنت تستخدم تطبيق Claude على الويب أو سطح المكتب، فاتبع [دليل موصل MCP لمتتبع مصروفات Claude](/blog/claude-expense-tracker-mcp-connector/). أما مسار Agent API أدناه فهو المناسب عندما تبدأ المهمة بملف يستطيع Claude Code الوصول إليه.

وهناك حدّان آخران من المفيد توضيحهما:

- معالجة مزوّد النموذج منفصلة عن API والتخزين في Expense Budget Tracker. قبل مشاركة بيانات كشف الحساب، راجع [توثيق استخدام البيانات في Claude Code](https://code.claude.com/docs/en/data-usage) وشروط المزوّد المضبوط في تثبيتك.
- يشغّل إعداد Docker Compose المحلي الموضح في [دليل الاستضافة الذاتية](/docs/self-hosting/) تطبيق الويب وخدمة المصادقة وقاعدة البيانات وعامل FX. لكنه لا يوفّر واجهة Agent API المُدارة المستخدمة هنا. أما نشر المستودع على AWS فهو إعداد منفصل يتضمن واجهة API عامة مخصصة للآلات.

## حدّد نطاق الاستيراد بدقة

ابدأ في المحاولة الأولى بحساب واحد وعملة واحدة وفترة كشف حساب مكتملة ومغلقة. يُعد CSV خيارًا مناسبًا لأن صفوفه سهلة الفحص. وإذا كان التصدير بصيغة أخرى، فاطلب أولًا من Claude Code التأكد من قدرته على قراءة الملف في بيئتك وعرض الصفوف بعد تحليلها. لا تفترض أن الملف مدعوم بناءً على اسمه وحده.

زوّد Claude Code بهذه المعلومات الست:

1. المسار المحلي لكشف الحساب.
2. الحساب البنكي والحساب المطابق له في المتتبع.
3. عملة الحساب.
4. تاريخا قيد أول معاملة وآخر معاملة.
5. الرصيد الافتتاحي أو آخر رصيد سابق تأكدت من صحته.
6. الرصيد الختامي في كشف الحساب.

استبعد المعاملات المعلّقة إلى أن تُقيّد فعليًا. واحتفظ بالملف المصدر كما هو، واطلب من Claude Code إعداد معاينة منفصلة.

يمكنك استخدام القواعد التالية في ملف `CLAUDE.md` محلي داخل مجلد الشؤون المالية:

```markdown
# سير عمل Expense Budget Tracker

- ابدأ من https://app.expense-budget-tracker.com/api/agent واتبع مستند الاكتشاف.
- أكّد مساحة العمل المستهدفة وافحص المخطط المباشر قبل كتابة SQL.
- استخدم إجراء القراءة في جميع عمليات الفحص والتسوية.
- قبل أي كتابة، اعرض إجماليات المصدر، والتكرارات المحتملة، ونص SQL الدقيق، وعدد الصفوف المتوقع تأثرها.
- انتظر موافقتي الصريحة على مجموعة التغييرات كاملة.
- استخدم إجراء الكتابة فقط لعبارة INSERT أو UPDATE أو DELETE التي وافقت عليها.
- تحقّق من كل كتابة بقراءة جديدة.
- لا تنشئ قيد موازنة ولا تحسم بصمت فئة غير مؤكدة.
- احتفظ بـ ApiKey خارج هذا الملف وخارج نظام التحكم في المصدر.
```

أضف التفاصيل الثابتة، مثل أسماء حساباتك الفعلية، وقواعد التصنيف، وطريقتك في تسجيل التحويلات، وعملة التقارير. ولا تنسخ فئات الأمثلة الواردة في هذا المقال إلا إذا كانت تطابق دفتر أستاذك.

## استورد كشف الحساب بعد معاينته كاملًا

بعد نجاح الاتصال، الصق المطالبة التالية واستبدل القيم بين الأقواس المربعة:

```text
استورد [المسار المحلي لكشف الحساب] إلى [الحساب في المتتبع] عن الفترة من [تاريخ بدء
القيد] حتى [تاريخ انتهاء القيد] بعملة [العملة]. الرصيد الافتتاحي هو [المبلغ]، والرصيد
الختامي في البنك هو [المبلغ].

أكّد أولًا مساحة العمل المختارة وافحص المخطط المباشر. استخدم إجراء القراءة فقط لفحص
الحساب المستهدف، والفئات الموجودة، وصفوف دفتر الأستاذ التي تتداخل مع فترة كشف الحساب.
أكّد قدرتك على قراءة الملف المحلي وتحليله وإعداد معاينة كاملة من دون كتابة أي شيء.

لكل صف في المصدر، اعرض معرّفه أو رقم الصف، وتاريخ القيد، والمبلغ مع إشارته، والعملة،
والحساب المستهدف، ونوع المعاملة المقترح، والفئة المقترحة، وحالة التكرار. ضع علامة على
التحويلات، والمبالغ المستردة، والتعويضات، والرسوم، والصفوف بعملات أجنبية، والجهات غير
المألوفة في المعاملات، والتصنيفات غير المؤكدة.

بعد ذلك، اعرض عدد صفوف المصدر ومجموع مبالغها مع الإشارات، وجميع صفوف دفتر الأستاذ
المقترحة، والتكرارات المحتملة، ونص SQL الدقيق الذي سترسله، وعدد الصفوف المتوقع تأثرها.
توقف وانتظر موافقتي الصريحة على مجموعة التغييرات كاملة.
```

يظل التعامل مع قاعدة البيانات مقتصرًا على القراءة إلى أن توافق على التغيير. على Claude Code أن يفحص المخطط المباشر بدلًا من نسخ أسماء الأعمدة من مقال، وأن يعثر على الحساب المطابق، ويستعلم عن الصفوف الموجودة ضمن التواريخ نفسها. تطابق التاريخ والمبلغ يجعل المعاملة مرشحة لأن تكون مكررة، لكنه لا يثبت تكرارها؛ فقد تتطابق عمليتا شراء سليمتان في الحقلين.

### مثال عملي من أربعة صفوف

لنفترض أن كشف حساب جارٍ يبدأ برصيد قدره €1,250.00 ويضم أربع معاملات مقيّدة:

| الصف | تاريخ القيد | الوصف | المبلغ مع إشارته | النوع المقترح | الفئة المقترحة | ملاحظة المراجعة |
|---|---|---|---:|---|---|---|
| 1 | 2026-08-31 | راتب | +€2,000.00 | دخل | راتب | واضح |
| 2 | 2026-09-02 | سوبرماركت | −€54.20 | مصروف | بقالة | تحقّق من التاجر إن لم يكن مألوفًا |
| 3 | 2026-09-03 | تحويل إلى المدخرات | −€300.00 | تحويل | — | أكّد الحساب الآخر |
| 4 | 2026-09-04 | مقهى | −€8.40 | مصروف | مطاعم | واضح |

مجموع المبالغ الأربعة، مع احتساب إشاراتها، هو `+€1,637.40`. وبإضافته إلى الرصيد الافتتاحي البالغ `€1,250.00`، يصبح الرصيد الختامي المتوقع `€2,887.40`. يمكن عرض هذا المثال كاملًا على شاشة واحدة، لكن أي استيراد أطول يجب أيضًا أن يتضمن كل صف من المصدر في المعاينة، وأن يوضح كل نقطة غير مؤكدة.

يجب تأكيد الحساب الآخر في التحويل، لأن نقل المال بين حساباتك لا يُعد إنفاقًا. ويجب كذلك الاحتفاظ بالنوع الصحيح للمبالغ المستردة والتعويضات. وإذا لم يكن التصنيف مؤكدًا، فاتركه معلّمًا لاتخاذ قرار بدلًا من اختيار الفئة التي تبدو أقرب.

### وافق على مجموعة تغييرات بعينها

راجع مساحة العمل، والحساب، والنطاق الزمني، وعدد الصفوف، ومجموع المبالغ مع إشاراتها، والتكرارات المحتملة، والتصنيفات. وافق على المعاينة ونص SQL المحددين، ولا تكتفِ بتعليمات عامة مثل «استورد كل شيء».

تفصل Agent API بين القراءة والكتابة. يستخدم Claude Code إجراء القراءة الذي اكتشفه لتنفيذ عبارة `SELECT` واحدة أو `WITH ... SELECT`، ثم يستخدم إجراء الكتابة فقط لتنفيذ عبارة `INSERT` أو `UPDATE` أو `DELETE` وافقت عليها صراحة. يظل المخطط المباشر هو المرجع المعتمد لأسماء الجداول والأعمدة؛ ويشرح [مرجع API](/docs/api/) عقد SQL وحدوده.

### اختبر عمليات الإدراج والتحديث الطويلة قبل تقسيمها

قبل تنفيذ عبارة `INSERT` أو `UPDATE` طويلة، تطلب تعليمات الاكتشاف المباشرة من الوكيل إرسال اختبار تمهيدي ممثل بالبنية نفسها لعبارة SQL: من صف واحد إلى 3 صفوف بقيم حرفية في حالة `INSERT`، أو صف مستهدف واحد في حالة `UPDATE`. تشمل موافقتك هذا الاختبار وبقية الصفوف في مجموعة التغييرات التي راجعتها.

إذا نجح الاختبار، فعلى Claude Code المتابعة فورًا بدفعات متسلسلة لا تتجاوز كل منها 100 سجل، مع التحقق من كل دفعة أثناء التنفيذ. بعد اختبار 3 صفوف من عملية استيراد معتمدة تضم 247 صفًا، تتبقى ثلاث دفعات: 100 و100 و44 صفًا. يصبح من الضروري طلب موافقة جديدة إذا تغيّر النطاق، أو ظهر غموض جديد، أو فشل التنفيذ. أما الدفعات اللاحقة المعتادة ضمن المجموعة المعتمدة نفسها فلا تحتاج إلى موافقة جديدة.

لا تدعم نسخة SQL المقيّدة `ON CONFLICT`، لذلك يجب التعامل مع التكرارات بصورة صريحة. كما أن نتائج القراءة محدودة بـ 100 صف. على Claude Code فحص البيانات الوصفية لعدد الصفوف وما إذا كانت النتائج مقتطعة، وحساب الإجماليات داخل SQL، وتقسيم التحقق التفصيلي إلى قراءات محددة ومرتبة. فالاستجابة المقتطعة لا تكفي للتحقق من اكتمال الاستيراد.

### أعد قراءة الصفوف المحفوظة

تثبت استجابة API الناجحة أن الطلب نُفّذ، لكنها لا تثبت أن كل قيمة محفوظة تطابق المعاينة. استعلم مرة أخرى عن الحساب والفترة المتأثرين، ثم قارن:

- عدد الصفوف المدرجة
- التواريخ والمبالغ مع إشاراتها والعملات
- ربط كل معاملة بالحساب
- أنواع المعاملات والفئات
- التكرارات المحتملة
- إجماليات الدفعات والإجمالي الكامل لكشف الحساب

إذا وجدت أي اختلاف، فعُد إلى التشخيص بالقراءة فقط. راجع تصحيحًا محددًا قبل تنفيذ عملية كتابة أخرى. ويتناول [دليل استيراد كشوف الحساب البنكية](/blog/how-to-import-bank-statements-into-an-expense-tracker/) الفترات المتداخلة والمبالغ المستردة والتحويلات بمزيد من التفصيل.

## سوِّ الرصيد والفئات كلًا على حدة

تتحقق تسوية الرصيد مما إذا كانت الحركات المسجلة تفسّر الرصيد الختامي لدى البنك ضمن نطاق تواريخ القيد نفسه.

بالنسبة إلى حساب إيداع عادي:

**الرصيد الختامي المتوقع = الرصيد الافتتاحي + التدفقات الداخلة المقيّدة − التدفقات الخارجة المقيّدة**

وعند استخدام حركات تحمل إشارات موجبة وسالبة:

**الرصيد الختامي المتوقع = الرصيد الافتتاحي + مجموع الحركات المقيّدة مع إشاراتها**

قد تتبع حسابات الخصوم، مثل بطاقات الائتمان، قاعدة مختلفة للإشارات. على Claude Code توضيح القاعدة التي وجدها قبل إجراء المقارنة.

تابع بهذه المطالبة:

```text
استخدم إجراء القراءة فقط. سوِّ [الحساب] عن الفترة من [تاريخ بدء القيد] حتى [تاريخ
انتهاء القيد] مع الرصيد الختامي في البنك، وقدره [المبلغ والعملة]. اذكر نقطة البداية،
وقاعدة الإشارات، وعدد الصفوف المخزنة، وإجمالي الحركات مع إشاراتها.

اعرض الرصيد الختامي المتوقع، والرصيد الختامي في البنك، والفرق الدقيق بينهما. إذا لم
يكن الفرق صفرًا، فاعرض الصفوف التي قد تكون مفقودة، أو مكررة، أو مستبعدة، أو ذات تاريخ
خاطئ، أو ذات إشارة خاطئة. لا تُدرج قيد موازنة ولا تغيّر أي بيانات.

بعد فحص الرصيد، راجع إجماليات الفئات على نحو منفصل. اعرض الصفوف غير المصنفة،
والتحويلات المحتسبة ضمن الإنفاق، والفئات التي تختلف عن المعاينة المعتمدة.
```

في مثال الصفوف الأربعة، `€1,250.00 + €1,637.40 = €2,887.40`. وإذا كان الرصيد الختامي في البنك هو أيضًا €2,887.40، فسيكون فرق الرصيد `€0.00`.

يثبت هذا الصفر صحة حساب الرصيد ضمن النطاق المختار، لكنه لا يثبت صحة التصنيفات. فإذا نقلت معاملة السوبرماركت البالغة €54.20 من فئة البقالة إلى فئة السفر، سيظل فرق الرصيد صفرًا، بينما ينتقل مبلغ €54.20 من إجمالي فئة إلى أخرى. لذلك تُعد مراجعة الفئات فحص قبول مستقلًا.

إذا لم يكن الفرق صفرًا، فافحص الرصيد الافتتاحي، والصفوف المفقودة أو المكررة، والتحويلات، والمعاملات المعلّقة، والإشارات، والتواريخ، والعملات. لا تضف معاملة موازنة مصطنعة لمجرد إخفاء الفرق. يشرح [دليل التسوية](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) خطوات التشخيص بمزيد من التفصيل.

## لا تحدّث الميزانية قبل اكتمال التسوية

لا تنتقل إلى الميزانية إلا بعد التأكد من صحة الصفوف عند إعادة قراءتها، وتسوية الحساب، ومنطقية إجماليات الفئات. يستطيع متتبع الميزانية مع Claude Code مقارنة النشاط الفعلي ببنود `budget_lines` وإعداد تغييرات مقترحة. لكن شهرًا واحدًا غير معتاد لا ينبغي أن يحدد خطة الشهر التالي تلقائيًا.

```text
أكّد مساحة العمل وافحص المخطط الحالي. استخدم إجراء القراءة لمقارنة الدخل والإنفاق
الفعليين خلال [الفترة المكتملة] ببنود الميزانية المطابقة. استبعد التحويلات بالاعتماد
على نوع المعاملة المخزن، واعرض النشاط غير المصنف على نحو منفصل.

لكل تغيير مقترح في الميزانية، اعرض الفئة، والمبلغ الحالي، والمبلغ الفعلي، والمبلغ
المقترح، والفرق، والسبب. ثم اعرض نص SQL الدقيق وعدد الصفوف المتوقع تأثرها. لا تكتب
أي شيء حتى أوافق على بنود محددة.

بعد الموافقة، استخدم إجراء الكتابة لهذه البنود فقط، وتحقّق منها بقراءة جديدة. أبلغني
عن أي قيمة مخزنة تختلف عن المقترح الذي وافقت عليه.
```

قد يكون المصروف الكبير استثنائيًا. وقد يتضح أن التجاوز الظاهري للميزانية ليس سوى تحويل أو مبلغ مسترد صُنّف خطأ. يستطيع Claude Code حساب الفروق وإعداد SQL، لكن تحديد مبالغ الشهر التالي يظل قرارك.

## اتبع الترتيب نفسه مع كل كشف حساب

حافظ على هذا الترتيب في كل مرة:

1. ابدأ من `https://app.expense-budget-tracker.com/api/agent` واتبع مستند الاكتشاف.
2. حمّل سياق الحساب، وأكّد مساحة العمل، وافحص المخطط المباشر.
3. زوّد Claude Code بملف كشف حساب واحد يستطيع الوصول إليه، وحدّد حدود الرصيد بوضوح.
4. اقرأ بيانات دفتر الأستاذ المتداخلة مع الفترة، وأعد معاينة الاستيراد كاملة.
5. وافق على مجموعة تغييرات بعينها.
6. إذا كان الإدراج طويلًا، فابدأ باختبار من 1–3 صفوف، ثم نفّذ دفعات متسلسلة لا تتجاوز 100 صف.
7. أعد قراءة كل دفعة محفوظة وقارنها بالمعاينة.
8. سوِّ الحساب مع الرصيد الختامي لدى البنك من دون إضافة قيد موازنة.
9. راجع إجماليات الفئات حتى إذا كان فرق الرصيد صفرًا.
10. أعد أي تغييرات على بنود الميزانية، ووافق عليها، وتحقّق منها على نحو منفصل.

ابدأ بحساب واحد وفترة مكتملة واحدة. بعد أن يتحول كشف الحساب إلى دفتر أستاذ مُسوّى وميزانية راجعتها، كرر الخطوات مع الحساب التالي. يتولى Claude Code العمل المتكرر على الملف وAPI، بينما يبقى كل قرار مالي ظاهرًا أمامك قبل أن يغيّر سجلاتك.
