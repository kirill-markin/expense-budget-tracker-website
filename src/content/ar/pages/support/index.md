## دعم الخدمة المستضافة وMCP

للحصول على مساعدة بشأن التطبيق المستضاف أو الحساب أو تفويض OAuth أو خادم MCP العام، راسل [markinkirill@gmail.com](mailto:markinkirill@gmail.com). يُقدّم الدعم حسب الإمكانات المتاحة، ولا نضمن مدة محددة للرد.

أرسل فقط تفاصيل التشخيص اللازمة للتحقيق:

- اسم العميل وإصداره؛
- تاريخ العطل ووقته ومنطقته الزمنية؛
- الـ endpoint أو الصفحة المعنية؛
- خطوة OAuth أو اسم أداة MCP؛
- نص الخطأ الدقيق بعد تنقيحه ومعرّف الطلب إن ظهر؛
- ما كنت تتوقعه وما حدث بالفعل.

لا ترسل مطلقًا كلمات المرور أو ملفات تعريف ارتباط الجلسة أو رموز OAuth أو توكنات الوصول أو التحديث أو مفاتيح API أو السجلات المالية الخام أو نص الطلب الكامل دون تنقيح.

## التقارير الأمنية

لا تفصح عن ثغرة مشتبه بها في issue عامة على GitHub. راسل [markinkirill@gmail.com](mailto:markinkirill@gmail.com) واستخدم الموضوع **Expense Budget Tracker security report** مع خطوات إعادة إنتاج مختصرة ومنقحة. لا تضع بيانات اعتماد حية أو بيانات مالية. إذا كان الوصول قد انكشف، فألغِ الاتصال أولًا من **الإعدادات > وصول الوكلاء** ودوّر أي بيانات اعتماد أخرى متأثرة.

## الأخطاء والاستضافة الذاتية وأسئلة المجتمع

استخدم [متعقب issues على GitHub](https://github.com/kirill-markin/expense-budget-tracker/issues) للأخطاء القابلة لإعادة الإنتاج وأسئلة الاستضافة الذاتية ونقاشات المجتمع التي يمكن نشرها علنًا. ابحث في issues الموجودة أولًا واحذف البيانات الخاصة من السجلات ولقطات الشاشة. يغطي [دليل الاستضافة الذاتية](/ar/docs/self-hosting/) و[مستودع الشيفرة المصدرية](https://github.com/kirill-markin/expense-budget-tracker) أسئلة النشر والتطوير.

## قبل الإبلاغ عن مشكلة MCP

تأكد من أن عميلك يدعم MCP البعيد عبر Streamable HTTP ومسار Authorization Code في OAuth 2.1 مع PKCE وDynamic Client Registration. استخدم endpoint الموحد كما هو موضح تمامًا في [دليل MCP](/ar/docs/mcp/)، ثم أعد المحاولة مرة واحدة بعد إعادة الاتصال. وإذا استمرت المشكلة، فأرسل التفاصيل المنقحة المذكورة أعلاه.
