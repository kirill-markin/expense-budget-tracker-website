## 概要

Expense Budget Tracker は、ホスト型の Model Context Protocol（MCP）コネクタを提供しています。接続先は次のとおりです。

`https://mcp.expense-budget-tracker.com/mcp`

このエンドポイントは Streamable HTTP と OAuth を使います。Streamable HTTP 経由のリモート MCP と OAuth ディスカバリーに対応する MCP クライアントに、この URL を渡してください。認可の際は、ブラウザでログインしてアクセスを許可します。

コネクタの認証情報には OAuth のアクセストークンとリフレッシュトークンを使います。[Agent API リファレンス](/ja/docs/api/) の長期間有効な `ApiKey` は、HTTP で直接接続するときに使うキーです。MCP エンドポイントでは使用できません。

## OAuth ディスカバリーと接続手順

ホスト型コネクタは、保護対象リソースのメタデータを次の URL で公開しています。

`https://mcp.expense-budget-tracker.com/.well-known/oauth-protected-resource/mcp`

このメタデータから認可サーバーを特定できます。認可サーバーのメタデータは、次の URL にあります。

`https://auth.expense-budget-tracker.com/.well-known/oauth-authorization-server`

対応するクライアントは、次の手順で接続します。

1. `https://mcp.expense-budget-tracker.com/mcp` に接続し、保護対象リソースのメタデータを検出します。
2. パブリック OAuth クライアントとして動的に登録します。クライアントシークレットは使いません。
3. 認可コードフローを開始し、ユーザーのブラウザで認可 URL を開きます。
4. すべての認可リクエストに PKCE を使います。コードチャレンジ方式は `S256` のみです。
5. `expenses:read` を要求します。`sql_execute` を呼び出す必要があるときだけ `expenses:write` を追加します。
6. 認可コードをアクセストークンとリフレッシュトークンに交換します。必要に応じて、クライアントがアクセストークンを更新します。

トークンをプロンプト、チャット履歴、ソースファイル、ログにコピーしないでください。保存先は MCP クライアントの認証情報ストレージに限ります。

## スコープ

- `expenses:read` は必須です。利用可能なワークスペースの一覧取得、スキーマの確認、読み取り専用の照会を許可します。
- `expenses:write` は任意です。データの作成・変更・削除が可能な `sql_execute` を別途許可します。

作業に必要な最小限のスコープを要求してください。データの分析やレポートの作成だけを行うクライアントは `expenses:read` を要求すれば十分です。`expenses:write` は不要です。

## ツール

### `list_workspaces`

ログイン中のユーザーが利用できるワークスペースを一覧表示します。データの読み取りや変更を行う前に、返されたワークスペースの識別子で対象を明示してください。

### `get_schema`

選択したワークスペースで MCP に公開されているリレーションと列を返します。テーブル名や列名を推測せず、SQL を書く前にこのツールを呼び出してください。

### `sql_query`

選択したワークスペースで、制限付きの読み取り専用 SQL クエリを 1 つ実行します。このツールにはデータベース側でも読み取り専用の制限がかかります。結果は 100 行までで、実行の制限時間は 20 秒です。

### `sql_execute`

選択したワークスペースのデータを変更する、制限付きの SQL を実行します。データの削除も可能なため、別途 `expenses:write` スコープが必要です。呼び出しを承認する前に、対象のワークスペースと実行される SQL 文を確認してください。

MCP サーバーは `sql_execute` を通じた書き込みにも対応しています。読み取り専用が保証されるのは、データベース側で制限をかけている `sql_query` の経路です。

## 安全な使い方

1. `list_workspaces` を呼び出し、対象のワークスペースをユーザーと確認します。
2. SQL を生成する前に `get_schema` を呼び出します。
3. データの確認、集計、残高の照合、レポートには `sql_query` を使います。
4. データの変更が必要な作業でのみ `expenses:write` を要求します。
5. `sql_execute` を呼び出す前に、実行する SQL 文と予想される変更内容を示し、対象のワークスペースを再確認します。
6. 書き込み後は `sql_query` で結果を確認します。

サーバーは使える SQL の範囲と公開リレーションを制限しています。この制限に加え、生成された SQL もよく確認してください。

## 上限と制約

- SQL の結果は最大 100 行
- 実行の制限時間は 20 秒
- ログイン中のユーザーが利用できるワークスペースのみアクセス可能
- `sql_query` で使える SQL は制限され、データベース側でも読み取り専用
- `sql_execute` には、必須の読み取りスコープに加えて `expenses:write` が必要

## プライバシーとセルフホスティング

認可済みの MCP クライアントは家計データを読み取れます。`expenses:write` を付与すると、データの作成・変更・削除もできます。接続前に [プライバシーポリシー](/ja/privacy/) とクライアント側のデータ取り扱いポリシーを確認してください。

上記のホスト型 URL は、運営元が提供する Expense Budget Tracker サービス専用です。ご自身で運用する場合は [セルフホスティングガイド](/ja/docs/self-hosting/) を参照し、ご自身のドメインに合わせて MCP エンドポイントと OAuth のメタデータを設定してください。実装は [ソースリポジトリ（英語）](https://github.com/kirill-markin/expense-budget-tracker) で公開しています。
