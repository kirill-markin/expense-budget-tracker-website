امن‌ترین شروع برای کار Claude با اپ پیگیری هزینه تقریباً کسل‌کننده است: Claude فضاهای کاری را فهرست می‌کند، اسکیمای زنده را می‌بیند و یک کوئری فقط‌خواندنی اجرا می‌کند. هیچ‌چیز در دفتر کل تغییر نمی‌کند.

این شروع آرام مهم است، چون همین کانکتور می‌تواند بعداً مجوز تغییر داده‌های مالی را هم بگیرد. دسترسی خواندن و نوشتن را از هم جدا نگه دارید، فضای کاری را صریح مشخص کنید و نتیجهٔ هر تغییر را پس از اجرا بررسی کنید.

Expense Budget Tracker برای همین گردش‌کار یک کانکتور راه دور MCP دارد که به‌صورت میزبانی‌شده ارائه می‌شود:

```text
https://mcp.expense-budget-tracker.com/mcp
```

این نشانی را به Claude اضافه کنید و فرایند OAuth را در مرورگر به پایان برسانید. پس از آن، Claude از طریق چهار ابزار مشخص و محدود با Expense Budget Tracker کار می‌کند. به ترمینال، کلید API یا فایل پیکربندی محلی MCP نیازی نیست.

![چاپگری چاپ مرجع محافظت‌شده را با نمونهٔ تازه‌ای مقایسه می‌کند که از یک لوح مسی انتخاب‌شده تهیه شده است](/blog/claude-expense-tracker-mcp-connector.png)

## این راهنما برای کانکتور است، نه API مربوط به Claude Code

Expense Budget Tracker دو مسیر برای دسترسی ماشینی دارد که اعتبارنامه‌هایشان را نباید با هم اشتباه گرفت.

| | کانکتور MCP راه دور | Agent API مستقیم |
|---|---|---|
| مناسب برای | گفت‌وگو در Claude و Claude Desktop | Claude Code، Codex، اسکریپت‌ها و دیگر ایجنت‌های ترمینالی |
| نشانی شروع | `https://mcp.expense-budget-tracker.com/mcp` | `https://api.expense-budget-tracker.com/v1/` |
| احراز هویت | OAuth مرورگر | `ApiKey` بلندمدت |
| رابط | ابزارهای MCP | نقطه‌های پایانی HTTP |
| اعتبارنامه‌ها | توکن‌های دسترسی و نوسازی OAuth که کلاینت MCP نگه می‌دارد | ApiKey که بیرون از حافظهٔ چت نگه‌داری می‌شود |

نقطهٔ اتصال MCP، `ApiKey` مربوط به API مستقیم را نمی‌پذیرد و آن کلید نیز برای ساخت کانکتور سفارشی Claude کاربردی ندارد. این دو یکپارچه‌سازی، فرایندهای احراز هویت و اعتبارنامه‌های جداگانه‌ای دارند.

اگر می‌خواهید Claude را از داخل برنامهٔ وب یا دسکتاپ به یک اپ پیگیری هزینه وصل کنید، این راهنما برای شماست. اگر کارتان با جمله‌ای مثل «این CSV را از لپ‌تاپ من بخوان» شروع می‌شود، به‌جای آن سراغ گردش‌کار ترمینالیِ [چطور با Claude Code هزینه‌ها را ثبت کنید و بودجه‌تان را مدیریت کنید](/blog/how-to-track-expenses-and-manage-your-budget-with-claude-code/) بروید. [راهنمای کامل‌تر راه‌اندازی رهگیر هزینه با هوش مصنوعی](/blog/ai-agent-expense-tracker-claude-code-codex-openclaw/) نیز نحوهٔ استفاده از Claude Code، Codex و OpenClaw را از طریق API مستقیم توضیح می‌دهد.

## کانکتور Expense Budget Tracker را به Claude اضافه کنید

در حال حاضر، مسیر افزودن کانکتور در حساب‌های شخصی Claude این است: **Customize > Connectors > Add custom connector**. Anthropic جزئیات به‌روز رابط کاربری و انواع حساب را در [راهنمای کانکتور سفارشی MCP راه دور](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) منتشر می‌کند.

### ۱. نشانی MCP راه دور را اضافه کنید

Claude یا Claude Desktop را باز کنید، سپس:

1. به **Customize > Connectors** بروید.
2. روی دکمهٔ **+** کلیک کنید و **Add custom connector** را انتخاب کنید.
3. نام آن را `Expense Budget Tracker` بگذارید.
4. نشانی `https://mcp.expense-budget-tracker.com/mcp` را به‌عنوان URL سرور MCP راه دور وارد کنید.
5. روی **Add** کلیک کنید.

لازم نیست در تنظیمات Advanced، OAuth Client ID یا Client Secret وارد کنید. سرور صدور مجوز Expense Budget Tracker امکان ثبت پویای یک کلاینت عمومی OAuth را دارد و در این فرایند از Client Secret استفاده نمی‌شود.

در حساب‌های Team و Enterprise، ابتدا باید یک Owner یا Primary Owner کانکتور سفارشی را به سازمان اضافه کند. سپس هر عضو با حساب خودش متصل می‌شود و تنها به فضاهای کاری در دسترس همان کاربر دسترسی دارد.

### ۲. متصل شوید و دسترسی OAuth را تأیید کنید

کنار کانکتور جدید روی **Connect** کلیک کنید. Claude فرایند کشف مجوز MCP را دنبال می‌کند و صفحهٔ ورود Expense Budget Tracker را در مرورگر باز می‌کند. همان‌جا وارد حساب شوید و مجوزهای درخواستی را بررسی کنید.

دو دامنهٔ دسترسی نقش‌های متفاوتی دارند:

- `expenses:read` الزامی است و اجازهٔ یافتن فضاهای کاری، بررسی اسکیما و اجرای کوئری‌های فقط‌خواندنی را می‌دهد.
- `expenses:write` اختیاری است و اجازهٔ استفاده از ابزار تغییردهندهٔ `sql_execute` را می‌دهد.

برای مرور هزینه‌ها، گزارش‌گیری، مغایرت‌گیری و تحلیل بودجه، تنها `expenses:read` را بدهید. `expenses:write` را زمانی اضافه کنید که Claude باید داده‌ای مشخص را درج، به‌روزرسانی یا حذف کند. اعطای این مجوز «برای احتیاط» ضرورتی ندارد.

توکن OAuth را داخل پرامپت نگذارید. مرورگر و سامانهٔ نگه‌داری اعتبارنامه‌های کانکتور Claude، توکن‌های دسترسی و نوسازی را مدیریت می‌کنند.

### ۳. کانکتور را در گفت‌وگو فعال کنید

اضافه‌کردن کانکتور به این معنا نیست که Claude باید در هر چت از آن استفاده کند. در یک گفت‌وگو، منوی **+** را باز کنید، **Connectors** را انتخاب کنید و Expense Budget Tracker را برای همان چت فعال کنید.

این امکان کنترل جداگانه برای هر گفت‌وگو هنگام کار با داده‌های مالی مفید است. وقتی گفت‌وگو به کانکتور نیاز ندارد، آن را خاموش بگذارید و فقط برای یک نشست متمرکز بر بودجه فعالش کنید.

## پشت صحنهٔ OAuth چه اتفاقی می‌افتد

لازم نیست این مراحل را دستی انجام دهید، اما شناختن شکل کلی فرایند، عیب‌یابی را ساده‌تر می‌کند.

کانکتور میزبانی‌شده، فرادادهٔ منبع محافظت‌شده را در `https://mcp.expense-budget-tracker.com/.well-known/oauth-protected-resource/mcp` منتشر می‌کند. این سند، Claude را به فرادادهٔ سرور صدور مجوز در `https://auth.expense-budget-tracker.com/.well-known/oauth-authorization-server` هدایت می‌کند.

Claude به‌عنوان یک کلاینت عمومی OAuth ثبت می‌شود، جریان Authorization Code را در مرورگر باز می‌کند و از PKCE با روش چالش `S256` استفاده می‌کند. پس از تأیید، کد مجوز را با توکن‌ها مبادله می‌کند و در صورت نیاز توکن دسترسی را نوسازی می‌کند. این فرایند با [مدل مجوزدهی MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization) هماهنگ است و کشف منبع محافظت‌شده و محافظت از کدهای مجوز با PKCE را در بر می‌گیرد.

یک نکته ممکن است کاربران Claude Desktop را غافلگیر کند: ترافیک کانکتور راه دور از رابط شبکهٔ محلی برنامهٔ دسکتاپ شما نمی‌آید. [به گفتهٔ Anthropic، اتصال‌های سفارشی راه دور MCP از زیرساخت ابری این شرکت برقرار می‌شوند](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)، حتی زمانی که از Claude Desktop استفاده می‌کنید. این کانکتور میزبانی‌شده از قبل در دسترس عمومی است. اما اگر یک سرور خصوصی MCP را خودتان میزبانی کنید، آن سرور باید اتصال‌های ورودی از زیرساخت Anthropic را بپذیرد تا Claude بتواند به آن دسترسی پیدا کند.

## چهار ابزاری که Claude در اختیار می‌گیرد

این کانکتور به‌جای آنکه دسترسی نامحدود به پایگاه داده بدهد، مجموعه‌ای کوچک از ابزارها را در اختیار Claude می‌گذارد.

| ابزار | چه کاری انجام می‌دهد | مجوز |
|---|---|---|
| `list_workspaces` | فضاهای کاری‌ای را فهرست می‌کند که کاربر واردشده به آن‌ها دسترسی دارد | `expenses:read` |
| `get_schema` | رابطه‌ها و ستون‌های قابل‌دسترسی در فضای کاری انتخاب‌شده را برمی‌گرداند | `expenses:read` |
| `sql_query` | یک کوئری SQL محدود و فقط‌خواندنی را اجرا می‌کند | `expenses:read` |
| `sql_execute` | SQL محدودی را اجرا می‌کند که داده‌ها را تغییر می‌دهد | `expenses:read` و `expenses:write` |

`sql_query` پشت یک مرز فقط‌خواندنی در پایگاه داده اجرا می‌شود. هر نتیجه حداکثر ۱۰۰ ردیف دارد و مهلت اجرا ۲۰ ثانیه است. البته وقتی `sql_execute` در دسترس باشد، کانکتور در مجموع فقط‌خواندنی نیست؛ به همین دلیل باید مجوز اختیاری نوشتن را جداگانه و با دقت بررسی کنید.

پیش از نوشتن SQL باید اسکیمای زنده را دید. نام جدول‌ها، ستون‌ها و رابطه‌های مجاز را از `get_schema` بگیرید، نه از یک پرامپت قدیمی، نمونه‌ای کپی‌شده یا چیزی که Claude از یک برنامهٔ مالی دیگر به خاطر دارد.

## نشست اول را با یک ترتیب امن پیش ببرید

در پرامپت اول از Claude بخواهید پیش از هر تحلیلی، زمینهٔ کار را مشخص کند:

```text
از کانکتور Expense Budget Tracker در حالت فقط‌خواندنی استفاده کن.

ابتدا list_workspaces را فراخوانی کن و نام‌ها و شناسه‌های فضاهای کاری در دسترس را
به من نشان بده. از من بخواه فضای کاری موردنظر را تأیید کنم، حتی اگر فقط یک مورد وجود
دارد. سپس get_schema را برای فضای کاری تأییدشده فراخوانی کن. فقط از sql_query استفاده
کن. هنوز sql_execute را فراخوانی نکن و هیچ تغییری پیشنهاد نده.

پس از دریافت اسکیما، هزینه‌های من را در ماه تقویمی جاری بر اساس دسته‌بندی خلاصه کن و
آن را با ماه تقویمی گذشته مقایسه کن. به‌جای بازگرداندن همهٔ ردیف‌های دفتر کل، از کوئری‌های
تجمیعی استفاده کن. کوئری را نشان بده و هر محدودیتی را که بر نتیجه اثر می‌گذارد توضیح بده.
```

ترتیب مهم است: ابتدا فضای کاری را انتخاب کنید، بعد اسکیمای فعلی آن را ببینید و تازه سپس کوئری را بنویسید. اگر یک کوئری بیش از ۱۰۰ رکورد برمی‌گرداند، از Claude بخواهید داده‌ها را در SQL تجمیع کند یا پرسش را به بازه‌های زمانی مناسب تقسیم کند. قرار نیست کل دفتر کل را از چت عبور دهید. محاسبه باید در خود پایگاه داده انجام شود و فقط نتیجهٔ مفید برگردد.

## چند پرامپت مفید برای اولین نشست فقط‌خواندنی

وقتی Claude فضای کاری را تأیید و اسکیما را بررسی کرد، می‌تواند فراتر از فهرست‌کردن خریدهای اخیر عمل کند.

### یک مرور ماهانهٔ بودجه انجام دهید

```text
فقط با استفاده از sql_query، درآمد و خرج واقعی را با بودجهٔ این ماه مقایسه کن.
اختلاف‌ها را بر اساس دسته‌بندی گروه‌بندی کن، بزرگ‌ترین اختلاف‌های قدرمطلق را اول قرار بده
و نبود دادهٔ بودجه را از هزینهٔ واقعیِ بیشتر از بودجه جدا کن. هیچ ردیف بودجه‌ای را تغییر نده.
SQL استفاده‌شده را نشان بده.
```

این همان نسخهٔ گفت‌وگومحورِ [مرور ماهانهٔ بودجه](/blog/how-to-do-a-monthly-budget-review/) است: اول اختلاف را پیدا کنید و بعد تصمیم بگیرید چه چیزی باید تغییر کند.

### به‌دنبال هزینه‌های احتمالاً تکراری بگردید

```text
از اسکیمای زنده و sql_query استفاده کن تا ثبت‌های هزینهٔ احتمالاً تکراری در ۴۵ روز
گذشته را پیدا کنی. هر جا این فیلدها وجود دارند، تاریخ‌ها، مبلغ‌ها، ارزها، حساب‌ها و
طرف‌های تراکنش را مقایسه کن. نتیجه را موارد احتمالی در نظر بگیر، نه موارد تکراری
تأییدشده. چیزی را حذف یا به‌روزرسانی نکن.
```

عبارت «موارد احتمالی، نه موارد تکراری تأییدشده» مهم است. دو خرید قهوه با مبلغ یکسان لزوماً به این معنا نیست که یک تراکنش تصادفی دوبار وارد شده است.

### یک بررسی مغایرت‌گیری آماده کنید

```text
از list_workspaces استفاده کن، فضای کاری شخصی من را تأیید کن، اسکیما را بررسی کن و
برای مانده‌های در دسترس از طریق کانکتور کوئری اجرا کن. توضیح بده ماندهٔ فعلی چگونه
از ثبت‌های دفتر کل به دست آمده است. اصلاحی انجام نده. خودم نتیجه را با صورت‌حساب بانکی‌ام
مقایسه می‌کنم.
```

اگر یک مانده با صورت‌حساب اصلی تطابق ندارد، همان‌جا توقف کنید و اختلاف را بررسی کنید. [گردش‌کار مغایرت‌گیری بودجه](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) توضیح می‌دهد که پیش از تغییر دفتر کل، چطور تراکنش‌های جاافتاده، موارد تکراری، اشکال‌های ماندهٔ آغازین و انتقال‌ها را از هم تفکیک کنید.

## هر تغییر را یک کار جداگانه در نظر بگیرید

دسترسی نوشتن زمانی مفید است که هدف و نتیجهٔ مورد انتظار روشن باشند: دسته‌بندی یک تراکنش باید اصلاح شود، هزینه‌ای تأییدشده باید ثبت شود یا یک ردیف بودجه به‌روزرسانی مشخصی لازم دارد. تغییر را کوچک و قابل‌بررسی نگه دارید؛ نه اینکه فرمان مبهمی مثل «همه‌چیز را مرتب کن» بدهید.

این پرامپت برای اصلاح دسته‌بندی یک تراکنش، محتاطانه و قابل‌بررسی است:

```text
باید دسته‌بندی یکی از ثبت‌های دفتر کل را اصلاح کنم.

1. list_workspaces را فراخوانی کن و فضای کاری مقصد را با من تأیید کن.
2. به‌جای حدس‌زدن نام ستون‌ها، get_schema را فراخوانی کن.
3. با sql_query و بر اساس تاریخ، مبلغ، ارز، حساب و جزئیات طرف تراکنشی که به تو
   می‌دهم، ورودی دقیق را پیدا کن.
4. اگر دقیقاً یک تطابق بدون ابهام وجود ندارد، توقف کن و از من بپرس چه کار کنم.
5. عبارت دقیق SQL پیشنهادی برای sql_execute، شناسهٔ فضای کاری، رکورد منطبق و اثر
   مورد انتظار را نشان بده. هنوز آن را اجرا نکن.
6. منتظر تأیید صریح من بمان.
7. پس از تأیید، sql_execute را یک بار فراخوانی کن. سپس یک sql_query تازه اجرا کن تا
   مقدار ذخیره‌شده را بررسی کنی و آن را به من گزارش بدهی.
```

این شیوه سه تصمیم را شفاف نگه می‌دارد: کدام فضای کاری، کدام رکورد و دقیقاً چه تغییری. راستی‌آزمایی یعنی پس از تغییر، یک خواندن تازه انجام شود؛ نه اینکه Claude صرفاً بگوید عملیات نوشتن احتمالاً موفق بوده است.

همین ساختار برای واردکردن داده نیز کاربرد دارد. از Claude بخواهید دسته‌بندی‌های موجود و موارد احتمالاً تکراری را بررسی کند، پیش‌نمایش ردیف‌هایی را که قرار است درج شوند نشان دهد و منتظر تأیید صریح شما بماند. پس از انجام تغییرات تأییدشده نیز از او بخواهید رکوردهای تازه را بررسی و ماندهٔ حاصل را مغایرت‌گیری کند. اگر کار شما با یک خروجی بانکی شروع می‌شود، [چطور صورت‌حساب بانکی را در یک رهگیر هزینه وارد کنیم](/blog/how-to-import-bank-statements-into-an-expense-tracker/) مراحل بررسی فایل منبع را توضیح می‌دهد.

## دسترسی کانکتور به داده‌های مالی را محدود نگه دارید

MCP نیاز به کپی‌کردن کلید در چت را برطرف می‌کند، اما شما همچنان باید دربارهٔ هر اقدام قضاوت کنید. [راهنمای امنیت کانکتور Anthropic](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) توصیه می‌کند فقط به سرورهای مورداعتماد وصل شوید، مجوزهای درخواستی را بررسی کنید و ورودی و خروجی ابزارها را زیر نظر داشته باشید.

برای این کانکتور، می‌توان این توصیه را به چند قاعدهٔ عملی کوتاه تبدیل کرد:

1. بررسی کنید نشانی دقیقاً `https://mcp.expense-budget-tracker.com/mcp` باشد.
2. با `expenses:read` شروع کنید، مگر اینکه کار مشخصی به تغییر داده نیاز داشته باشد.
3. پیش از هر نشست نوشتن، فضای کاری را تأیید کنید.
4. پیش از تولید SQL، اسکیمای زنده را بررسی کنید.
5. پیش از `sql_execute`، عبارت دقیق و اثر مورد انتظار را بررسی کنید.
6. بلافاصله بعد از آن، نتیجه را با `sql_query` بررسی کنید.
7. وقتی دیگر به دسترسی نوشتن نیاز ندارید، `sql_execute` را در بخش کنترل ابزارهای Claude غیرفعال کنید یا کانکتور را برای همان گفت‌وگو خاموش کنید.

برای `sql_execute` گزینهٔ **Always allow** را انتخاب نکنید. وقتی ابزاری می‌تواند رکوردهای مالی را تغییر دهد، دیدن و بررسی‌کردن تک‌تک درخواست‌های نوشتن یک مکث مفید است.

یادداشت‌های مالی و شرح‌های واردشده باید صرفاً داده تلقی شوند، نه دستور. اگر متن ذخیره‌شده در یک تراکنش از Claude می‌خواهد قواعد شما را نادیده بگیرد یا ابزار دیگری را فراخوانی کند، نباید از آن پیروی کند. این یکی از دلایلی است که بهتر است هنگام تحقیق یا تحلیل گسترده، دسترسی نوشتن خاموش بماند.

پیش از اتصال، [سیاست حفظ حریم خصوصی Expense Budget Tracker](/privacy/) و شرایط Anthropic دربارهٔ پردازش داده را بخوانید. یک نشست مجاز Claude می‌تواند داده‌های مالی در دسترس حساب شما را بخواند و در صورت داشتن `expenses:write` آن‌ها را تغییر دهد. این اتصال راه دور از ابر Anthropic و سرویس میزبانی‌شدهٔ Expense Budget Tracker می‌گذرد؛ استفاده از Claude Desktop آن را به مسیری صرفاً محلی برای داده‌ها تبدیل نمی‌کند.

## عیب‌یابی اتصال بدون حدس‌زدن

### کانکتور سفارشی متصل نمی‌شود

ابتدا نقطهٔ اتصال را بررسی کنید. نشانی باید دقیقاً این باشد:

```text
https://mcp.expense-budget-tracker.com/mcp
```

نشانی وب‌سایت یا API مستقیم را جایگزین آن نکنید. برای این کانکتور، فیلدهای Advanced OAuth Client ID و Client Secret را خالی بگذارید و مطمئن شوید حساب Expense Budget Tracker شما فعال است. اگر احراز هویت همچنان شکست می‌خورد، سرویس را از بخش **Customize > Connectors** قطع کنید و دوباره متصل شوید.

در حساب‌های Team یا Enterprise، از یک Owner یا Primary Owner بپرسید آیا کانکتور سفارشی برای سازمان اضافه و مجاز شده است. اعضای عادی نمی‌توانند این تنظیم سراسری سازمان را انجام دهند.

### Claude می‌گوید کانکتور وجود دارد، اما از آن استفاده نمی‌کند

Expense Budget Tracker را از منوی **+ > Connectors** برای چت فعلی فعال کنید. سپس نام کانکتور را در پرامپت بیاورید و از Claude بخواهید با `list_workspaces` شروع کند. یک کانکتور پیکربندی‌شده می‌تواند در یک گفت‌وگوی مشخص غیرفعال بماند.

### `sql_execute` در دسترس نیست یا مجوز رد می‌شود

احتمالاً مجوز OAuth شامل `expenses:read` است، اما دامنهٔ اختیاری `expenses:write` را ندارد. اگر کار فقط تحلیلی است، همین وضعیت را حفظ کنید. اگر کاری مشخص و تأییدشده به تغییر داده نیاز دارد، دوباره متصل شوید و پیش از دادن مجوز نوشتن، آن را با دقت بررسی کنید.

### یک کوئری ناموفق است یا دادهٔ زیادی برمی‌گرداند

دوباره `get_schema` را فراخوانی کنید و SQL را بر اساس رابطه‌ها و ستون‌هایی که برمی‌گرداند بسازید. درخواست باید در محدودهٔ SQL مجاز کانکتور بماند. در دفترهای کل بزرگ، به‌جای درخواست بیش از سقف ۱۰۰ ردیف، مجموع‌ها، تعدادها و نتایج گروه‌بندی‌شده را در SQL محاسبه کنید. اگر اجرای کوئری بیش از ۲۰ ثانیه طول می‌کشد، پرسش را محدودتر کنید.

### Claude داده‌های مالی اشتباه را می‌بیند

پیش از هر تغییری توقف کنید. `list_workspaces` را فراخوانی کنید، نام‌ها و شناسه‌های برگشتی را مقایسه و فضای کاری مقصد را صریحاً تأیید کنید. سپس `get_schema` را برای همان فضای کاری فراخوانی کنید و خواندن را از نو انجام دهید. دسترسی Claude به فضاهای کاریِ حساب واردشده محدود است، اما باز هم باید دقیقاً همان فضایی را انتخاب کند که شما در نظر دارید.

### Claude یک `ApiKey` می‌خواهد

Claude به‌جای کانکتور راه دور MCP، مسیر یکپارچه‌سازی مستقیم HTTP را دنبال می‌کند. برای این راه‌اندازی، به نشانی کانکتور و فرایند OAuth در مرورگر برگردید. اگر عمداً به اتوماسیون ترمینالی یا درخواست مستقیم HTTP نیاز دارید، از [مرجع Agent API](/docs/api/) استفاده کنید.

## راه‌اندازی کوتاه است؛ چرخهٔ بررسی مهم‌تر است

برای اتصال Claude به Expense Budget Tracker فقط به یک URL و ورود در مرورگر نیاز دارید. چیزی که در بلندمدت اهمیت دارد، روال پس از اتصال است: فضاهای کاری را فهرست کنید، اسکیما را ببینید، ابتدا داده‌ها را بخوانید، کمترین سطح دسترسی لازم را بدهید و هر تغییر را آن‌قدر دقیق تعریف کنید که بتوانید آن را خط‌به‌خط بررسی کنید.

از [مستندات کامل کانکتور MCP](/docs/mcp-connector/) شروع کنید، `https://mcp.expense-budget-tracker.com/mcp` را در بخش **Customize > Connectors** اضافه کنید و یک مرور ماهانهٔ فقط‌خواندنی انجام دهید. وقتی به تغییری نیاز داشتید، از Claude بخواهید پیش از تأیید شما، فضای کاری، رکورد، SQL و اثر مورد انتظار را نشان دهد. همین چرخهٔ بررسی است که یک اپ پیگیری هزینه برای Claude را از یک دموی ساده به گردش‌کاری مالی تبدیل می‌کند که واقعاً می‌توان به آن اعتماد کرد.
