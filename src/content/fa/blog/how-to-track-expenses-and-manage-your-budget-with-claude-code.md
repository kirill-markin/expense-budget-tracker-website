یک ردیاب هزینه کاربردی با Claude Code باید کار را با خواندن آغاز کند، نه نوشتن. پیش از آنکه حتی یک تراکنش بانکی وارد دفتر کل شود، Claude Code می‌تواند فضای کاری را شناسایی کند، شِمای زنده را بررسی کند، حساب مقصد و بازهٔ زمانی را بسنجد و تغییراتی را که قصد دارد انجام دهد به شما نشان دهد.

همین فرصت بازبینی دلیل استفاده از یک عامل هوشمند در ترمینال برای این کار است. Claude Code می‌تواند کارهای مربوط به فایل و HTTP را انجام دهد، درحالی‌که قضاوت مالی در اختیار شما می‌ماند: کدام حساب درست است، آیا یک ردیف انتقال وجه است، کدام دسته مناسب است و آیا اصلاً تغییر پیشنهادی باید ثبت شود یا نه.

در نتیجه، به‌جای یک چت‌بات مالی عمومی، یک ردیاب هزینه مبتنی بر هوش مصنوعی دارید که مرز تأیید در آن روشن است.

Expense Budget Tracker این گردش کار را از طریق Agent API مستقیم خود پشتیبانی می‌کند. نقطه شروع، یک نشانی عمومی برای کشف API است:

```text
https://api.expense-budget-tracker.com/v1/
```

Claude Code می‌تواند از این نقطه راه‌اندازی اولیه با رمز یک‌بارمصرف ایمیلی را کامل کند، `ApiKey` بلندمدت دریافتی را بیرون از حافظهٔ چت نگه دارد، شِمای مجاز را بررسی کند و برای خواندن و نوشتن تأییدشده از نقطه‌های پایانی جداگانه استفاده کند.

## این راه‌اندازی چه می‌کند و داده‌ها کجا می‌روند

Claude Code در ترمینال شما اجرا می‌شود و می‌تواند با فایل صورت‌حسابی که روی رایانه در اختیارش می‌گذارید کار کند. اما این به آن معنا نیست که کل گردش کار آفلاین یا فقط محلی است.

[نیازمندی‌های فعلی Claude Code در مستندات Anthropic](https://docs.anthropic.com/en/docs/claude-code/getting-started) اتصال به اینترنت را الزامی می‌دانند. احراز هویت و پردازش هوش مصنوعی از Anthropic یا ارائه‌دهندهٔ مدلی استفاده می‌کنند که در نصب Claude Code شما تنظیم شده است. بنابراین ممکن است محتوای مرتبط با صورت‌حساب، پرامپت‌ها و نتایج API طبق شرایط آن ارائه‌دهنده بیرون از رایانهٔ شما پردازش شوند.

بخش‌های دیگر این مسیر از هم جدا هستند:

| مرز | آنجا چه اتفاقی می‌افتد |
|---|---|
| رایانهٔ شما | صورت‌حساب مبدأ ابتدا یک فایل محلی است. Claude Code فقط به فایل‌هایی دسترسی پیدا می‌کند که شما اجازه داده‌اید. |
| Claude Code و ارائه‌دهندهٔ مدل آن | Claude Code فایل را تفسیر می‌کند، کوئری‌ها را آماده می‌کند و نتایج را توضیح می‌دهد. برای احراز هویت و پردازش هوش مصنوعی اتصال اینترنت لازم است. |
| Agent API مستقیم | Claude Code درخواست‌های خواندن احراز هویت‌شده و نوشتن‌های تأییدشده‌ای را که برای کار لازم‌اند ارسال می‌کند. API نمی‌تواند فایل‌های دلخواه روی رایانهٔ شما را مرور کند. |
| فضای ذخیره‌سازی Expense Budget Tracker | سوابق مالی تأییدشده در پایگاه دادهٔ میزبانی‌شده ذخیره می‌شوند؛ یا اگر برنامه را خودتان میزبانی کنید، در زیرساخت تحت کنترل شما ذخیره می‌شوند. |

این روش با اتصال‌دهندهٔ MCP از راه دور برای Claude و Claude Desktop نیز متفاوت است. Agent API مستقیم از یک `ApiKey` بلندمدت استفاده می‌کند و این راهنما همین مسیر را پوشش می‌دهد. MCP در نشانی دیگری از OAuth مرورگر استفاده می‌کند؛ صرف اتصال آن به Claude، دسترسی به فایل‌های محلی را فراهم نمی‌کند.

اگر مهم‌ترین نیازتان نداشتن اتصال دائمی به بانک است، [اپلیکیشن بودجه‌بندی بدون اتصال به بانک](/blog/budget-app-without-bank-linking/) این مرزهای داده را با جزئیات بیشتری توضیح می‌دهد.

## اتصال Claude Code از طریق نشانی کشف API

Claude Code را با [راهنمای رسمی راه‌اندازی Anthropic](https://docs.anthropic.com/en/docs/claude-code/getting-started) نصب کنید و وارد حساب شوید. [مرجع CLI](https://docs.anthropic.com/en/docs/claude-code/cli-usage) شیوهٔ اجرای تعاملی و غیرتعاملی فرمان‌ها را توضیح می‌دهد.

وقتی `claude` در ترمینال شما کار کرد، آن را در پوشه‌ای باز کنید که فایل‌های مالی‌تان را نگه می‌دارید و این پرامپت را به آن بدهید:

```text
با استفاده از https://api.expense-budget-tracker.com/v1/ به Expense Budget Tracker
متصل شو. به‌جای حدس زدن جزئیات نقطه‌های پایانی، پاسخ کشف API را دنبال کن. ایمیل
حسابم و سپس کد ۸ رقمی صندوق ورودی‌ام را از من بخواه. فقط پس از تأیید محل ذخیره‌سازی
از سوی من، ApiKey دریافتی را بیرون از حافظهٔ چت ذخیره کن.

پس از ورود، /me را فراخوانی کن، فضاهای کاری‌ام را فهرست کن، از من بخواه فضای کاری
مقصد را تأیید کنم، آن را برای این کلید ذخیره کن و /schema را بررسی کن. هنوز هیچ داده
مالی ننویس.
```

مراحل فعلی راه‌اندازی اولیه چنین است:

1. `GET https://api.expense-budget-tracker.com/v1/` را اجرا کنید و اقدام‌های موجود در پاسخ کشف API را دنبال کنید.
2. وقتی Claude Code درخواست کرد، ایمیل حساب را وارد کنید.
3. کد ۸ رقمی ایمیل را وارد کنید. پس از راستی‌آزمایی موفق، یک `ApiKey` بلندمدت دریافت می‌کنید.
4. کلید را بیرون از حافظهٔ چت ذخیره کنید؛ ترجیحاً با نام `EXPENSE_BUDGET_TRACKER_API_KEY` در محلی که خودتان تأیید کرده‌اید. آن را در هیچ مخزنی کامیت نکنید.
5. با هدر `Authorization: ApiKey <key>`، نقطه‌های پایانی `/v1/me` و `/v1/workspaces` را فراخوانی کنید.
6. فضای کاری مدنظر را با `POST /v1/workspaces/{workspaceId}/select` انتخاب کنید.
7. پیش از تولید SQL، مسیر `/v1/schema` را فراخوانی کنید.

فضای کاری انتخاب‌شده برای همان کلید ذخیره می‌شود. در درخواست‌های SQL بعدی می‌توان هدر `X-Workspace-Id` را حذف کرد؛ بااین‌حال، اگر بخواهید فقط در یک درخواست از فضای کاری دیگری به‌جای فضای کاری ذخیره‌شده استفاده کنید، Claude Code همچنان می‌تواند این هدر را بفرستد. اگر حساب دقیقاً یک فضای کاری داشته باشد و هنوز فضای کاری‌ای برای کلید انتخاب نشده باشد، API می‌تواند آن را به‌طور خودکار ذخیره و استفاده کند. بااین‌حال، بهتر است پیش از هر نوشتن، در مرحلهٔ بازبینی نام فضای کاری را صریحاً ذکر کنید.

جزئیات جریان احراز هویت و راهنمای ذخیره‌سازی در [راه‌اندازی عامل هوش مصنوعی](/docs/agent-setup/) آمده است.

## پیش از نخستین ورود داده، یک قانون بازبینی به Claude Code بدهید

یک فایل محلی `CLAUDE.md` می‌تواند قواعد اجرایی این پوشهٔ مالی را بدون ذخیره‌کردن خود کلید حفظ کند. دستورالعمل‌ها را کوتاه و مشخص نگه دارید:

```markdown
# گردش کار Expense Budget Tracker

- از https://api.expense-budget-tracker.com/v1/ شروع کن و /schema را بررسی کن.
- برای هر عملیات خواندن از POST /v1/sql/query استفاده کن.
- پیش از نوشتن، فضای کاری مقصد، SQL دقیق، تعداد ردیف‌های مورد انتظار برای تغییر،
  جمع مبالغ مبدأ و موارد تکراری احتمالی را نشان بده. منتظر تأیید صریح من بمان.
- فقط برای INSERT، UPDATE یا DELETE دقیقاً تأییدشده از POST /v1/sql/execute استفاده کن.
- هر عملیات نوشتن را با یک درخواست تازه به /v1/sql/query راستی‌آزمایی کن.
- هرگز یک تراکنش ترازکننده نساز و دسته‌بندی نامطمئن را بی‌سروصدا تغییر نده.
- ApiKey را بیرون از این فایل و بیرون از حافظهٔ چت نگه دار.
```

اگر نام واقعی حساب‌ها، شیوهٔ دسته‌بندی، قواعد انتقال وجه و ارز گزارش‌دهی شما ثابت‌اند، آن‌ها را اضافه کنید. فقط به این دلیل که مقاله‌ای از چند دستهٔ نمونه استفاده کرده، آن‌ها را در ردیاب کپی نکنید. Claude Code باید داده‌های موجود شما را کوئری کند و از شِمای زنده استفاده کند.

## وارد کردن یک صورت‌حساب بانکی با Claude Code

بهتر است نخستین بار عمداً مقدار کمی داده وارد کنید: یک حساب، یک ارز، یک دورهٔ بسته‌شدهٔ صورت‌حساب و فایلی که بتوانید ردیف‌هایش را بازبینی کنید. CSV نقطهٔ شروع خوبی است، چون ساختارش به‌روشنی دیده می‌شود. برای قالب‌های دیگر، پیش از اعتماد به ردیف‌های استخراج‌شده باید نتیجهٔ استخراج را متناسب با همان فایل بررسی کنید.

### ۱. محدودهٔ دادهٔ مبدأ را مشخص کنید

پیش از آنکه Claude Code چیزی را تجزیه کند، این موارد را مشخص کنید:

- حساب بانکی و حساب متناظر آن در ردیاب
- ارز حساب
- نخستین و آخرین تاریخ تراکنش‌های ثبت‌شده در صورت‌حساب
- ماندهٔ آغازین یا آخرین ماندهٔ صحیح و تأییدشده
- ماندهٔ پایانی صورت‌حساب
- اینکه تراکنش‌های در انتظار در فایل وجود دارند یا نه

برای وارد کردن و مغایرت‌گیری، فقط از تراکنش‌های ثبت‌شده استفاده کنید. تراکنش‌های در انتظار را تا زمان ثبت نهایی، بیرون از مجموعهٔ تأییدشده نگه دارید.

### ۲. پیش از ساخت ردیف‌ها، مقصد را بررسی کنید

از Claude Code بخواهید ابتدا از نقطهٔ پایانی خواندن استفاده کند:

```text
می‌خواهم فایل ~/finances/checking-2026-07.csv را وارد کنم.

فقط از /v1/sql/query استفاده کن. فضای کاری انتخاب‌شده را تأیید کن، /v1/schema را
بررسی کن، حساب‌های موجود را فهرست کن و تنها حسابی را که با این صورت‌حساب مطابقت دارد
شناسایی کن. بازهٔ زمانی صورت‌حساب را در ledger_entries کوئری کن و به‌دنبال هم‌پوشانی
بگرد. حساب، ارز، محدودهٔ تاریخ، تعداد ردیف‌های موجود و هر مورد تکراری احتمالی را نشان
بده. چیزی ننویس.
```

نقطهٔ پایانی اصلی خواندن این است:

```text
POST https://api.expense-budget-tracker.com/v1/sql/query
```

این نقطهٔ پایانی یک `SELECT` یا `WITH ... SELECT` فقط‌خواندنی می‌پذیرد. بدنهٔ درخواست باید حاوی SQL منطبق با شِمای فعلی `/schema` باشد:

```json
{
  "sql": "SELECT * FROM accounts LIMIT 100"
}
```

Claude Code باید به‌جای آوردن کل دفتر کل به مکالمه، جمع‌ها و نتایج گروه‌بندی‌شده را در SQL محاسبه کند. نتیجهٔ هر کوئری به ۱۰۰ ردیف محدود است.

### ۳. پیش‌نمایش را بررسی کنید، نه وعده را

پیش از آنکه Claude Code یک `INSERT` بسازد، از آن بخواهید صورت‌حساب را به یک جدول پیش‌نمایش تبدیل کند. این پیش‌نمایش دست‌کم باید شامل ردیف مبدأ، تاریخ، مبلغ، ارز، حساب مقصد، نوع پیشنهادی تراکنش، دسته پیشنهادی و وضعیت تکراری بودن باشد.

این ردیف‌ها را با دقت بررسی کنید:

- انتقال‌ها میان حساب‌های خودتان
- برگشت وجه و بازپرداخت هزینه‌ها
- برداشت‌های نقدی و کارمزدهای بانکی
- طرف‌های تراکنش ناآشنا
- تراکنش‌های ارز خارجی
- ردیف‌های نزدیک به ابتدا و انتهای دورهٔ صورت‌حساب
- هر موردی که شبیه یک رکورد موجود در دفتر کل است

یکسان‌بودن تاریخ و مبلغ می‌تواند نشانهٔ تکراری‌بودن باشد، اما آن را ثابت نمی‌کند؛ ممکن است دو تراکنش معتبر تاریخ و مبلغ یکسانی داشته باشند. اگر دادهٔ مبدأ یک شناسهٔ بانکی پایدار دارد و شِمای زنده فیلد مناسبی برای آن در نظر گرفته است، از آن به‌عنوان قرینه استفاده کنید. در غیر این صورت، شناسه را در پیش‌نمایش نگه دارید و آن را به پایگاه داده تحمیل نکنید.

سپس یک خلاصه فشرده برای تأیید بخواهید:

```text
بدون نوشتن داده، پیش‌نمایش وارد کردن را آماده کن. این موارد را نشان بده:

1. فضای کاری و حساب تأییدشده
2. بازهٔ تاریخ و ارز دادهٔ مبدأ
3. تعداد و جمع جبری ردیف‌های مبدأ
4. همه ردیف‌های پیشنهادی دفتر کل
5. موارد تکراری احتمالی و دسته‌بندی‌های نامطمئن
6. دستور یا دستورهای INSERT دقیقی که ارسال می‌کنی
7. تعداد ردیف‌های مورد انتظار برای تغییر

متوقف شو و منتظر تأیید من بمان.
```

### ۴. فقط مجموعهٔ تغییرات تأییدشده را ارسال کنید

نقطهٔ پایانی اصلی نوشتن این است:

```text
POST https://api.expense-budget-tracker.com/v1/sql/execute
```

این نقطهٔ پایانی یک `INSERT`، `UPDATE` یا `DELETE` تأییدشده، از جمله شکل‌های پشتیبانی‌شدهٔ `WITH`، می‌پذیرد. این مسیر عمداً از نقطهٔ پایانی خواندن جداست.

هر دستور تغییر حداکثر می‌تواند بر ۱۰۰ ردیف اثر بگذارد. برای وارد کردن تعداد زیادی ردیف، پیش از اجرا کل مجموعهٔ تغییرات پیشنهادی را تأیید کنید. Claude Code باید ابتدا ۱ تا ۳ ردیف نمونه با همان ساختار SQL را به‌صورت آزمایشی ارسال کند. اگر این مرحله موفق بود، باید بلافاصله باقی ردیف‌های تأییدشده را در دسته‌های پیاپیِ حداکثر ۱۰۰ ردیفی ارسال کند. باید هر دسته را پیگیری و راستی‌آزمایی کند، اما نباید فقط برای اجازهٔ ادامه یا تأیید دوباره متوقف شود. تغییر دامنهٔ کار، ابهام تازه یا اجرای ناموفق، نقطهٔ بازبینی جدیدی ایجاد می‌کند.

قابلیت‌های SQL از `ON CONFLICT` پشتیبانی نمی‌کنند؛ بنابراین رسیدگی به داده‌های تکراری باید صریح باشد، نه اینکه پشت یک عملیات upsert پنهان شود.

`POST /v1/sql` همچنان برای سازگاری و اجرای محدود اسکریپت‌های چنددستوری اتمیک وجود دارد. این مسیر، نقطهٔ پایانی معمول برای خواندن صورت‌حساب یا نوشتن‌های روزمره نیست.

### ۵. ردیف‌ها را دوباره بخوانید

پاسخ موفق API پایان کارِ وارد کردن داده‌ها نیست. از Claude Code بخواهید حساب و دورهٔ زمانی تحت تأثیر را دوباره از طریق `/v1/sql/query` کوئری کند و نتیجهٔ ذخیره‌شده را با پیش‌نمایش تأییدشده مقایسه کند:

- تعداد ردیف‌های تحت تأثیر
- تاریخ‌ها و مبالغ
- ارز مبدأ
- انتساب به حساب
- نوع تراکنش‌ها و دسته‌ها
- تعداد موارد تکراری

از Claude Code نخواهید «هر چیزی را که اشتباه به نظر می‌رسد اصلاح کند». اگر راستی‌آزمایی تفاوتی پیدا کرد، به تشخیص فقط‌خواندنی برگردید، یک اصلاح مشخص آماده کنید و آن اصلاح را جداگانه تأیید کنید.

[راهنمای جامع‌تر وارد کردن صورت‌حساب بانکی](/blog/how-to-import-bank-statements-into-an-expense-tracker/) انتقال‌ها، برگشت وجه، دوره‌های هم‌پوشان و ردیف‌های دیگری را پوشش می‌دهد که می‌توانند فرایند وارد کردن داده را در ظاهر بی‌نقص اما در عمل گمراه‌کننده کنند.

## پیش از وارد کردن حساب بعدی، یک حساب را مغایرت‌گیری کنید

مغایرت‌گیری ثابت می‌کند که گردش‌های دفتر کل با صورت‌حساب بانکی سازگارند. یک حساب بانکی را با حساب متناظر آن در ردیاب، با همان ارز و در همان محدودهٔ تراکنش‌های ثبت‌شده مقایسه کنید.

برای یک حساب سپردهٔ معمولی، بررسی پایه چنین است:

**ماندهٔ پایانی مورد انتظار = ماندهٔ آغازین + ورودی‌های ثبت‌شده − خروجی‌های ثبت‌شده**

اگر ردیاب از گردش‌های علامت‌دار استفاده می‌کند، شکل معادل آن چنین است:

**ماندهٔ پایانی مورد انتظار = ماندهٔ آغازین + مجموع جبری گردش‌های ثبت‌شده**

حساب‌های بدهی مانند کارت اعتباری ممکن است قاعدهٔ علامت‌گذاری متفاوتی داشته باشند. پیش از مقایسهٔ اعداد، از Claude Code بخواهید قاعده‌ای را که یافته توضیح دهد.

از پرامپتی استفاده کنید که فرایند تشخیص را فقط‌خواندنی نگه می‌دارد:

```text
فقط از /v1/sql/query استفاده کن. حساب جاری واردشده را با ماندهٔ پایانی صورت‌حساب
به مبلغ [مبلغ و ارز] تطبیق بده. مبدأ ماندهٔ آغازین و قاعدهٔ علامت‌گذاری را بیان کن.
اگر مانده‌ها متفاوت‌اند، اختلاف دقیق را نشان بده و ردیف‌های احتمالاً جاافتاده، تکراری
یا دارای علامت اشتباه را فهرست کن. تراکنش ترازکننده ثبت نکن و داده‌های موجود را تغییر نده.
```

اگر اختلاف صفر نیست، ماندهٔ آغازین، تراکنش‌های جاافتاده یا تکراری، انتقال‌ها، موارد در انتظار، علامت‌ها، تاریخ‌ها و ارزها را بررسی کنید. یک تراکنش ترازکنندهٔ ساختگی، ماندهٔ نمایش‌داده‌شده را برابر می‌کند اما علت اختلاف را پنهان نگه می‌دارد.

اختلاف صفر ثابت می‌کند که جمع گردش‌های حساب با مانده می‌خواند. اما ثابت نمی‌کند که دسته‌بندی‌ها درست‌اند. پیش از رفتن سراغ حساب بعدی، جمع هر دسته را جداگانه بررسی کنید. [راهنمای تطبیق بودجه با ماندهٔ بانک](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) این تفاوت را دقیق‌تر توضیح می‌دهد.

## مخارج را از طریق نقطهٔ پایانی خواندن تحلیل کنید

پس از راستی‌آزمایی داده‌های واردشده، Claude Code می‌تواند از `ledger_entries` برای تحلیل فقط‌خواندنی مخارج استفاده کند. پرسش را دقیق مطرح کنید و SQL را نیز بخواهید تا بتوانید مبنای محاسبهٔ پاسخ را بررسی کنید.

```text
/v1/schema را بررسی کن، سپس با استفاده از /v1/sql/query مخارج هر دسته را در سه ماه
تقویمی کامل اخیر مقایسه کن. پیش از نوشتن SQL، تاریخ دقیق شروع و پایان را تعیین کن.
انتقال‌ها را بر اساس نوع تراکنش ذخیره‌شده حذف کن. تجمیع را در SQL انجام بده، کوئری
را نشان بده و هر ردیف کنارگذاشته‌شده یا مورد تردید را توضیح بده. داده‌ای را تغییر نده.
```

این موضوع مهم است، زیرا «مخارج» نام یک ستون یکسان در همهٔ شِماها نیست. پاسخ مفید به شِمای فعلی، انواع تراکنش، ارز حساب، برگشت وجه و محدودهٔ دقیق تاریخ بستگی دارد. Claude Code می‌تواند کوئری را بنویسد، اما شما همچنان باید بتوانید ببینید چه مواردی در محاسبه شمرده شده‌اند.

برای بررسی‌های موردی، سؤال‌های مشخصی مانند این‌ها مطرح کنید:

- کدام دسته‌ها میان دو ماه کامل بیشترین تغییر را داشته‌اند؟
- کدام طرف‌های تراکنش جمع مبلغ یک دسته را تشکیل می‌دهند؟
- آیا در آخرین دوره واردشده موارد تکراری احتمالی وجود دارد؟
- کدام دسته‌های مخارج واقعی هیچ ردیف بودجه متناظری ندارند؟

وقتی Claude Code گروه‌بندی و فیلتر را در خود پایگاه داده انجام می‌دهد، سقف ۱۰۰ ردیفی نتایج معمولاً کافی است.

## بودجه را با Claude Code به‌روزرسانی کنید، بدون اینکه تصمیم‌گیری را به آن واگذار کنید

تغییرات بودجه همان چرخهٔ بازبینیِ وارد کردن صورت‌حساب را دنبال می‌کنند. Claude Code می‌تواند `budget_lines` را بخواند، برنامه را با فعالیت واقعی دفتر کل مقایسه کند و یک `INSERT`، `UPDATE` یا `DELETE` پیشنهادی آماده کند. این شما هستید که تصمیم می‌گیرید آیا مبالغ جدید با برنامه‌هایتان سازگارند یا نه.

```text
با استفاده از /v1/sql/query درآمد و مخارج واقعی این ماه را با budget_lines مقایسه کن.
سپس بودجهٔ ماه آینده را بر اساس دسته‌های موجود و شِمای فعلی پیش‌نویس کن.

برای هر ردیف تغییرکرده، مبلغ فعلی، مبلغ پیشنهادی، اختلاف و دلیل را نشان بده.
SQL دقیق و تعداد ردیف‌های مورد انتظار برای تغییر را نشان بده. تا وقتی ردیف‌های مشخصی
را تأیید نکرده‌ام /v1/sql/execute را فراخوانی نکن. پس از اجرای نوشتن تأییدشده، آن ردیف‌ها
را دوباره کوئری و راستی‌آزمایی کن.
```

اجازه ندهید یک ماه پرخرج بی‌سروصدا به برنامهٔ جدید تبدیل شود. ممکن است یک هزینهٔ بزرگ استثنایی باشد، نبودن یک دسته ناشی از مشکل داده‌ای باشد یا یک انتقال اشتباه دسته‌بندی شده باشد. Claude Code می‌تواند تفاوت‌ها را آشکار کند، اما بودجه‌بندی با Claude Code همچنان به قضاوت شما دربارهٔ آنچه باید در ادامه رخ دهد نیاز دارد.

## مرزهای فعلی Agent API را بشناسید

API مجموعهٔ کوچکی از رابطه‌های داده‌ای را در دسترس می‌گذارد. همیشه `/v1/schema` را منبع معتبر وضعیت فعلی بدانید، اما تفکیک کنونی خواندن و نوشتن چنین است:

| رابطه | دسترسی |
|---|---|
| `ledger_entries` | خواندن و نوشتن تأییدشده |
| `budget_lines` | خواندن و نوشتن تأییدشده |
| `workspace_settings` | خواندن و نوشتن تأییدشده |
| `account_metadata` | خواندن و نوشتن تأییدشده |
| `accounts` | فقط خواندن |
| `fx_rates_raw` | فقط خواندن |
| `fx_rates_daily` | فقط خواندن |

محدودیت‌های فعلی Agent API عبارت‌اند از:

- حداکثر ۱۰۰ ردیف خروجی برای هر کوئری
- حداکثر ۱۰۰ ردیف تحت تأثیر برای هر دستور تغییر و هر درخواست
- مهلت کلی ۲۵ ثانیه برای هر درخواست SQL
- ۱۰ درخواست در ثانیه و ۱۰٬۰۰۰ درخواست در روز برای هر کلید

سیاست SQL موارد زیر را مسدود می‌کند: DDL مانند `CREATE`، `DROP` و `ALTER`، عبارت‌های مدیریت تراکنش، کامنت‌های SQL، شناسه‌های نقل‌قول‌شده، رشته‌های `dollar-quoted`، تابع `set_config()` و توابع محدودشده. توابع مجاز فعلی عبارت‌اند از `SUM`، `COUNT`، `MIN`، `MAX`، `AVG` و `COALESCE`. برای جست‌وجوی متنی بدون حساسیت به حروف بزرگ و کوچک، به‌جای `LOWER(...)` از `ILIKE` استفاده کنید و به‌جای `NOW()` یا `DATE_TRUNC()` بازه‌های تاریخی صریح بنویسید. نقطه‌های پایانی اصلی در هر درخواست فقط یک دستور می‌پذیرند. `ON CONFLICT` پشتیبانی نمی‌شود.

این کنترل‌ها دامنهٔ SQL را محدود می‌کنند، اما تعیین نمی‌کنند که آیا یک دسته درست است یا یک ردیف صورت‌حساب واقعاً انتقال وجه است. امنیت سطح ردیف (Row Level Security) فضاهای کاری را در سطح پایگاه داده از هم جدا می‌کند. کلیدهای `ApiKey` به‌صورت هش SHA-256 ذخیره می‌شوند و می‌توان آن‌ها را از داخل محصول باطل کرد. بااین‌حال، باید از مقدار متنی کلید روی رایانه‌تان محافظت و هر تغییر مالی را بازبینی کنید.

برای قرارداد فعلی نقطه‌های پایانی و محدودیت‌ها به [مرجع API](/docs/api/) مراجعه کنید.

## Agent API در Claude Code و MCP در Claude دو مسیر جدا هستند

جست‌وجو برای ردیاب هزینهٔ مخصوص Claude اغلب استفاده در ترمینال را با اتصال‌دهنده‌های Claude یا Claude Desktop در هم می‌آمیزد. Expense Budget Tracker از هر دو پشتیبانی می‌کند، اما نمی‌توان روش راه‌اندازی و اطلاعات احراز هویت آن‌ها را به‌جای یکدیگر به کار برد.

| | Claude Code با Agent API | Claude یا Claude Desktop با MCP |
|---|---|---|
| مناسب‌ترین کاربرد | فایل‌های محلی، گردش کار ترمینالی، اسکریپت‌ها و HTTP مستقیم | مکالمه‌ها در یک کلاینت Claude با قابلیت MCP |
| از اینجا شروع کنید | `https://api.expense-budget-tracker.com/v1/` | `https://mcp.expense-budget-tracker.com/mcp` |
| احراز هویت | رمز یک‌بارمصرف ایمیلی، سپس `ApiKey` بلندمدت | OAuth مبتنی بر مرورگر |
| رابط خواندن/نوشتن | `/v1/sql/query` و `/v1/sql/execute` | ابزارهای `sql_query` و در صورت نیاز `sql_execute` |
| دسترسی به فایل محلی | به فایل‌ها و مجوزهایی بستگی دارد که در اختیار Claude Code هستند | خود اتصال‌دهنده از راه دور چنین دسترسی‌ای نمی‌دهد |

وقتی هدفتان اتصال Claude یا Claude Desktop است، از [مستندات اتصال‌دهندهٔ MCP](/docs/mcp-connector/) یا [راهنمای کامل اتصال ردیاب هزینهٔ Claude با MCP](/blog/claude-expense-tracker-mcp-connector/) استفاده کنید. اگر کار با یک صورت‌حساب محلی و ترمینال آغاز می‌شود، همین گردش کار Agent API را ادامه دهید.

## یک پرامپت قابل استفاده مجدد برای کل گردش کار

این پرامپت کشف API، پیش‌نمایش، تأیید و راستی‌آزمایی را در یک توالی نگه می‌دارد:

```text
از طریق https://api.expense-budget-tracker.com/v1/ به Expense Budget Tracker متصل شو
و پاسخ کشف API را دنبال کن. از ApiKey ذخیره‌شده بیرون از حافظهٔ چت استفاده کن. /me را
فراخوانی کن، فضاهای کاری را فهرست کن، فضای کاری مقصد را با من تأیید و انتخاب کن و
/schema را بررسی کن.

می‌خواهم [مسیر CSV محلی] را برای [حساب] در [بازهٔ تاریخی پایان‌یافته] و با [ارز] وارد کنم.
ابتدا با /v1/sql/query حساب، دسته‌های موجود و ردیف‌های هم‌پوشان دفتر کل را بررسی کن.
فایل را تجزیه و یک پیش‌نمایش کامل آماده کن. موارد تکراری احتمالی، انتقال‌ها، برگشت وجه،
بازپرداخت هزینه‌ها، کارمزدها، طرف‌های تراکنش غیرعادی و دسته‌های نامطمئن را مشخص کن.

جمع مبالغ مبدأ، ردیف‌های پیشنهادی، SQL دقیق و تعداد ردیف‌های مورد انتظار برای تغییر را
نشان بده. تا زمانی که کل مجموعهٔ تغییرات را تأیید نکرده‌ام چیزی ننویس. فقط برای همان
نوشتن تأییدشده از /v1/sql/execute استفاده کن. برای وارد کردن تعداد زیادی ردیف، ابتدا
یک آزمون با ۱ تا ۳ ردیف نمونه بفرست. اگر موفق بود، بلافاصله باقی ردیف‌های تأییدشده را
در دسته‌های پیاپی حداکثر ۱۰۰ ردیفی ادامه بده. هر دسته را از طریق /v1/sql/query
راستی‌آزمایی کن و فقط در صورتی دوباره از من تأیید بخواه که دامنهٔ کار تغییر کند،
ابهام تازه‌ای پدید آید یا اجرا شکست بخورد.

در پایان، همین یک حساب را با ماندهٔ پایانی صورت‌حساب تطبیق بده. اگر تطابق نداشت، بدون
ساخت تراکنش ترازکننده یا تغییر داده، اختلاف را توضیح بده.
```

با یک حساب و یک دورهٔ بسته‌شده شروع کنید. اگر پیش‌نمایش قابل فهم است، ردیف‌های تأییدشده به‌درستی بازخوانی می‌شوند و مغایرتی در ماندهٔ پایانی باقی نمی‌ماند، یک گردش کار مدیریت مالی شخصی با Claude دارید که می‌توان آن را بازبینی کرد—نه چت‌باتی با اجازه‌ای مبهم برای تغییر دفاتر مالی شما.
