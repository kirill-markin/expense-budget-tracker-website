Expense Budget Tracker یک نشانی واحد برای سرور راه‌دور MCP میزبانی‌شده ارائه می‌کند:

```text
https://mcp.expense-budget-tracker.com/mcp
```

همین نشانی را در همهٔ کلاینت‌های سازگار استفاده کنید. سرور میزبانی‌شده از Streamable HTTP و OAuth 2.1 استفاده می‌کند و در این endpoint کلید API نمی‌پذیرد.

## کلاینت‌های پشتیبانی‌شده

این endpoint با ChatGPT و دیگر کلاینت‌های MCP که همهٔ موارد زیر را پشتیبانی کنند کار می‌کند:

- سرور راه‌دور MCP روی Streamable HTTP؛
- جریان Authorization Code در OAuth 2.1 همراه با PKCE؛
- ثبت پویای کلاینت OAuth یا Dynamic Client Registration.

Claude، Codex، OpenClaw و کلاینت‌های دیگر نیز زمانی می‌توانند از همین endpoint استفاده کنند که نسخهٔ فعلی آن‌ها از این انتقال راه‌دور و جریان احراز هویت پشتیبانی کند. کلاینتی که فقط سرور محلی `stdio` را می‌پذیرد نمی‌تواند مستقیماً به endpoint میزبانی‌شده متصل شود.

## اتصال و اعطای مجوز

1. نشانی `https://mcp.expense-budget-tracker.com/mcp` را به‌عنوان یک سرور راه‌دور سفارشی MCP در کلاینت خود اضافه کنید.
2. کلاینت منبع محافظت‌شده و سرور مجوزدهی را کشف می‌کند، سپس نام و نشانی‌های بازگشت خود را از طریق Dynamic Client Registration ثبت می‌کند.
3. مرورگر صفحهٔ ورود و رضایت Expense Budget Tracker را باز می‌کند. وارد شوید، نام کلاینت و مجوزهای درخواستی را بررسی کنید و فقط دسترسی موردنیاز را تأیید کنید.
4. کلاینت کد مجوز را با PKCE مبادله می‌کند و با اعتبارنامه‌های کوتاه‌عمر متصل می‌شود. نیازی نیست توکنی را در کلاینت کپی کنید.
5. پیش از خواندن یا تغییر داده‌های مالی، از کلاینت بخواهید `list_workspaces` را فراخوانی کند.

سرور مجوزدهی می‌تواند scopeهای زیر را اعطا کند:

| Scope | دسترسی |
| --- | --- |
| `expenses:read` | فهرست‌کردن فضاهای کاری، دیدن شِمای مجاز و پرس‌وجوی داده‌های مالی. |
| `expenses:write` | اجرای یک `INSERT`، `UPDATE` یا `DELETE` مجاز از طریق `sql_execute`. دسترسی نوشتن از دسترسی خواندن جداست. |

اتصال فقط خواندنی `expenses:read` را دریافت می‌کند. اتصال دارای امکان نوشتن هر دو scope یعنی `expenses:read` و `expenses:write` را دریافت می‌کند.

## ابزارها

| ابزار | کاربرد | مرز |
| --- | --- | --- |
| `list_workspaces` | همهٔ فضاهای کاری در دسترس کاربر واردشده را فهرست می‌کند. | فقط خواندنی؛ نیازمند `expenses:read`. |
| `get_schema` | رابطه‌ها، ستون‌ها، محدودیت‌ها، سقف‌ها و راهنمای مجاز یک فضای کاری را برمی‌گرداند. | فقط خواندنی؛ نیازمند `expenses:read`. |
| `sql_query` | دقیقاً یک `SELECT` یا `WITH ... SELECT` مورد تأیید سیاست را اجرا می‌کند. | تراکنش فقط خواندنی با نقش محدود؛ نیازمند `expenses:read`. |
| `sql_execute` | دقیقاً یک `INSERT`، `UPDATE` یا `DELETE` مورد تأیید سیاست را اجرا می‌کند. | دادهٔ مالی را تغییر می‌دهد و idempotent نیست؛ نیازمند `expenses:write`. |

ابزارها فقط با داده‌های Expense Budget Tracker کار می‌کنند. آن‌ها نمی‌توانند وب را مرور کنند، به سرویس دیگری دسترسی بگیرند، DDL اجرا کنند یا رابطه‌ها و ستون‌های بازگردانده‌شده توسط `get_schema` را دور بزنند.

## انتخاب فضای کاری

ابتدا `list_workspaces` را فراخوانی کنید. اگر دقیقاً یک فضای کاری برگردد، می‌توانید `workspaceId` را در فراخوانی‌های دیگر ننویسید. اگر بیش از یک فضا وجود دارد، یکی از شناسه‌های بازگردانده‌شده را انتخاب کنید و همان `workspaceId` را در همهٔ فراخوانی‌های `get_schema`، `sql_query` و `sql_execute` به‌صراحت بفرستید. سرور به‌جای حدس‌زدن، فضای کاری مبهم یا خارج از دسترس را رد می‌کند.

پس از انتخاب فضا و پیش از نوشتن SQL، `get_schema` را فراخوانی کنید. قرارداد دقیق رابطه‌ها و SQL در [مرجع API](/fa/docs/api/) نگهداری می‌شود؛ این راهنما فقط اتصال MCP و مدل ایمنی آن را توضیح می‌دهد.

## مرزهای خواندن و نوشتن

برای بررسی و گزارش‌گیری از `sql_query` استفاده کنید. `sql_execute` را فقط زمانی به کار ببرید که تغییر درخواستی روشن باشد و کاربر آن را تأیید کرده باشد. چون عملیات تغییردهنده idempotent نیست، نوشتن نامطمئن را کورکورانه تکرار نکنید: ابتدا وضعیت نهایی را پرس‌وجو کنید و فقط اگر مطمئن شدید تغییر اعمال نشده است، دوباره تلاش کنید.

جداسازی فضاهای کاری در سمت سرور با امنیت سطح ردیف Postgres و نقش‌های محدود پایگاه داده اعمال می‌شود. خود سرویس scopeهای OAuth، عضویت در فضای کاری، سیاست SQL، مهلت اجرای دستور و سقف ردیف‌های پاسخ را کنترل می‌کند.

## حریم خصوصی، لغو دسترسی و راهنمایی

کلاینت هوش مصنوعی یک شخص ثالث مستقل است. ممکن است درخواست‌ها و نتیجهٔ ابزارها را مطابق شرایط و سیاست حریم خصوصی خودش پردازش یا نگهداری کند. پیش از اتصال داده‌های مالی، آن سیاست را بررسی کنید. [سیاست حفظ حریم خصوصی](/fa/privacy/) توضیح می‌دهد سرویس میزبانی‌شده چه چیزهایی را پردازش و ذخیره می‌کند.

دسترسی یک کلاینت MCP متصل را در برنامهٔ میزبانی‌شده از مسیر **تنظیمات > دسترسی عامل‌ها** لغو کنید. با لغو دسترسی، اعتبارنامه‌های دسترسی و تازه‌سازی آن اتصال بی‌اعتبار می‌شوند. برای مشکلات اتصال به [صفحهٔ پشتیبانی](/fa/support/) مراجعه کنید.
