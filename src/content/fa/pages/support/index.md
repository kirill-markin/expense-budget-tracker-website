## پشتیبانی سرویس میزبانی‌شده و MCP

برای راهنمایی دربارهٔ برنامهٔ میزبانی‌شده، حساب کاربری، مجوزدهی OAuth یا سرور عمومی MCP به [markinkirill@gmail.com](mailto:markinkirill@gmail.com) ایمیل بزنید. پشتیبانی در حد توان ارائه می‌شود و زمان پاسخ تضمین‌شده نیست.

فقط اطلاعات تشخیصی لازم برای بررسی را بفرستید:

- نام و نسخهٔ کلاینت؛
- تاریخ، ساعت و منطقهٔ زمانی خطا؛
- endpoint یا صفحهٔ درگیر؛
- مرحلهٔ OAuth یا نام ابزار MCP؛
- متن دقیق و پاک‌سازی‌شدهٔ خطا و شناسهٔ درخواست، اگر نمایش داده شده است؛
- نتیجهٔ مورد انتظار و آنچه واقعاً رخ داده است.

هرگز گذرواژه، کوکی نشست، کد OAuth، توکن دسترسی یا تازه‌سازی، کلید API، رکوردهای خام مالی یا بدنهٔ پاک‌سازی‌نشدهٔ درخواست را ارسال نکنید.

## گزارش‌های امنیتی

آسیب‌پذیری احتمالی را در issue عمومی GitHub منتشر نکنید. با موضوع **Expense Budget Tracker security report** به [markinkirill@gmail.com](mailto:markinkirill@gmail.com) ایمیل بزنید و یک نمونهٔ حداقلی و پاک‌سازی‌شده ارائه کنید. اعتبارنامهٔ فعال یا دادهٔ مالی را وارد نکنید. اگر احتمال می‌دهید دسترسی افشا شده باشد، ابتدا اتصال را از **تنظیمات > دسترسی عامل‌ها** لغو و هر اعتبارنامهٔ درگیر دیگری را تعویض کنید.

## خطاها، میزبانی شخصی و پرسش‌های جامعه

برای خطاهای قابل بازتولید، پرسش‌های میزبانی شخصی و گفت‌وگوهای عمومی جامعه از [issue tracker در GitHub](https://github.com/kirill-markin/expense-budget-tracker/issues) استفاده کنید. ابتدا issueهای موجود را جست‌وجو و اطلاعات خصوصی را از گزارش‌ها و تصویرها حذف کنید. [راهنمای میزبانی شخصی](/fa/docs/self-hosting/) و [مخزن کد منبع](https://github.com/kirill-markin/expense-budget-tracker) موضوعات استقرار و توسعه را پوشش می‌دهند.

## پیش از گزارش مشکل MCP

مطمئن شوید کلاینت شما MCP راه‌دور روی Streamable HTTP، جریان Authorization Code در OAuth 2.1 همراه با PKCE و Dynamic Client Registration را پشتیبانی می‌کند. endpoint واحد را دقیقاً مطابق [راهنمای MCP](/fa/docs/mcp-connector/) وارد کنید و پس از اتصال دوباره فقط یک بار دیگر تلاش کنید. اگر مشکل باقی ماند، اطلاعات پاک‌سازی‌شدهٔ بالا را ارسال کنید.
