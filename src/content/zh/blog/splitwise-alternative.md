两个人平摊一笔 120 美元的杂货费，同一笔消费可以产生两种不同却都正确的记录。Splitwise 记录：付款人应收 60 美元。家庭预算记录：杂货支出 120 美元，付款账户余额减少 120 美元。混淆这两种记录，迁移时一笔消费就可能变成两笔，甚至三笔支出。

这才是选择 **2026 年 Splitwise 替代方案**时真正要判断的事。如果你想更好地计算谁欠谁钱，应该比较同类的费用分摊工具。如果你需要的是预算与实际支出对比、真实账户余额、转账和家庭财务报告，那么你要找的是另一类账本。

[Expense Budget Tracker](/features/) 适合后一种情况。它并不能直接取代 Splitwise，而这一区别比一长串功能清单更重要。

## 先说结论

Splitwise 专门用于管理共享支出：记录谁付了钱，按均分、不等额、百分比或份额分摊费用，维护群组余额，简化债务并完成结算。它也支持周期性支出。如果一次旅行、一顿聚餐或一个家庭最常问的是“谁该还谁多少钱？”，这些正是需要的功能（[Splitwise 概览](https://secure.splitwise.com/)）。

Expense Budget Tracker **不会**计算谁欠谁钱、简化债务、扫描收据、连接银行，也不提供一键式 Splitwise 导入。如果其中任何一项不可或缺，请继续使用 Splitwise，或选择其他多人支出记录工具。

当长期共享财务需要一张完整的全景图时，Expense Budget Tracker 才能发挥作用：共享工作区、多个真实账户、预算与实际支出对比、根据账本记录计算的余额、作为独立账本类型的转账、原币记录，以及按所选币种生成的报告。它是开源项目，支持自行托管，让你完全掌控数据；托管服务则提供 MCP 连接器和 HTTP Agent API。

因此，**适合情侣的 Splitwise 替代方案**可能指两类完全不同的产品。有些情侣需要一款结算规则更好用的共享支出记录工具；另一些情侣已经不再以结算为核心问题，需要的是共享预算应用。

## 同一笔消费，两种不同的账本

假设 Maya 花 120 美元购买杂货，家里按 50/50 分摊。

Splitwise 记录的是债务关系：Maya 付了钱，Leo 欠她 60 美元。Leo 之后转给她 60 美元，余额便归零。

家庭预算记录的是实际发生的财务事件：

- Maya 的真实账户产生一笔 120 美元的杂货支出
- 月度预算中的杂货实际支出增加 120 美元
- 如果两个账户都在追踪范围内，再记录一笔从 Leo 账户转到 Maya 账户的 60 美元转账

这笔转账只改变现金由谁持有。它不是又买了一次杂货，也不是 Maya 的新收入。

这就是 **Splitwise 与预算应用对比**中最关键的区别。费用分摊账本追踪人与人之间的债务，预算账本追踪真实账户的资金活动，并将实际支出与计划对比。把每笔欠款都记成支出，会把两种模型混在一起，夸大家庭的支出总额。

[与伴侣分摊支出指南](/blog/how-to-split-expenses-with-your-partner/)介绍了 50/50 和按收入比例分摊的计算方法。[情侣该用联名账户还是独立账户](/blog/joint-vs-separate-bank-accounts-for-couples/)则说明了背后的账户结构。

## 多币种场景很快就会暴露差异

想象一个旅行团：餐厅账单用 EUR 结算，酒店费用以 USD 计价，还有一位成员用 GBP 付款。Splitwise 默认将各币种的余额分开记录。Pro 用户可以按当前市场汇率，将一个群组或好友关系中的全部支出换算成自己的默认币种。换算范围包括过去和已经结算的支出；之后新增的外币支出则需要再次换算（[Splitwise 多币种指南](https://kb.splitwise.com/balances-and-expenses/how-can-i-manage-a-friendship-or-group-with-multiple-currencies)）。

如果目标是旅行结束后算出一个待结算金额，这样很方便。[共享旅行支出记录指南](/blog/how-to-track-shared-travel-expenses/)仍需体现每笔费用由谁垫付，所以 Splitwise 可能依旧更合适。

如果一个家庭的账户本来就分别使用 EUR、USD 和 GBP，需求会不同：每个账户都必须能以原币核对。Expense Budget Tracker 会在每条账本记录中保留原始金额和币种，并在读取时按每日汇率换算为工作区的报告币种，不会覆盖原币金额。这样一来，你既能拿 USD 账户与其对账单核对，也能查看合并后的 EUR 报告。

两种模型没有绝对的输赢。按当前汇率换算很适合临时群组结算；对于需要在几个月后仍与源账户保持一致的长期账本，保留原币记录更合适。

## 共享工作区不会改变账户所有权

Expense Budget Tracker 允许多位用户在同一个工作区内共用预算、账本、账户和报告。Postgres 行级安全（Row-Level Security）会把这个工作区与其他工作区隔离开来。

能够访问同一个工作区，并不会让原本独立的资金在法律上成为共同财产。它不会判断哪些费用才算公平、伴侣双方应该各出多少，也不会决定底层银行账户归谁所有。这些问题仍取决于相关人员、账户协议和适用法律。

它的好处很实际，范围也更窄：工作区里的每个人都能规划并查看同一套财务记录。这对情侣或家庭很有用，但对临时旅行团来说，通常没必要用到这么完整的体系。

## 如何迁移 Splitwise 导出的 CSV，同时避免重复计算

Expense Budget Tracker 没有一键式 Splitwise 导入。安全迁移的第一步，是把真实消费与这些消费产生的债务和还款分开。

### 1. 导出一个群组或好友关系

在 Splitwise 网站上打开相应的群组或好友关系，进入设置或齿轮菜单，然后选择 **Export as spreadsheet（导出为电子表格）**。Splitwise 的官方支持回复称，这会下载一份包含该群组或好友关系所有支出的 CSV。Pro 用户还可以在高级账户设置中下载完整的 JSON 账户备份（[Splitwise 导出说明](https://feedback.splitwise.com/forums/162446-general/suggestions/3096099-download-export-splitwise-data)）。

先选一个长期使用的家庭群组或旅行群组，原始文件保持不动。范围明确的导出文件更容易检查和核对，也比把几个无关群组混在一起稳妥。

### 2. 先核对，再确定切换日期

请所有人补录遗漏的消费和实际还款。将当前 Splitwise 余额与群组成员认为尚未结清的金额核对，然后定下一个切换日期：从这一天起，新的家庭消费统一记入预算账本。

你可以在切换日前结清群组，也可以把一笔有明确记录的未结余额留在 Splitwise 中。不要把未结余额记成新的预算支出。它汇总的是早期消费产生的债务，并不是另一笔消费。

保存未经修改的导出文件、切换日期，以及对所有未结余额处理方式的约定。

### 3. 将每位付款人对应到实际付款账户

只创建真正属于共享预算范围的真实账户，并保留各自的原币。将每位 Splitwise 付款人对应到实际的资金来源，例如 Maya 的支票账户、Leo 的信用卡或联名旅行卡。

同时把消费描述对应到预算类别，但不要在迁移过程中重新设计整套分类。将杂货直接对应到杂货类别，比迁移到一半再引入新的分类体系更容易审计。

如果某个账户不在账本范围内，请明确记录这条边界。不要为了让每一行都有去处而虚构账户。

### 4. 每笔实际消费只导入一次

对于所选期间内的每笔真实消费，在实际付款账户中创建一条全额支出记录。保留交易日期、源金额、原始币种、描述和有用的来源引用。

不要把付款人的消费和每个人分摊到的份额分别导入成支出，也不要把“你欠别人”或“别人欠你”的余额导入成支出。前面的 120 美元杂货示例应该只生成一笔 120 美元的杂货支出，而不是一笔 120 美元消费、两笔 60 美元份额，再加一笔 60 美元余额。

先挑选五到十条有代表性的记录。如果导出文件中有退款、取消、修改过的支出或外币记录，也要把它们纳入样本。看似合理的总额，最容易在这些地方掩盖正负号错误或重复记录。

### 5. 如果转账双方都在追踪范围内，将实际结算记为转账

如果一笔还款发生在工作区内两个都受追踪的账户之间，请将其记录为从付款人账户转到收款人账户的转账。两个账户的余额都会变化，但家庭收入和支出不变。

如果账本范围内只有一方账户，就无法记录完整的双账户转账。请选择一种有明确说明的统一处理方式，并将受追踪账户与其对账单核对。[伴侣支出指南](/blog/how-to-split-expenses-with-your-partner/)介绍了一种只追踪单个账户的折中办法。

要守住的规则很简单：不要同时把消费和欠款余额作为支出导入。结算只是转移先前支出产生的价值，不会让那笔支出再发生一次。

### 6. 先核对样本，再导入其余记录

对照原始银行或信用卡对账单检查样本：

- 日期、金额和原始币种
- 每笔消费对应的付款账户
- 退款和冲正
- 受追踪账户之间每笔转账的双方记录
- 重复项和分类总额
- 切换时点的账户期末余额

先核对原币账户余额，再相信换算后的家庭总额。货币换算可能让仪表板看似合理，而源账户仍然有错。

如果文件较大，可以把范围明确的 CSV，以及清晰的账户和类别对应关系交给兼容的智能体。[智能体设置](/docs/agent-setup/)介绍如何连接，[API 参考](/docs/api/)则说明工作区选择、schema 检查、受限读取和经批准的写入。这是智能体辅助流程，不是自动导入器。请先检查建议写入的记录，写入后再查询数据。[银行对账单导入检查清单](/blog/how-to-import-bank-statements-into-an-expense-tracker/)提供了更完整的核对流程。

### 7. 完整试跑一个月

导入一个已经结束的完整月份，将其支出和期末余额与对账单核对，再制定下个月的计划。还要确认每周录入或导入一次，对所有使用者来说都切实可行。

在账户余额、支出总额、转账和币种全部一致之前，不要修改 Splitwise 的导出文件和原群组。迁移成功的标准，是一个月的数据能全部核对上，而不是仪表板看起来更整洁。

## 混合使用往往更合适

一个应用不必服务所有群组。旅行、室友、聚餐，以及任何需要灵活分摊规则或债务简化的群组，可以继续使用 Splitwise。Expense Budget Tracker 更适合人数较少、需要共同管理周期性收入、账户余额、分类预算、储蓄转账和家庭财务报告的人。

混合使用时，同一笔旅行消费可能在 Splitwise 中记录一次，用于结算；在家庭账本中再记录一次，用于预算。这很正常，因为两个系统记录的是同一事件的不同侧面。只有当家庭账本又把 Splitwise 中的分摊份额或欠款余额记成新支出时，才会重复计算。

如果你对 Splitwise 唯一不满的是录入上限或界面，可以比较其他具备同类欠款计算功能的多人支出记录工具。如果结算历史无法回答你的预算和账户问题，那么围绕完整账本构建的**开源 Splitwise 替代方案**才是更相关的选择。

## 到底该选哪一个？

以下情况继续使用 Splitwise：

- 需要快速录入群组支出和灵活的分摊公式
- 需要用余额显示谁欠谁多少钱
- 需要债务简化和结算记录
- 需要通过 Pro 使用收据扫描、明细拆分或受支持的交易导入
- 只需管理一个不需要家庭预算的临时群组

如果这些工作同样重要，只是你更喜欢另一款共享支出产品，请选择同类型的 Splitwise 替代方案。

以下情况可以试用 Expense Budget Tracker：

- 需要一套共享的预算与实际支出对比
- 需要多个真实账户，以及根据账本记录计算的余额
- 需要不计入收入或支出的转账
- 需要保留原币记录，并在读取时换算为报告币种
- 需要共享工作区访问权限和数据库层面的隔离
- 需要自行托管、托管 MCP 或直接使用 HTTP Agent API

对情侣来说，应该把公平性决策与记账决策分开。先商定分摊规则，明确每个账户的法律所有权，再选择真正能回答你们每月实际问题的账本。

[打开 Expense Budget Tracker](https://app.expense-budget-tracker.com/)，在保留 Splitwise 群组不变的前提下试跑一个已经结束的完整月份。等新账本的数据能够全部核对上再迁移；如果之后仍需要 Splitwise 的欠款计算功能，就继续保留它。
