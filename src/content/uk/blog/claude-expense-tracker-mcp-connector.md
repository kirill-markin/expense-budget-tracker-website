Найбезпечніша перша розмова між Claude і вашим трекером витрат майже до нудного проста. Claude показує список робочих просторів, переглядає актуальну схему й виконує один запит лише для читання. У реєстрі нічого не змінюється.

Такий спокійний початок важливий, адже пізніше той самий конектор може отримати дозвіл змінювати фінансові дані. Головне — розділяти доступ на читання й запис, явно вказувати робочий простір і перевіряти кожну зміну після її внесення.

Саме для такого сценарію Expense Budget Tracker має готовий віддалений MCP-конектор:

```text
https://mcp.expense-budget-tracker.com/mcp
```

Додайте цю URL-адресу в Claude, пройдіть OAuth-авторизацію в браузері — і Claude зможе працювати з трекером через чотири інструменти з чітко визначеними можливостями. Термінал, API-ключ і локальний файл конфігурації MCP для цього не потрібні.

## Це підключення через конектор, а не через API для Claude Code

Expense Budget Tracker підтримує два способи машинного доступу, і їхні облікові дані легко переплутати.

| | Віддалений MCP-конектор | Прямий Agent API |
|---|---|---|
| Найкраще підходить для | Розмов у Claude та Claude Desktop | Claude Code, Codex, скриптів та інших термінальних агентів |
| Адреса підключення | `https://mcp.expense-budget-tracker.com/mcp` | `https://api.expense-budget-tracker.com/v1/` |
| Автентифікація | OAuth у браузері | Довгостроковий `ApiKey` |
| Інтерфейс | Інструменти MCP | HTTP-ендпойнти |
| Облікові дані | Токени доступу й оновлення OAuth, які зберігає MCP-клієнт | ApiKey, що зберігається поза пам'яттю чату |

MCP-ендпойнт не приймає `ApiKey`, який використовується для прямого API. Цей ключ також не можна перетворити на користувацький конектор Claude. Це дві окремі інтеграції з різними способами авторизації.

Цей посібник допоможе підключити Claude до трекера витрат у вебверсії Claude або в Claude Desktop. Якщо ж завдання починається зі слів «прочитай цей CSV із мого ноутбука», скористайтеся термінальним сценарієм із матеріалу [Як відстежувати витрати й керувати бюджетом за допомогою Claude Code](/blog/how-to-track-expenses-and-manage-your-budget-with-claude-code/). У ширшому [посібнику з налаштування ШІ-трекера витрат](/blog/ai-agent-expense-tracker-claude-code-codex-openclaw/) описано роботу Claude Code, Codex і OpenClaw через прямий API.

## Додайте конектор Expense Budget Tracker до Claude

В особистому обліковому записі Claude зараз потрібно перейти до **Customize > Connectors > Add custom connector**. Актуальні інструкції щодо інтерфейсу й типів облікових записів Anthropic публікує у своєму [посібнику з користувацьких віддалених MCP-конекторів](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### 1. Додайте URL-адресу віддаленого MCP-сервера

Відкрийте Claude або Claude Desktop, а потім:

1. Перейдіть до **Customize > Connectors**.
2. Натисніть кнопку **+** і виберіть **Add custom connector**.
3. Назвіть його `Expense Budget Tracker`.
4. Введіть `https://mcp.expense-budget-tracker.com/mcp` як URL-адресу віддаленого MCP-сервера.
5. Натисніть **Add**.

Вам не потрібно вводити OAuth Client ID або Client Secret у розширених налаштуваннях. Сервер авторизації Expense Budget Tracker підтримує динамічну реєстрацію публічного OAuth-клієнта, для якого секрет клієнта не використовується.

Для облікових записів Team і Enterprise Owner або Primary Owner має спочатку додати користувацький конектор до організації. Після цього кожен учасник підключає власний обліковий запис і отримує доступ лише до тих робочих просторів, які йому доступні.

### 2. Підключіться й надайте доступ через OAuth

Натисніть **Connect** поруч із новим конектором. Claude знайде параметри авторизації за протоколом MCP і відкриє сторінку входу до Expense Budget Tracker у браузері. Увійдіть до облікового запису й перегляньте запитувані дозволи.

Конектор використовує дві області доступу з різними можливостями:

- `expenses:read` обов'язкова. Вона дає змогу переглядати доступні робочі простори й схему та виконувати запити лише для читання.
- `expenses:write` необов'язкова. Вона дозволяє використовувати інструмент `sql_execute`, який може змінювати дані.

Для огляду витрат, звітів, звірки й аналізу бюджету надавайте лише `expenses:read`. Додавайте `expenses:write`, тільки коли Claude має вставити, оновити або видалити конкретні дані. Немає причин надавати цей дозвіл «про всяк випадок».

Не вставляйте токен OAuth у промпт. Браузер і сховище облікових даних конектора Claude самі керують токенами доступу й оновлення.

### 3. Увімкніть конектор у розмові

Додавання конектора не означає, що Claude використовуватиме його в кожному чаті. Відкрийте в потрібній розмові меню **+**, виберіть **Connectors** і ввімкніть Expense Budget Tracker.

Можливість окремо вмикати конектор для кожної розмови особливо корисна під час роботи з фінансовими даними. Залишайте його вимкненим, коли він не потрібен, і вмикайте лише для конкретної сесії роботи з бюджетом.

## Що Claude робить під час OAuth

Виконувати ці кроки вручну не потрібно, але розуміння процесу допомагає діагностувати проблеми з підключенням.

Хмарний конектор публікує метадані захищеного ресурсу за адресою `https://mcp.expense-budget-tracker.com/.well-known/oauth-protected-resource/mcp`. Цей документ спрямовує Claude до метаданих сервера авторизації за адресою `https://auth.expense-budget-tracker.com/.well-known/oauth-authorization-server`.

Claude реєструється як публічний OAuth-клієнт, запускає в браузері сценарій Authorization Code й використовує PKCE з методом `S256`. Після підтвердження він обмінює код на токени й за потреби оновлює токени доступу. Це відповідає [моделі авторизації MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization), зокрема виявленню захищеного ресурсу та захисту кодів авторизації через PKCE.

Одна деталь дивує користувачів Claude Desktop: трафік віддаленого конектора не виходить із локального мережевого інтерфейсу настільного застосунку. [За інформацією Anthropic, користувацькі віддалені MCP-підключення виходять із її хмарної інфраструктури](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), навіть коли ви користуєтеся Claude Desktop. Конектор Expense Budget Tracker уже доступний через інтернет. Щоб Claude підключився до приватного MCP-сервера, який ви розгорнули самостійно, такий сервер має приймати з'єднання з інфраструктури Anthropic.

## Чотири інструменти, які отримує Claude

Замість необмеженого підключення до бази даних конектор надає чотири інструменти з вузькими можливостями.

| Інструмент | Що він робить | Дозвіл |
|---|---|---|
| `list_workspaces` | Показує робочі простори, доступні користувачу, який увійшов у систему | `expenses:read` |
| `get_schema` | Повертає доступні відношення та стовпці для вибраного робочого простору | `expenses:read` |
| `sql_query` | Виконує один обмежений SQL-запит лише для читання | `expenses:read` |
| `sql_execute` | Виконує обмежену SQL-команду, яка змінює дані | `expenses:read` і `expenses:write` |

Для `sql_query` на рівні бази даних діють права лише на читання. Він повертає не більше 100 рядків і виконується не довше 20 секунд. Якщо доступний `sql_execute`, конектор уже не можна вважати суто інструментом для читання, тому необов'язковий дозвіл на запис варто розглядати окремо.

Актуальну схему потрібно отримати до написання SQL. Назви таблиць, стовпці й дозволені відношення треба брати з `get_schema`, а не зі старого промпту, скопійованого прикладу чи пам'яті Claude про інший фінансовий застосунок.

## Почніть першу сесію в безпечній послідовності

Перший промпт має змусити Claude спочатку визначити контекст і лише потім переходити до аналізу:

```text
Використовуй конектор Expense Budget Tracker у режимі лише для читання.

Спочатку виклич list_workspaces і покажи доступні назви та ідентифікатори
робочих просторів. Попроси мене підтвердити, який робочий простір використовувати,
навіть якщо він лише один. Потім виклич get_schema для підтвердженого робочого
простору. Використовуй лише sql_query. Не викликай sql_execute й поки не пропонуй
жодних змін.

Отримавши схему, підсумуй мої витрати за категоріями в поточному календарному
місяць і порівняй їх із попереднім календарним місяцем. Використовуй агрегатні
запити, а не повертай кожен рядок реєстру. Покажи запит і поясни всі обмеження,
які впливають на результат.
```

Порядок важливий: виберіть робочий простір, перегляньте його актуальну схему й лише потім пишіть запит. Якщо один запит має повернути понад 100 рядків, попросіть Claude агрегувати дані в SQL або розбити аналіз на логічні періоди. Мета не в тому, щоб протягнути весь реєстр через чат. Потрібно обчислити відповідь на рівні бази даних і повернути лише корисний результат.

## Корисні промпти для першої сесії лише для читання

Після того як Claude підтвердив робочий простір і переглянув схему, він може робити більше, ніж просто показувати останні покупки.

### Проведіть щомісячний огляд бюджету

```text
Використовуючи лише sql_query, порівняй фактичні доходи й витрати з бюджетом на цей
місяць. Згрупуй різниці за категоріями, постав найбільші абсолютні різниці на
перше місце й відокрем відсутні бюджетні дані від справжнього перевищення витрат.
Не змінюй жодного рядка бюджету. Покажи використаний SQL.
```

Це спосіб провести [щомісячний огляд бюджету](/blog/how-to-do-a-monthly-budget-review/) просто в розмові: спочатку знайти розбіжність, а вже потім вирішувати, що потрібно змінити.

### Знайдіть можливі дублікати витрат

```text
Використай актуальну схему й sql_query, щоб знайти можливі дублікати записів про
витрати за останні 45 днів. Порівняй дати, суми, валюти, рахунки й контрагентів,
де такі поля є. Вважай результат кандидатами, а не підтвердженими дублікатами.
Нічого не видаляй і не оновлюй.
```

Фраза «кандидати, а не підтверджені дублікати» важлива. Дві однакові покупки кави ще не означають, що одну операцію випадково імпортували двічі.

### Підготуйте перевірку балансу

```text
Використай list_workspaces, підтвердь мій особистий робочий простір, переглянь схему
й отримай баланси, доступні через конектор. Поясни, які записи реєстру формують
останній баланс. Не внось виправлень. Я самостійно порівняю результат із банківською
випискою.
```

Якщо баланс не збігається з банківською випискою, не виправляйте дані одразу — спершу дослідіть розбіжність. В [інструкції зі звірки бюджету](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) пояснено, як відокремити пропущені транзакції, дублікати, проблеми з початковим балансом і перекази, перш ніж змінювати реєстр.

## Виконуйте кожну зміну даних як окреме завдання

Доступ для запису корисний, коли ціль і очікуваний результат зрозумілі: потрібно виправити категорію однієї транзакції, записати схвалену витрату або внести погоджену зміну до рядка бюджету. Обмежтеся невеликою зміною, яку легко перевірити, замість розмитої команди «наведи лад у всьому».

Ось обережний промпт для зміни категорії однієї транзакції:

```text
Мені потрібно виправити категорію одного запису в реєстрі.

1. Виклич list_workspaces і попроси мене підтвердити цільовий робочий простір.
2. Виклич get_schema, не припускай назви стовпців.
3. Використай sql_query, щоб знайти точний запис за датою, сумою, валютою, рахунком
   і даними контрагента, які я надам.
4. Якщо не знайдеш рівно одного однозначного збігу, зупинися й запитай мене, що робити.
5. Покажи точну SQL-команду, яку пропонуєш для sql_execute, ідентифікатор робочого
   простору, знайдений запис і очікуваний результат. Поки не виконуй її.
6. Дочекайся мого явного підтвердження.
7. Після підтвердження один раз виклич sql_execute. Потім виконай новий sql_query,
   щоб перевірити збережене значення, і повідом мені результат.
```

Так ви завжди бачите три ключові речі: який робочий простір обрано, який запис знайдено й яку саме зміну буде внесено. Перевірка — це повторне читання після зміни, а не запевнення Claude, що запис, імовірно, спрацював.

Та сама схема працює для імпорту. Попросіть Claude переглянути наявні категорії й можливі дублікати, показати, які саме рядки він планує вставити, та дочекатися явного підтвердження. Після запису схвалених даних перевірте вставлені рядки й звірте отриманий баланс. Якщо ви починаєте з банківського експорту, у матеріалі [Як імпортувати банківські виписки в трекер витрат](/blog/how-to-import-bank-statements-into-an-expense-tracker/) описано етапи перевірки вихідного файлу.

## Залишайте мінімальні дозволи під час роботи з фінансовими даними

MCP усуває потребу копіювати ключ у чат, але ви все одно маєте контролювати дії конектора. [Рекомендації Anthropic із безпеки конекторів](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) радять підключатися лише до надійних серверів, переглядати запитувані дозволи й звертати увагу на дані, які інструменти отримують і повертають.

Для цього конектора правила можна звести до короткого списку:

1. Переконайтеся, що URL-адреса точно збігається з `https://mcp.expense-budget-tracker.com/mcp`.
2. Починайте з `expenses:read`, якщо для запланованого завдання не потрібно змінювати дані.
3. Підтверджуйте робочий простір перед кожною сесією, у якій вноситимете зміни.
4. Переглядайте актуальну схему перед генеруванням SQL.
5. Перевіряйте точну SQL-команду й очікуваний результат перед `sql_execute`.
6. Одразу після цього перевіряйте результат за допомогою `sql_query`.
7. Вимикайте `sql_execute` в налаштуваннях інструментів Claude або вимикайте конектор для розмови, коли він більше не потрібен.

Не вибирайте **Always allow** для `sql_execute`. Пауза перед кожною операцією запису корисна, коли інструмент може змінювати фінансові дані.

Фінансові нотатки й імпортовані описи теж мають залишатися даними, а не інструкціями. Якщо текст, збережений у транзакції, просить Claude проігнорувати ваші правила або викликати інший інструмент, не виконуйте його. Це ще одна причина вимикати доступ для запису під час широкого аналізу даних.

Перед підключенням перегляньте [Політику конфіденційності Expense Budget Tracker](/privacy/) і умови обробки даних Anthropic. Авторизована сесія Claude може читати фінансові дані, доступні вашому обліковому запису, а з `expenses:write` — змінювати їх. Віддалене підключення проходить через хмару Anthropic і хмарний сервіс Expense Budget Tracker; Claude Desktop не перетворює його на суто локальний канал передавання даних.

## Діагностуйте проблеми з підключенням без здогадок

### Користувацький конектор не підключається

Спочатку перевірте адресу підключення. Вона має бути такою:

```text
https://mcp.expense-budget-tracker.com/mcp
```

Не підставляйте URL-адресу сайту або адресу прямого API. Залиште поля Advanced OAuth Client ID і Client Secret порожніми. Переконайтеся, що у вас є активний обліковий запис Expense Budget Tracker. Якщо автентифікація все одно не працює, від'єднайте й повторно підключіть конектор через **Customize > Connectors**.

Для облікового запису Claude Team або Enterprise запитайте в Owner чи Primary Owner, чи додано користувацький конектор до організації та чи дозволено його використовувати. Окремі учасники не можуть самостійно змінити це налаштування на рівні організації.

### Claude каже, що конектор є, але не використовує його

Увімкніть Expense Budget Tracker для поточного чату через меню **+ > Connectors**. Потім назвіть конектор у промпті й попросіть Claude почати з `list_workspaces`. Налаштований конектор може залишатися вимкненим в окремій розмові.

### `sql_execute` недоступний або Claude не має дозволу

Найімовірніше, під час OAuth ви надали `expenses:read` без необов'язкової області `expenses:write`. Залиште все так, якщо завдання полягає в аналізі. Якщо конкретне схвалене завдання потребує зміни даних, повторно підключіться й перегляньте запитуваний дозвіл на запис, перш ніж його надати.

### Запит завершується помилкою або повертає забагато даних

Знову викличте `get_schema` і складіть SQL на основі повернених відношень та стовпців. Не виходьте за межі можливостей SQL, які підтримує конектор. Для великих реєстрів обчислюйте підсумки, кількість записів і згруповані результати в SQL, а не просіть повернути понад 100 рядків. Запити, що перевищують 20-секундний ліміт виконання, потрібно звузити.

### Claude переглядає не ті фінансові дані

Зупиніться, перш ніж щось записувати. Викличте `list_workspaces`, порівняйте повернені назви й ідентифікатори та явно підтвердьте цільовий простір. Потім викличте `get_schema` для цього робочого простору й повторно виконайте запит лише для читання. Claude бачить лише робочі простори, доступні користувачу, який увійшов у систему, але все одно має вибрати саме той простір, який ви вказали.

### Claude просить `ApiKey`

Він виконує сценарій прямої HTTP-інтеграції, а не віддаленого MCP-конектора. Для цього налаштування поверніться до URL-адреси конектора й авторизації OAuth у браузері. Якщо вам справді потрібна автоматизація з термінала або прямі HTTP-запити, натомість використовуйте [довідник Agent API](/docs/api/).

## Саме налаштування коротке, але головне — цикл перевірки

Щоб підключити Claude до Expense Budget Tracker, достатньо вказати одну URL-адресу й один раз увійти через браузер. Надалі важливо дотримуватися простої послідовності: отримати список робочих просторів, переглянути схему, спочатку читати, надавати мінімально необхідні дозволи й описувати зміни настільки конкретно, щоб їх можна було перевірити рядок за рядком.

Почніть із повної [документації MCP-конектора](/docs/mcp-connector/), додайте `https://mcp.expense-budget-tracker.com/mcp` у розділі **Customize > Connectors** і проведіть щомісячний огляд лише для читання. Коли все ж знадобиться щось змінити, попросіть Claude показати робочий простір, запис, SQL та очікуваний результат, перш ніж надавати дозвіл. Так трекер витрат для Claude перестає бути просто зручною демонстрацією і стає надійним сценарієм роботи з фінансами.
