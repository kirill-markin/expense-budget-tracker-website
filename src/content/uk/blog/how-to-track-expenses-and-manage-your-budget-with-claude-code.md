Виписка з чотирьох рядків може пройти звірку з різницею `€0.00`, а бюджет усе одно залишиться неправильним. Достатньо віднести покупку в супермаркеті на €54.20 до «Подорожей» замість «Продуктів»: залишок на рахунку збігається до цента, а звіт за категоріями помиляється на €54.20.

Тому для обліку витрат із Claude Code потрібні дві окремі перевірки. По-перше, після врахування збережених операцій залишок має збігатися з банківським. По-друге, категорії цих операцій мають відповідати перевіреній виписці. Claude Code може розібрати файл, виконати розрахунки й звернутися до API. Ви вибираєте рахунок і категорії, переглядаєте запропоновані записи та погоджуєте кожну конкретну зміну.

У цьому сценарії Expense Budget Tracker не підтримує прямого підключення до банку й не має форми для завантаження виписки. Експортуйте виписку самостійно, покладіть її в каталог, до якого Claude Code має доступ, і надсилайте через керований Agent API лише погоджені записи. Якщо для вас головне — не надавати постійного доступу до банку, у статті [Бюджетний застосунок без підключення до банку](/blog/budget-app-without-bank-linking/) докладніше пояснено ширші компроміси такого підходу.

## Підключіть Claude Code за одним службовим посиланням

Установіть Claude Code і ввійдіть в обліковий запис за [офіційною короткою інструкцією](https://code.claude.com/docs/en/quickstart) Anthropic. У [довіднику CLI](https://code.claude.com/docs/en/cli-reference) пояснено, як працюють робочі каталоги й додатковий доступ до файлів.

Запустіть `claude` в каталозі з випискою або надайте Claude Code доступ до цього каталогу способом, який підтримує ваше середовище. Потім вставте такий запит:

```text
Підключись до Expense Budget Tracker за цим службовим посиланням:
https://app.expense-budget-tracker.com/api/agent

Виконай GET-запит, прочитай отриманий JSON і переходь за актуальними URL-адресами
дій. Не намагайся вгадати послідовність роботи API й не прописуй її жорстко. Запитай
мою електронну адресу для Expense Budget Tracker і розпочни вхід за одноразовим
кодом (OTP) з електронного листа.
Коли запит буде виконано, порадь перевірити папки «Спам» і «Небажана пошта», якщо
листа не видно. Потім попроси ввести 8-значний код і виконай отриману дію перевірки.

Після перевірки попроси мене погодити постійне місце для зберігання отриманого
ApiKey поза пам’яттю чату й системою контролю версій. Завантаж контекст мого
облікового запису, покажи список робочих просторів і попроси підтвердити потрібний.
Збережи його як типовий для цього ключа та переглянь актуальну схему. Виконай один
невеликий запит лише для читання, щоб перевірити вибраний робочий простір. Не
записуй жодних фінансових даних.
```

[Службове посилання в застосунку](https://app.expense-budget-tracker.com/api/agent) повертає актуальний службовий документ для підключення. Наразі він містить базову адресу API `https://api.expense-budget-tracker.com/v1/`, а також URL-адреси дій для автентифікації та SQL. Вставляйте саме посилання на домені застосунку: Claude Code має переходити за адресами, які повертає сервіс, а не покладатися на запам’ятовану внутрішню послідовність.

Той самий процес через електронну пошту працює і для реєстрації, і для входу. Після введення 8-значного коду Claude Code отримає довготривалий `ApiKey`. Погодьте конкретне місце для його зберігання — наприклад, файл із секретами, виключений із системи контролю версій. Ніколи не записуйте ключ у `CLAUDE.md` і не додавайте його до комітів у репозиторії. У розділі [Налаштування ШІ-агента](/docs/agent-setup/) описано базову послідовність автентифікації та вибору робочого простору.

## Не плутайте Agent API з MCP

Запит «трекер витрат Claude» може стосуватися двох різних інтеграцій. У цій статті Claude Code працює в терміналі через Agent API. Claude і Claude Desktop натомість можуть підключатися через віддалений MCP-конектор, розміщений у хмарі.

| | Claude Code з Agent API | Claude або Claude Desktop із MCP |
|---|---|---|
| Найкраще підходить для | Роботи в терміналі з доступними локальними файлами та прямими HTTP-запитами | Діалогу в клієнті Claude з підтримкою MCP |
| Початкова адреса | `https://app.expense-budget-tracker.com/api/agent` | `https://mcp.expense-budget-tracker.com/mcp` |
| Автентифікація | Одноразовий код з електронного листа, потім довготривалий `ApiKey` | OAuth у браузері |
| Інтерфейс даних | URL-адреси зі службового документа, що ведуть до ендпоїнтів для запитів і виконання команд | Інструменти `sql_query` і, за потреби, `sql_execute` |
| Доступ до виписки | Файли й каталоги, доступні в поточному сеансі Claude Code | Віддалений конектор не має доступу до локальних файлів |

Ці інтеграції використовують різні облікові дані — замінити одні іншими не можна. Для вебверсії або настільного застосунку Claude скористайтеся [посібником із підключення MCP до трекера витрат Claude](/blog/claude-expense-tracker-mcp-connector/). Процес з Agent API, описаний нижче, підходить тоді, коли робота починається з файлу, доступного Claude Code.

Ще дві межі варто проговорити окремо:

- Постачальник моделі обробляє дані окремо від API та сховища Expense Budget Tracker. Перш ніж передавати дані виписки, прочитайте [документацію Claude Code про використання даних](https://code.claude.com/docs/en/data-usage) та умови постачальника, налаштованого у вашому середовищі.
- Локальна конфігурація Docker Compose з [інструкції із самостійного розгортання](/docs/self-hosting/) запускає вебзастосунок, сервіс автентифікації, базу даних і FX-воркер. Вона не містить керованого Agent API, який використовується в цій статті. Розгортання репозиторію в AWS — окрема конфігурація із загальнодоступним API для програмних клієнтів.

## Чітко окресліть межі імпорту

Для першого запуску візьміть один рахунок, одну валюту й один повністю закритий період виписки. CSV зручний тим, що його рядки легко перевірити. Якщо у вас інший формат, спочатку попросіть Claude Code підтвердити, що файл читається у вашому середовищі, і показати розібрані рядки. Сама назва файлу ще не доводить, що його формат підтримується.

Надайте Claude Code шість відомостей:

1. Локальний шлях до виписки.
2. Банківський рахунок і відповідний рахунок у трекері.
3. Валюту рахунку.
4. Дати першої та останньої проведених операцій.
5. Початковий залишок або останній відомий правильний залишок.
6. Кінцевий залишок із виписки.

Не включайте непроведені операції, доки банк їх не проведе. Не змінюйте вихідний файл, а попередній перегляд попросіть Claude Code підготувати окремо.

Для фінансового каталогу можна додати в локальний `CLAUDE.md` такі правила:

```markdown
# Робота з Expense Budget Tracker

- Починай з https://app.expense-budget-tracker.com/api/agent і дотримуйся процедури підключення.
- Перш ніж складати SQL, підтвердь цільовий робочий простір і переглянь актуальну схему.
- Для всіх перевірок і звірок використовуй лише дію читання.
- Перед записом покажи підсумки вихідних даних, можливі дублікати, точний SQL і очікувану кількість змінених рядків.
- Чекай на моє явне погодження всього набору змін.
- Використовуй дію запису лише для погоджених INSERT, UPDATE або DELETE.
- Після кожного запису виконуй нове читання й перевіряй результат.
- Ніколи не створюй балансувальний запис і не вибирай мовчки категорію для неоднозначної операції.
- Зберігай ApiKey поза цим файлом і системою контролю версій.
```

Додайте сталі відомості: справжні назви рахунків, правила категоризації, спосіб обліку переказів і валюту звітності. Не копіюйте категорії з прикладу в цій статті, якщо вони не відповідають вашому реєстру операцій.

## Імпортуйте виписку лише після повного попереднього перегляду

Коли підключення запрацює, вставте цей запит і замініть значення в квадратних дужках:

```text
Імпортуй [локальний шлях до виписки] до [рахунку в трекері] за період від
[дати початку проведених операцій] до [дати завершення проведених операцій] у [валюті].
Початковий залишок становить [сума], а кінцевий залишок за даними банку — [сума].

Спочатку підтвердь вибраний робочий простір і переглянь актуальну схему. Використовуй
лише дію читання, щоб перевірити цільовий рахунок, наявні категорії та записи в
реєстрі операцій, дати яких перетинаються з періодом виписки. Підтвердь, що можеш
прочитати локальний файл, розібрати його й підготувати повний попередній перегляд,
нічого не записуючи.

Для кожного вихідного рядка покажи його ідентифікатор у джерелі або номер, дату
проведення, суму зі знаком, валюту, цільовий рахунок, запропонований тип операції,
запропоновану категорію та статус дубліката. Познач перекази, повернення коштів,
відшкодування, комісії, операції в іноземній валюті, незнайомих контрагентів і
неоднозначні класифікації.

Потім покажи кількість вихідних рядків і їхню загальну суму зі знаком, усі
запропоновані записи в реєстрі, можливі дублікати, точний SQL, який ти надішлеш,
і очікувану кількість змінених рядків. Зупинись і чекай на моє явне погодження
всього набору змін.
```

Робота з базою даних залишається в режимі лише для читання, доки ви не погодите зміни. Claude Code має переглянути актуальну схему, а не копіювати назви стовпців зі статті, знайти відповідний рахунок і перевірити наявні записи за ті самі дати. Збіг дати й суми робить операцію лише кандидатом у дублікати, а не підтвердженим дублікатом: дві справжні покупки можуть мати однакові значення в обох полях.

### Приклад із чотирма рядками

Припустімо, початковий залишок у виписці з поточного рахунку становить €1,250.00, а далі в ній є чотири проведені операції:

| Рядок | Дата проведення | Опис | Сума зі знаком | Запропонований тип | Запропонована категорія | Що перевірити |
|---|---|---|---:|---|---|---|
| 1 | 2026-08-31 | Зарплата | +€2,000.00 | Дохід | Зарплата | Усе зрозуміло |
| 2 | 2026-09-02 | Супермаркет | −€54.20 | Витрата | Продукти | Перевірте продавця, якщо він вам не знайомий |
| 3 | 2026-09-03 | Переказ на заощадження | −€300.00 | Переказ | — | Підтвердьте інший рахунок |
| 4 | 2026-09-04 | Кафе | −€8.40 | Витрата | Харчування поза домом | Усе зрозуміло |

Сума чотирьох операцій з урахуванням знаків становить `+€1,637.40`. Додавши її до початкового залишку `€1,250.00`, отримуємо очікуваний кінцевий залишок `€2,887.40`. Цей приклад уміщується на одному екрані. У довшому імпорті попередній перегляд усе одно має містити кожен вихідний рядок і чітко позначати кожну неоднозначність.

Для переказу треба підтвердити другий рахунок, адже переміщення грошей між власними рахунками не є витратою. Повернення коштів і відшкодування також мають зберігати свій фактичний тип. Якщо класифікація неоднозначна, залиште її позначеною для окремого рішення, а не вибирайте найімовірнішу категорію.

### Погодьте один конкретний набір змін

Перевірте робочий простір, рахунок, межі періоду, кількість рядків, загальну суму з урахуванням знаків, можливі дублікати та класифікацію операцій. Погодьте конкретний попередній перегляд і SQL, а не загальну вказівку «імпортувати все».

В Agent API читання відокремлено від запису. Claude Code використовує отриману дію читання для одного `SELECT` або `WITH ... SELECT`, а дію запису — лише для явно погодженого `INSERT`, `UPDATE` або `DELETE`. Актуальна схема визначає назви таблиць і стовпців; у [довіднику API](/docs/api/) описано контракт SQL та його обмеження.

### Перевірте довгі вставки й оновлення перед пакетним записом

Перед довгим `INSERT` або `UPDATE` актуальні інструкції зі службового документа вимагають надіслати репрезентативний пробний запит із такою самою структурою SQL: 1–3 рядки з літеральними значеннями для `INSERT` або один цільовий рядок для `UPDATE`. Ваше погодження охоплює і цю пробу, і решту рядків у перевіреному наборі змін.

Якщо проба успішна, Claude Code має відразу продовжити роботу послідовними пакетами не більш як по 100 записів і перевіряти кожен пакет. Після проби з 3 рядків у погодженому імпорті на 247 рядків залишаться пакети зі 100, 100 і 44 рядків. Зміна обсягу, нова неоднозначність або помилка виконання потребують нового погодження. Для звичайних наступних пакетів із уже погодженого набору воно не потрібне.

Обмежений SQL не підтримує `ON CONFLICT`, тому дублікати треба обробляти явно. Результат читання не може містити більш як 100 рядків. Claude Code має перевіряти в метаданих відповіді кількість рядків і ознаку скорочення результату, обчислювати підсумки засобами SQL, а детальну перевірку розбивати на вузькі впорядковані запити читання. Скорочена відповідь не вважається повною перевіркою імпорту.

### Ще раз зчитайте збережені записи

Успішна відповідь API підтверджує, що запит було виконано. Вона не гарантує, що кожне збережене значення відповідає попередньому перегляду. Знову зробіть запит до потрібного рахунку за відповідний період і порівняйте:

- кількість вставлених рядків
- дати, суми зі знаком і валюти
- прив’язку до рахунку
- типи операцій і категорії
- можливі дублікати
- підсумки пакетів і загальну суму всієї виписки

Якщо знайдете розбіжність, поверніться до діагностики в режимі лише для читання. Перед наступним записом перевірте й погодьте одне конкретне виправлення. У [посібнику з імпорту банківських виписок](/blog/how-to-import-bank-statements-into-an-expense-tracker/) докладніше розглянуто періоди, що перетинаються, повернення коштів і перекази.

## Звіряйте залишок і категорії окремо

Звірка залишку показує, чи відповідають збережені операції кінцевому залишку за даними банку в тих самих межах дат проведення.

Для звичайного депозитного рахунку:

**очікуваний кінцевий залишок = початковий залишок + проведені надходження − проведені списання**

Якщо суми операцій мають знак:

**очікуваний кінцевий залишок = початковий залишок + сума проведених операцій з урахуванням знаків**

Для рахунків із заборгованістю, зокрема кредитних карток, може діяти інше правило знаків. Перш ніж виконувати розрахунок, Claude Code має вказати, яке правило він виявив.

Продовжте таким запитом:

```text
Використовуй лише дію читання. Звір [рахунок] за період від [дати початку проведених
операцій] до [дати завершення проведених операцій] із кінцевим залишком за даними
банку [сума й валюта]. Вкажи початкову межу, правило знаків, кількість збережених
рядків і загальну суму операцій з урахуванням знаків.

Покажи очікуваний кінцевий залишок, кінцевий залишок за даними банку й точну різницю.
Якщо різниця не дорівнює нулю, переліч можливі пропущені, дубльовані або виключені
рядки, а також рядки з неправильною датою чи знаком. Не додавай балансувальний запис
і не змінюй жодних даних.

Після звірки залишку окремо перевір підсумки за категоріями. Переліч рядки без
категорії, перекази, враховані як витрати, і категорії, що відрізняються від
погодженого попереднього перегляду.
```

У прикладі з чотирма рядками `€1,250.00 + €1,637.40 = €2,887.40`. Якщо кінцевий залишок за даними банку також становить €2,887.40, різниця дорівнює `€0.00`.

Нульова різниця підтверджує арифметику рахунку у вибраних межах, але не правильність категорій. Якщо перенести операцію «Супермаркет» на €54.20 із «Продуктів» до «Подорожей», різниця залишиться нульовою, проте €54.20 перемістяться між підсумками двох категорій. Тому перевірка категорій — окремий етап приймання.

Якщо різниця не дорівнює нулю, перевірте початковий залишок, пропущені й дубльовані рядки, перекази, непроведені операції, знаки, дати та валюти. Ніколи не додавайте штучної балансувальної операції лише заради нульової різниці. У [посібнику зі звірки](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) цей діагностичний цикл описано докладніше.

## Оновлюйте бюджет тільки після звірки

Переходьте до бюджету лише тоді, коли повторне читання підтвердило всі записи, рахунок зійшовся, а підсумки за категоріями виглядають правильно. Claude Code може працювати як трекер бюджету: порівнювати фактичні операції з `budget_lines` і готувати запропоновані зміни. Один незвичайний місяць не повинен автоматично визначати наступний план.

```text
Підтвердь робочий простір і переглянь актуальну схему. За допомогою дії читання
порівняй фактичні доходи й витрати за [повний період] із відповідними рядками бюджету.
Виключи перекази за збереженим типом операції та окремо покажи операції без категорії.

Для кожної запропонованої зміни бюджету покажи категорію, поточну суму, фактичну
суму, запропоновану суму, різницю та причину. Потім покажи точний SQL і очікувану
кількість змінених рядків. Нічого не записуй, доки я не погоджу конкретні рядки.

Після погодження використовуй дію запису лише для цих рядків і перевір їх новим
читанням. Повідом про кожне збережене значення, яке відрізняється від погодженої
пропозиції.
```

Велика витрата може бути разовою. Те, що виглядає як перевищення бюджету, іноді виявляється неправильно класифікованим переказом або поверненням коштів. Claude Code може розрахувати різниці й підготувати SQL, але суми на наступний місяць визначаєте ви.

## Повторюйте ту саму послідовність для кожної виписки

Для кожної виписки дотримуйтеся однакового порядку:

1. Почніть із `https://app.expense-budget-tracker.com/api/agent` і дотримуйтеся процедури підключення.
2. Завантажте контекст облікового запису, підтвердьте робочий простір і перегляньте актуальну схему.
3. Надайте Claude Code один доступний файл виписки й чітко вкажіть початковий та кінцевий залишки.
4. Зчитайте записи реєстру, дати яких перетинаються з періодом виписки, і підготуйте повний попередній перегляд імпорту.
5. Погодьте один конкретний набір змін.
6. Для довгого `INSERT` виконайте пробу з 1–3 рядків, а потім записуйте послідовними пакетами не більш як по 100 рядків.
7. Зчитайте кожен збережений пакет і порівняйте його з попереднім переглядом.
8. Звірте рахунок із кінцевим залишком за даними банку, не додаючи балансувального запису.
9. Перевірте підсумки за категоріями, навіть якщо різниця залишків дорівнює нулю.
10. Окремо підготуйте, погодьте й перевірте всі зміни в рядках бюджету.

Почніть з одного рахунку й одного закритого періоду. Коли операції з цієї виписки опиняться у звіреному реєстрі, а бюджет буде перевірено, повторіть процес для наступного рахунку. Claude Code бере на себе рутинну роботу з файлами та API, а кожне фінансове рішення залишається видимим до того, як зміняться ваші записи.
