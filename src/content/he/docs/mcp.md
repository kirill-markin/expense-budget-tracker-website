Expense Budget Tracker מספק כתובת אחת לשרת MCP מרוחק ומתארח:

```text
https://mcp.expense-budget-tracker.com/mcp
```

השתמשו באותה כתובת בכל לקוח תואם. השרת המתארח משתמש ב-Streamable HTTP וב-OAuth 2.1; נקודת הקצה הזו אינה מקבלת מפתחות API.

## לקוחות נתמכים

נקודת הקצה פועלת עם ChatGPT ועם לקוחות MCP אחרים שתומכים בכל אלה:

- שרתי MCP מרוחקים באמצעות Streamable HTTP;
- תהליך Authorization Code של OAuth 2.1 עם PKCE;
- רישום דינמי של לקוח OAuth, או Dynamic Client Registration.

Claude, Codex, OpenClaw ולקוחות נוספים יכולים להשתמש באותה נקודת קצה כאשר הגרסה הנוכחית שלהם תומכת בתעבורה המרוחקת ובתהליך האימות האלה. לקוח שתומך רק בשרתי `stdio` מקומיים אינו יכול להתחבר ישירות לנקודת הקצה המתארחת.

## חיבור והרשאה

1. הוסיפו את `https://mcp.expense-budget-tracker.com/mcp` כשרת MCP מרוחק מותאם אישית בלקוח שלכם.
2. הלקוח מגלה את המשאב המוגן ואת שרת ההרשאה, ולאחר מכן רושם את שמו ואת כתובות ההפניה שלו באמצעות Dynamic Client Registration.
3. הדפדפן פותח את מסך הכניסה וההסכמה של Expense Budget Tracker. היכנסו, בדקו את שם הלקוח ואת ההרשאות המבוקשות, ואשרו רק את הגישה שברצונכם להעניק.
4. הלקוח מחליף את קוד ההרשאה באמצעות PKCE ומתחבר עם אישורי גישה קצרי טווח. אין צורך להעתיק אסימון אל הלקוח.
5. בקשו מהלקוח לקרוא ל-`list_workspaces` לפני קריאה או שינוי של נתונים פיננסיים.

שרת ההרשאה יכול להעניק את ה-scopes הבאים:

| Scope | גישה |
| --- | --- |
| `expenses:read` | הצגת סביבות עבודה, בדיקת סכמת הנתונים המותרת ושאילתות על נתונים פיננסיים. |
| `expenses:write` | הפעלת `INSERT`, `UPDATE` או `DELETE` מותרים באמצעות `sql_execute`. הרשאת הכתיבה נפרדת מהרשאת הקריאה. |

חיבור לקריאה בלבד מקבל `expenses:read`. חיבור שמאפשר כתיבה מקבל גם `expenses:read` וגם `expenses:write`.

## כלים

| כלי | מטרה | גבול |
| --- | --- | --- |
| `list_workspaces` | מציג את כל סביבות העבודה הזמינות למשתמש המחובר. | קריאה בלבד; דורש `expenses:read`. |
| `get_schema` | מחזיר את הקשרים, העמודות, האילוצים, המגבלות והנחיות הסוכן המותרים בסביבת עבודה אחת. | קריאה בלבד; דורש `expenses:read`. |
| `sql_query` | מפעיל בדיוק פקודת `SELECT` או `WITH ... SELECT` אחת שאושרה לפי המדיניות. | טרנזקציה לקריאה בלבד בתפקיד מוגבל; דורש `expenses:read`. |
| `sql_execute` | מפעיל בדיוק פקודת `INSERT`, `UPDATE` או `DELETE` אחת שאושרה לפי המדיניות. | משנה נתונים פיננסיים ואינו אידמפוטנטי; דורש `expenses:write`. |

הכלים פועלים רק על נתוני Expense Budget Tracker. הם אינם יכולים לגלוש באינטרנט, לגשת לשירות אחר, להריץ DDL או לעקוף את הקשרים והעמודות שמוחזרים על ידי `get_schema`.

## בחירת סביבת עבודה

קראו תחילה ל-`list_workspaces`. אם מוחזרת סביבת עבודה אחת בלבד, אפשר להשמיט את `workspaceId` מהקריאות האחרות. אם זמינות כמה סביבות, בחרו אחד מהמזהים שהוחזרו והעבירו את אותו `workspaceId` במפורש בכל קריאה ל-`get_schema`, ל-`sql_query` ול-`sql_execute`. השרת דוחה סביבה עמומה או בלתי נגישה במקום לנחש.

לאחר בחירת הסביבה ולפני כתיבת SQL, קראו ל-`get_schema`. [מדריך ה-API](/he/docs/api/) הוא המקור לחוזה המפורט של הקשרים ושל SQL; המדריך הזה מתאר רק את חיבור ה-MCP ואת מודל הבטיחות.

## גבולות קריאה וכתיבה

השתמשו ב-`sql_query` לבדיקה ולדוחות. השתמשו ב-`sql_execute` רק כשהשינוי המבוקש ברור והמשתמש אישר אותו. מכיוון ששינויים אינם אידמפוטנטיים, אל תחזרו באופן עיוור על כתיבה שתוצאתה אינה ודאית: בדקו קודם את המצב שנוצר וחזרו על הפעולה רק אם הוכח שהשינוי לא בוצע.

הבידוד בין סביבות העבודה נאכף בצד השרת באמצעות אבטחה ברמת שורה של Postgres ותפקידי מסד נתונים מוגבלים. השירות אוכף את ה-scopes של OAuth, את החברות בסביבת העבודה, את מדיניות ה-SQL, את מגבלת הזמן ואת מספר שורות התגובה.

## פרטיות, ביטול גישה ועזרה

לקוח ה-AI הוא צד שלישי נפרד. הוא עשוי לעבד או לשמור הנחיות ותוצאות כלים בהתאם לתנאים ולמדיניות הפרטיות שלו. עיינו במדיניות הזו לפני חיבור נתונים פיננסיים. [מדיניות הפרטיות](/he/privacy/) מסבירה מה השירות המתארח מעבד ושומר.

בטלו גישה של לקוח MCP מחובר מתוך **הגדרות > גישת סוכנים** באפליקציה המתארחת. הביטול פוסל את אישורי הגישה והרענון של אותו חיבור. לבעיות חיבור, השתמשו ב[עמוד התמיכה](/he/support/).
