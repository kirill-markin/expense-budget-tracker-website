אפשר להגיע להפרש של `€0.00` בדף חשבון בן ארבע שורות ועדיין לקבל תקציב שגוי. אם מסווגים רכישה בסופרמרקט בסך €54.20 כנסיעות במקום כמצרכים, יתרת החשבון נשארת מדויקת — אבל דוח הקטגוריות סוטה ב-€54.20.

כלי שימושי למעקב הוצאות עם Claude Code חייב לבצע שתי בדיקות, לא אחת: התנועות שנשמרו צריכות להסביר את יתרת הבנק, והקטגוריות שנשמרו צריכות להתאים לדף החשבון שבדקתם. Claude Code יכול לנתח את הקובץ, לבצע את החישובים ולשלוח קריאות API. אתם בוחרים את החשבון ואת הקטגוריות, עוברים על הרשומות המוצעות ומאשרים בדיוק מה ייכתב.

בתצורה הזו אין ל-Expense Budget Tracker חיבור מובנה לבנק או תהליך להעלאת דף חשבון. ייצאו בעצמכם את דף החשבון מהבנק, שמרו אותו במקום ש-Claude Code רשאי לקרוא ושלחו דרך Agent API המנוהל רק את הרשומות שאישרתם. אם חשוב לכם בעיקר להימנע מגישה קבועה לחשבון הבנק, [אפליקציית תקציב ללא חיבור לבנק](/blog/budget-app-without-bank-linking/) מסבירה את השיקולים הרחבים יותר.

## חברו את Claude Code בעזרת קישור גילוי אחד

התקינו את Claude Code והתחברו אליו לפי [המדריך הרשמי להתחלה מהירה](https://code.claude.com/docs/en/quickstart) של Anthropic. [מסמך העזר ל-CLI](https://code.claude.com/docs/en/cli-reference) מסביר איך עובדות תיקיות עבודה ואיך מעניקים גישה לקבצים נוספים.

הפעילו את `claude` מתוך התיקייה שמכילה את דף החשבון, או תנו לו גישה לתיקייה בדרך שבה תומכת ההתקנה שלכם. לאחר מכן הדביקו את ההנחיה הזו:

```text
התחבר ל-Expense Budget Tracker דרך קישור הגילוי הזה:
https://app.expense-budget-tracker.com/api/agent

אחזר אותו בבקשת GET, קרא את ה-JSON שיוחזר ופעל לפי כתובות הפעולה העדכניות.
אל תנחש את תהליך ה-API ואל תקבע אותו מראש. בקש ממני את כתובת האימייל שלי
ב-Expense Budget Tracker והתחל את תהליך ה-OTP באימייל.
לאחר שהבקשה תצליח, אם ההודעה אינה מופיעה אמור לי לבדוק את תיקיות הספאם או
דואר הזבל, בקש ממני את הקוד בן 8 הספרות ופעל לפי פעולת האימות שהוחזרה.

לאחר האימות, בקש ממני לאשר מקום אחסון קבוע ל-ApiKey שהוחזר, מחוץ לזיכרון השיחה
ומחוץ לבקרת הגרסאות. טען את פרטי החשבון שלי, הצג את מרחבי העבודה שלי, בקש ממני
לאשר את מרחב העבודה המיועד, שמור אותו כברירת המחדל למפתח הזה ובדוק את הסכימה
הפעילה. הרץ שאילתה קטנה אחת לקריאה בלבד כדי לאשר את מרחב העבודה שנבחר.
אל תכתוב נתונים פיננסיים.
```

[קישור הסוכן של האפליקציה](https://app.expense-budget-tracker.com/api/agent) מחזיר את מסמך הגילוי הפעיל. כרגע מופיעה בו `https://api.expense-budget-tracker.com/v1/` ככתובת הבסיס של ה-API, לצד כתובות ה-URL לפעולות האימות וה-SQL. הדביקו את הקישור בדומיין האפליקציה; Claude Code צריך לעקוב אחר כתובות ה-URL שהשירות מחזיר ולא להסתמך על רצף פנימי קבוע.

אותו תהליך באימייל משמש גם להרשמה וגם להתחברות. לאחר שתמסרו את הקוד בן 8 הספרות, Claude Code יקבל `ApiKey` ארוך טווח. אשרו מיקום אחסון מוגדר, למשל קובץ סודות שאינו נכלל בבקרת הגרסאות. לעולם אל תשמרו את המפתח ב-`CLAUDE.md` ואל תוסיפו אותו למאגר. [הגדרת סוכן AI](/docs/agent-setup/) מתעדת את תהליך האימות ואת בחירת מרחב העבודה שעליהם מבוסס החיבור.

## אל תערבבו בין Agent API ל-MCP

הביטוי ״מעקב הוצאות עם Claude״ יכול להתייחס לשני חיבורים שונים. המאמר הזה עוסק ב-Claude Code שפועל בטרמינל דרך Agent API. לעומת זאת, Claude ו-Claude Desktop יכולים להשתמש במחבר MCP מרוחק ומתארח.

| | Claude Code עם Agent API | Claude או Claude Desktop עם MCP |
|---|---|---|
| מתי מתאים | עבודה בטרמינל עם גישה לקבצים מקומיים ו-HTTP ישיר | שיחות בלקוח Claude שתומך ב-MCP |
| נקודת התחלה | `https://app.expense-budget-tracker.com/api/agent` | `https://mcp.expense-budget-tracker.com/mcp` |
| אימות | OTP באימייל ולאחריו `ApiKey` ארוך טווח | OAuth בדפדפן |
| ממשק נתונים | כתובות URL ממסמך הגילוי שמובילות לנקודות קצה לקריאה ולביצוע | הכלי `sql_query` והכלי האופציונלי `sql_execute` |
| גישה לדף החשבון | קבצים ותיקיות שזמינים להפעלה הנוכחית של Claude Code | המחבר המרוחק אינו מספק גישה לקבצים מקומיים |

אי אפשר להשתמש באותם פרטי גישה בשני החיבורים. אם אתם עובדים באפליקציית Claude בדפדפן או במחשב, פעלו לפי [המדריך למחבר MCP למעקב הוצאות עם Claude](/blog/claude-expense-tracker-mcp-connector/). השתמשו בתהליך ה-Agent API שמתואר בהמשך כשהמשימה מתחילה בקובץ ש-Claude Code יכול לגשת אליו.

יש עוד שני גבולות שחשוב לחדד:

- עיבוד הנתונים אצל ספק המודל נפרד מה-API ומהאחסון של Expense Budget Tracker. לפני שתשתפו נתונים מדף החשבון, עיינו ב[תיעוד השימוש בנתונים של Claude Code](https://code.claude.com/docs/en/data-usage) ובתנאים של הספק שמוגדר בהתקנה שלכם.
- ההתקנה המקומית באמצעות Docker Compose שב[מדריך לאירוח עצמי](/docs/self-hosting/) מפעילה את אפליקציית הווב, שירות האימות, מסד הנתונים ושירות הרקע לשערי מטבע. היא אינה מספקת את Agent API המנוהל שבו משתמש המאמר. פריסת AWS של המאגר היא תצורה נפרדת שכוללת את ממשק ה-API הציבורי שמיועד למכונות.

## הגדירו לייבוא גבולות ברורים

בייבוא הראשון, השתמשו בחשבון אחד, במטבע אחד ובתקופה סגורה אחת של דף החשבון. CSV הוא פורמט נוח כי קל לעבור על השורות שלו. בכל פורמט ייצוא אחר, בקשו תחילה מ-Claude Code לוודא שהוא יכול לקרוא את הקובץ בסביבה שלכם ולהציג את השורות שפענח. אל תניחו שיש תמיכה בפורמט רק לפי שם הקובץ.

מסרו ל-Claude Code את ששת הפרטים האלה:

1. הנתיב המקומי לדף החשבון.
2. חשבון הבנק והחשבון התואם לו במערכת המעקב.
3. מטבע החשבון.
4. התאריך הראשון והתאריך האחרון של העסקאות שנרשמו.
5. יתרת הפתיחה או היתרה התקינה האחרונה הידועה.
6. יתרת הסגירה בדף החשבון.

השאירו עסקאות ממתינות מחוץ לייבוא עד שהבנק ירשום אותן סופית. השאירו את קובץ המקור ללא שינוי ובקשו מ-Claude Code להכין תצוגה מקדימה נפרדת.

הנה קבוצת כללים מקומית שימושית לקובץ `CLAUDE.md` בתיקיית הכספים:

```markdown
# תהליך העבודה של Expense Budget Tracker

- התחל ב-https://app.expense-budget-tracker.com/api/agent ופעל לפי מסמך הגילוי.
- אשר את מרחב העבודה המיועד ובדוק את הסכימה הפעילה לפני כתיבת SQL.
- השתמש בפעולת הקריאה לכל בדיקה והתאמה.
- לפני כתיבה, הצג את סכומי המקור, כפילויות אפשריות, SQL מדויק ומספר השורות הצפוי.
- המתן לאישור מפורש שלי לקבוצת השינויים המלאה.
- השתמש בפעולת הכתיבה רק עבור INSERT, UPDATE או DELETE שאושרו.
- אמת כל כתיבה באמצעות קריאה חדשה.
- לעולם אל תמציא רשומת איזון ואל תפתור בשקט שיוך לא ודאי לקטגוריה.
- שמור את ה-ApiKey מחוץ לקובץ הזה ומחוץ לבקרת הגרסאות.
```

הוסיפו פרטים קבועים כמו שמות החשבונות האמיתיים שלכם, כללי הקטגוריות, האופן שבו אתם רושמים העברות ומטבע הדיווח. אל תעתיקו את הקטגוריות לדוגמה מהמאמר אלא אם הן מתאימות לספר החשבונות שלכם.

## ייבאו את דף החשבון רק לאחר תצוגה מקדימה מלאה

לאחר שהחיבור פועל, הדביקו את ההנחיה הבאה והחליפו את הערכים שבסוגריים המרובעים:

```text
ייבא את [הנתיב המקומי לדף החשבון] אל [החשבון במערכת] עבור [תאריך הרישום הראשון]
עד [תאריך הרישום האחרון], ב-[מטבע]. יתרת הפתיחה היא [סכום] ויתרת הסגירה של הבנק
היא [סכום].

תחילה אשר את מרחב העבודה שנבחר ובדוק את הסכימה הפעילה. השתמש רק בפעולת הקריאה
כדי לבדוק את חשבון היעד, את הקטגוריות הקיימות ואת שורות ספר החשבונות שחופפות
לתקופת דף החשבון. ודא שאתה יכול לקרוא את הקובץ המקומי, לפענח אותו ולהכין תצוגה
מקדימה מלאה בלי לכתוב דבר.

לכל שורת מקור, הצג את מזהה המקור או מספר השורה, תאריך הרישום, הסכום החיובי או השלילי,
המטבע, חשבון היעד, סוג העסקה המוצע, הקטגוריה המוצעת וסטטוס הכפילות. סמן העברות,
החזרים כספיים, החזרי הוצאות, עמלות, שורות במטבע זר, צדדים לא מוכרים לעסקה
וסיווגים לא ודאיים.

לאחר מכן הצג את מספר שורות המקור ואת הסכום הכולל שלהן, כולל הסימנים, את כל השורות
המוצעות לספר החשבונות, כפילויות אפשריות, את ה-SQL המדויק שתשלח ואת מספר השורות
שצפויות להיות מושפעות. עצור והמתן לאישור מפורש שלי לקבוצת השינויים המלאה.
```

העבודה מול מסד הנתונים נשארת לקריאה בלבד עד שתאשרו שינוי. Claude Code צריך לבדוק את הסכימה הפעילה במקום להעתיק שמות עמודות ממאמר, למצוא את החשבון המתאים ולבצע שאילתה על הרשומות הקיימות באותם תאריכים. תאריך וסכום זהים הופכים עסקה לכפילות אפשרית, לא לכפילות ודאית. שתי רכישות אמיתיות יכולות להיות זהות בשני השדות.

### דוגמה מלאה בת ארבע שורות

נניח שבחשבון עו״ש יתרת הפתיחה היא €1,250.00, ובדף החשבון מופיעות ארבע תנועות שנרשמו:

| שורה | תאריך רישום | תיאור | סכום (+/−) | סוג מוצע | קטגוריה מוצעת | הערה לבדיקה |
|---|---|---|---:|---|---|---|
| 1 | 2026-08-31 | משכורת | +€2,000.00 | הכנסה | משכורת | ברור |
| 2 | 2026-09-02 | סופרמרקט | −€54.20 | הוצאה | מצרכים | בדקו את בית העסק אם אינו מוכר |
| 3 | 2026-09-03 | העברה לחיסכון | −€300.00 | העברה | — | אשרו את החשבון השני |
| 4 | 2026-09-04 | בית קפה | −€8.40 | הוצאה | מסעדות ובתי קפה | ברור |

סכום ארבע התנועות, כולל הסימנים, הוא `+€1,637.40`. כשמוסיפים אותו ליתרת הפתיחה בסך `€1,250.00`, מתקבלת יתרת סגירה צפויה של `€2,887.40`. הדוגמה הזו נכנסת במסך אחד, אבל גם בייבוא ארוך יותר כל שורת מקור חייבת להופיע בתצוגה המקדימה וכל אי-ודאות חייבת להיות מסומנת.

בהעברה צריך לאשר את החשבון השני, כי העברת כסף בין חשבונות שלכם אינה הוצאה. גם החזרים כספיים והחזרי הוצאות צריכים להישמר לפי הסוג האמיתי שלהם. אם הסיווג אינו ודאי, השאירו אותו מסומן להכרעה במקום לבחור בקטגוריה שנראית הסבירה ביותר.

### אשרו קבוצת שינויים אחת ומדויקת

בדקו את מרחב העבודה, החשבון, טווח התאריכים, מספר השורות, הסכום הכולל כולל הסימנים, הכפילויות האפשריות והסיווגים. אשרו במפורש את התצוגה המקדימה ואת ה-SQL שהוצגו, במקום לתת הוראה כללית ״לייבא הכול״.

Agent API מפריד בין קריאה לכתיבה. Claude Code משתמש בפעולת הקריאה שהתגלתה עבור פקודת `SELECT` אחת או `WITH ... SELECT`, ואז משתמש בפעולת הכתיבה רק עבור `INSERT`, `UPDATE` או `DELETE` שאושרו במפורש. הסכימה הפעילה היא מקור האמת לגבי הטבלאות והעמודות; [מסמך העזר ל-API](/docs/api/) מסביר את חוזה ה-SQL ואת המגבלות שלו.

### לפני INSERT או UPDATE ארוכים, הריצו פעולת ניסיון

לפני `INSERT` או `UPDATE` ארוכים, הוראות הגילוי הפעילות מנחות את הסוכן לשלוח פעולת ניסיון מייצגת באותה תבנית SQL: 1–3 שורות עם ערכים מפורשים עבור `INSERT`, או שורת יעד אחת עבור `UPDATE`. האישור שלכם חל גם על פעולת הניסיון וגם על שאר השורות בקבוצת השינויים שבדקתם.

אם פעולת הניסיון מצליחה, Claude Code צריך להמשיך מיד באצוות עוקבות של עד 100 רשומות ולאמת כל אצווה תוך כדי. אחרי פעולת ניסיון של 3 שורות מתוך ייבוא מאושר בן 247 שורות, נשארות אצוות של 100, 100 ו-44 שורות. שינוי בהיקף, אי-ודאות חדשה או כשל בביצוע מחייבים אישור חדש. אצוות המשך שגרתיות בתוך הקבוצה שכבר אושרה אינן דורשות אישור נוסף.

ממשק ה-SQL המוגבל אינו תומך ב-`ON CONFLICT`, ולכן צריך לטפל בכפילויות במפורש. תוצאות קריאה מוגבלות ל-100 שורות. Claude Code צריך לבדוק במטא-נתונים של התגובה את מספר השורות ואת סטטוס הקיטוע, לחשב סכומים מצטברים ב-SQL ולחלק את האימות המפורט לשאילתות קריאה מצומצמות וממוינות. תגובה שנקטעה אינה בדיקת ייבוא מלאה.

### קראו מחדש את השורות שנשמרו

תגובת API מוצלחת מוכיחה שהבקשה בוצעה. היא אינה מוכיחה שכל ערך שנשמר תואם לתצוגה המקדימה. בצעו שאילתה נוספת על החשבון ועל התקופה שהכתיבה השפיעה עליהם, והשוו:

- מספר השורות שנוספו
- תאריכים, סכומים כולל הסימן ומטבעות
- שיוך לחשבון
- סוגי עסקאות וקטגוריות
- כפילויות אפשריות
- סכומי האצוות והסכום המלא של דף החשבון

אם משהו אינו תואם, חזרו לאבחון לקריאה בלבד. בדקו תיקון נקודתי אחד לפני שתבצעו כתיבה נוספת. [המדריך לייבוא דפי חשבון בנק](/blog/how-to-import-bank-statements-into-an-expense-tracker/) מרחיב על תקופות חופפות, החזרים והעברות.

## בדקו בנפרד את היתרה ואת הקטגוריות

התאמת יתרה בודקת אם התנועות שנשמרו מסבירות את יתרת הסגירה של הבנק באותו טווח תאריכי רישום.

בחשבון פיקדון רגיל:

**יתרת סגירה צפויה = יתרת פתיחה + תקבולים שנרשמו − תשלומים שנרשמו**

כשהתנועות נשמרות בערכים חיוביים ושליליים:

**יתרת סגירה צפויה = יתרת פתיחה + סכום התנועות הרשומות**

בחשבונות התחייבות כמו כרטיסי אשראי עשויה להיות מוסכמת סימנים אחרת. Claude Code צריך לציין את המוסכמה שמצא לפני שהוא מחשב את ההשוואה.

המשיכו עם ההנחיה הזו:

```text
השתמש רק בפעולת הקריאה. בצע התאמת יתרה עבור [החשבון] מ-[תאריך הרישום הראשון]
עד [תאריך הרישום האחרון] מול יתרת הסגירה של הבנק בסך [סכום ומטבע]. ציין את נקודת
הפתיחה, את מוסכמת הסימנים, את מספר השורות שנשמרו ואת הסכום הכולל של התנועות,
כולל הסימנים.

הצג את יתרת הסגירה הצפויה, את יתרת הסגירה של הבנק ואת ההפרש המדויק. אם ההפרש
אינו אפס, רשום שורות שעשויות להיות חסרות, כפולות, מוחרגות, בתאריך שגוי או בסימן
שגוי. אל תוסיף רשומת איזון ואל תשנה נתונים.

לאחר בדיקת היתרה, בדוק בנפרד את הסכומים לפי קטגוריה. רשום שורות ללא קטגוריה,
העברות שנספרו כהוצאה וקטגוריות שאינן תואמות לתצוגה המקדימה שאושרה.
```

בדוגמה בת ארבע השורות, `€1,250.00 + €1,637.40 = €2,887.40`. אם גם יתרת הסגירה של הבנק היא €2,887.40, הפרש היתרה הוא `€0.00`.

הפרש של אפס מאשר שחישוב היתרה נכון בטווח שנבחר. הוא אינו מאשר שהקטגוריות נכונות. שינוי הקטגוריה של שורת הסופרמרקט בסך €54.20 ממצרכים לנסיעות משאיר את הפרש היתרה על אפס, אבל מעביר €54.20 בין סכומי הקטגוריות. לכן בדיקת הקטגוריות היא בדיקת קבלה נפרדת.

כשההפרש אינו אפס, בדקו את יתרת הפתיחה, שורות חסרות או כפולות, העברות, עסקאות ממתינות, סימנים, תאריכים ומטבעות. לעולם אל תוסיפו עסקת איזון מלאכותית כדי להעלים את ההפרש. [המדריך להתאמה](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) מסביר את תהליך האבחון בפירוט רב יותר.

## עדכנו את התקציב רק אחרי ההתאמה

עברו לתקציב רק לאחר שווידאתם בקריאה חוזרת שהשורות נשמרו נכון, החשבון מותאם וסכומי הקטגוריות הגיוניים. כלי למעקב תקציב עם Claude Code יכול להשוות את הפעילות בפועל ל-`budget_lines` ולהכין הצעות לשינויים. חודש חריג אחד אינו מגדיר אוטומטית את התוכנית הבאה.

```text
אשר את מרחב העבודה ובדוק את הסכימה הנוכחית. השתמש בפעולת הקריאה כדי להשוות
את ההכנסות וההוצאות בפועל עבור [תקופה מלאה] לסעיפי התקציב התואמים. החרג העברות
לפי סוג העסקה שנשמר והצג בנפרד פעילות ללא קטגוריה.

לכל שינוי מוצע בתקציב, הצג את הקטגוריה, הסכום הנוכחי, הסכום בפועל, הסכום המוצע,
ההפרש והסיבה. לאחר מכן הצג את ה-SQL המדויק ואת מספר השורות שצפויות להיות מושפעות.
אל תכתוב עד שאאשר סעיפים מסוימים.

לאחר האישור, השתמש בפעולת הכתיבה רק עבור אותם סעיפים ואמת אותם באמצעות קריאה
חדשה. דווח על כל ערך שנשמר ואינו תואם להצעה שאושרה.
```

הוצאה גדולה עשויה להיות יוצאת דופן. חריגה לכאורה מהתקציב עשויה להתברר כהעברה או כהחזר שסווגו באופן שגוי. Claude Code יכול לחשב את ההפרשים ולהכין את ה-SQL; את הסכומים לחודש הבא אתם עדיין קובעים.

## שמרו על אותו סדר בכל דף חשבון

בכל דף חשבון, עבדו לפי אותו סדר:

1. התחילו ב-`https://app.expense-budget-tracker.com/api/agent` ופעלו לפי מסמך הגילוי.
2. טענו את פרטי החשבון, אשרו את מרחב העבודה ובדקו את הסכימה הפעילה.
3. מסרו ל-Claude Code קובץ נגיש אחד של דף החשבון וגבולות יתרה מפורשים.
4. קראו את נתוני ספר החשבונות שחופפים לתקופה והכינו תצוגה מקדימה מלאה לייבוא.
5. אשרו קבוצת שינויים אחת ומדויקת.
6. לפני `INSERT` ארוך, הריצו פעולת ניסיון של 1–3 שורות ואז אצוות עוקבות של עד 100 רשומות.
7. קראו מחדש כל אצווה שנשמרה והשוו אותה לתצוגה המקדימה.
8. התאימו את החשבון ליתרת הסגירה של הבנק בלי להוסיף רשומת איזון.
9. בדקו את סכומי הקטגוריות גם כשהפרש היתרה הוא אפס.
10. הכינו, אשרו ואמתו בנפרד כל שינוי בסעיפי התקציב.

התחילו בחשבון אחד ובתקופה סגורה אחת. אחרי שדף החשבון הותאם לספר החשבונות והתקציב נבדק, חזרו על התהליך בחשבון הבא. Claude Code ממשיך לטפל בעבודה החוזרת על קבצים ועל קריאות API, וכל החלטה פיננסית מוצגת לכם לפני שנעשה שינוי ברשומות.
