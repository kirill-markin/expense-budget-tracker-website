מעקב הוצאות שימושי עם Claude Code צריך להתחיל בקריאה, לא בכתיבה. עוד לפני שעסקת בנק אחת נכנסת לספר החשבונות, Claude Code יכול לזהות את מרחב העבודה, לבדוק את הסכימה הפעילה, לוודא את חשבון היעד ואת טווח התאריכים ולהראות לכם מה הוא מתכנן לשנות.

נקודת הבקרה הזו היא הסיבה להשתמש בסוכן מסוף למשימה. Claude Code יכול לטפל בקובץ ובתקשורת ה-HTTP, בעוד שההחלטות הפיננסיות נשארות בידיכם: איזה חשבון נכון, האם שורה מסוימת היא העברה, איזו קטגוריה מתאימה והאם בכלל לבצע את הכתיבה המוצעת.

כך מתקבל מעקב הוצאות מבוסס AI עם נקודת אישור ברורה, ולא צ'אטבוט כללי לענייני כספים.

Expense Budget Tracker תומך בתהליך העבודה הזה ישירות דרך Agent API. נקודת ההתחלה היא כתובת גילוי ציבורית אחת:

```text
https://api.expense-budget-tracker.com/v1/
```

משם Claude Code יכול להשלים את ההגדרה הראשונית באמצעות קוד חד-פעמי באימייל, לשמור את ה-`ApiKey` ארוך-הטווח שהוחזר מחוץ לזיכרון הצ'אט, לבדוק את הסכימה הזמינה ולהשתמש בנקודות קצה נפרדות לפעולות קריאה ולכתיבות שאושרו.

## איך התהליך הזה עובד — ולאן הנתונים עוברים

Claude Code פועל במסוף שלכם ויכול לעבוד עם קובץ דף חשבון שתאפשרו לו לגשת אליו במחשב. זה עדיין לא אומר שכל התהליך מתבצע במצב לא מקוון או במחשב המקומי בלבד.

[הדרישות העדכניות של Anthropic ל-Claude Code](https://docs.anthropic.com/en/docs/claude-code/getting-started) מציינות שנדרש חיבור לאינטרנט. האימות ועיבוד ה-AI מתבצעים באמצעות Anthropic או ספק המודל שהוגדר בהתקנת Claude Code שלכם. לכן, תוכן רלוונטי מדף החשבון, הנחיות ותוצאות API עשויים לעבור עיבוד מחוץ למחשב, בהתאם לתנאי אותו ספק.

שאר הנתיב נפרד:

| גבול | מה קורה בו |
|---|---|
| המחשב שלכם | דף החשבון שממנו מתחילים הוא קובץ מקומי. Claude Code מקבל רק את הרשאות הגישה לקבצים שתעניקו לו. |
| Claude Code וספק המודל שלו | Claude Code מפרש את הקובץ, מכין שאילתות ומסביר את התוצאות. נדרש חיבור לאינטרנט לצורך אימות ועיבוד AI. |
| Agent API ישיר | Claude Code שולח את פעולות הקריאה המאומתות ואת הכתיבות המאושרות שנדרשות למשימה. ה-API אינו יכול לעיין בקבצים שרירותיים במחשב שלכם. |
| האחסון של Expense Budget Tracker | רשומות פיננסיות שאושרו נשמרות במסד הנתונים המתארח, או בתשתית שבשליטתכם אם אתם מארחים את היישום בעצמכם. |

המסלול הזה שונה גם ממחבר ה-MCP המרוחק של Claude ושל Claude Desktop. ה-API הישיר משתמש ב-`ApiKey` ארוך-טווח, והוא המסלול שבו עוסק המדריך הזה. MCP משתמש ב-OAuth בדפדפן בכתובת אחרת; החיבור אליו לבדו אינו מקנה גישה לקבצים מקומיים.

אם הדרישה העיקרית שלכם היא להימנע מחיבור קבוע לבנק, המאמר [אפליקציית תקציב ללא חיבור לבנק](/blog/budget-app-without-bank-linking/) מסביר את גבולות הנתונים האלה ביתר פירוט.

## חיבור Claude Code דרך כתובת הגילוי

התקינו את Claude Code והשלימו את האימות באמצעות [מדריך ההתקנה הרשמי](https://docs.anthropic.com/en/docs/claude-code/getting-started) של Anthropic. [מסמך העזר ל-CLI](https://docs.anthropic.com/en/docs/claude-code/cli-usage) מסביר כיצד להשתמש בפקודות אינטראקטיביות ולא אינטראקטיביות.

לאחר שהפקודה `claude` פועלת במסוף, הפעילו אותה בספרייה שבה אתם שומרים את קובצי הכספים ותנו לה את ההנחיה הבאה:

```text
התחבר ל-Expense Budget Tracker באמצעות https://api.expense-budget-tracker.com/v1/.
פעל לפי תגובת הגילוי במקום להניח פרטים על נקודות הקצה. בקש ממני את כתובת
האימייל של החשבון ולאחר מכן את הקוד בן 8 הספרות מתיבת הדואר הנכנס. שמור את
ה-ApiKey שהוחזר מחוץ לזיכרון הצ'אט רק לאחר שאאשר את מיקום האחסון.

לאחר הכניסה, קרא ל-/me, הצג את מרחבי העבודה שלי, בקש ממני לאשר את מרחב העבודה
המיועד, שמור את מרחב העבודה עבור המפתח הזה ובדוק את /schema. אל תכתוב עדיין נתונים פיננסיים.
```

רצף ההצטרפות הנוכחי הוא:

1. שלחו `GET https://api.expense-budget-tracker.com/v1/` ופעלו לפי הפעולות בתגובת הגילוי.
2. ספקו את כתובת האימייל של החשבון כאשר Claude Code מבקש אותה.
3. ספקו את הקוד בן 8 הספרות מהאימייל. אימות מוצלח מחזיר `ApiKey` ארוך-טווח.
4. שמרו את המפתח מחוץ לזיכרון הצ'אט, רצוי כ-`EXPENSE_BUDGET_TRACKER_API_KEY` במיקום שאישרתם. אל תכניסו אותו למאגר קוד.
5. קראו ל-`/v1/me` ול-`/v1/workspaces` עם `Authorization: ApiKey <key>`.
6. בחרו את מרחב העבודה הרצוי באמצעות `POST /v1/workspaces/{workspaceId}/select`.
7. קראו ל-`/v1/schema` לפני יצירת SQL.

מרחב העבודה שנבחר נשמר עבור המפתח הזה. בקשות SQL עתידיות יכולות להשמיט את `X-Workspace-Id`, אף ש-Claude Code עדיין יכול לשלוח את הכותרת אם תרצו לעקוף את מרחב העבודה השמור עבור בקשה אחת. אם בחשבון יש בדיוק מרחב עבודה אחד ועדיין לא נשמרה בחירה למפתח, ה-API יכול לשמור אותו ולהשתמש בו אוטומטית. למרות זאת, כדאי לציין במפורש את מרחב העבודה בכל בדיקה שלפני כתיבה.

תהליך האימות המפורט והנחיות האחסון נמצאים במדריך [הגדרת סוכן AI](/docs/agent-setup/).

## הגדירו ל-Claude Code כלל בדיקה לפני הייבוא הראשון

קובץ `CLAUDE.md` מקומי יכול לשמור את כללי העבודה עבור ספריית הכספים הזו, בלי לשמור את המפתח עצמו. כתבו הנחיות קצרות ומדויקות:

```markdown
# תהליך העבודה עם Expense Budget Tracker

- התחל מ-https://api.expense-budget-tracker.com/v1/ ובדוק את /schema.
- השתמש ב-POST /v1/sql/query לכל קריאה.
- לפני כתיבה, הצג את מרחב העבודה המיועד, את ה-SQL המדויק, את מספר השורות שצפויות
  להיות מושפעות, את הסכומים במקור וכפילויות אפשריות. המתן לאישור מפורש ממני.
- השתמש ב-POST /v1/sql/execute רק עבור פקודת INSERT, UPDATE או DELETE המדויקת שאושרה.
- אמת כל כתיבה באמצעות בקשת /v1/sql/query חדשה.
- לעולם אל תמציא עסקת איזון ואל תשנה בשקט קטגוריה שאינה ודאית.
- שמור את ה-ApiKey מחוץ לקובץ הזה ומחוץ לזיכרון הצ'אט.
```

הוסיפו את שמות החשבונות האמיתיים, מוסכמות הקטגוריות, כללי ההעברות ומטבע הדיווח שלכם, אם הם קבועים. אל תעתיקו קטגוריות לדוגמה אל המערכת רק מפני שמאמר השתמש בהן. Claude Code צריך להריץ שאילתות על הנתונים הקיימים שלכם ולהשתמש בסכימה הפעילה.

## ייבוא של דף חשבון בנק אחד בעזרת Claude Code

הדרך הבטוחה ביותר להתחיל היא בייבוא קטן במכוון: חשבון אחד, מטבע אחד, תקופה סגורה אחת בדף החשבון וקובץ שאפשר לבדוק את שורותיו. CSV הוא נקודת התחלה טובה מפני שהמבנה שלו גלוי. בפורמטים אחרים צריך לבדוק בנפרד כיצד הנתונים חולצו מהקובץ לפני שאפשר לתת אמון בשורות שהתקבלו.

### 1. קבעו את גבולות נתוני המקור

לפני ש-Claude Code מנתח דבר כלשהו, זהו:

- את חשבון הבנק ואת החשבון התואם לו במערכת
- את מטבע החשבון
- את התאריך הראשון והאחרון שבהם נרשמו עסקאות בדף החשבון
- את יתרת הפתיחה או את היתרה התקינה האחרונה הידועה
- את יתרת הסגירה של דף החשבון
- האם הקובץ כולל עסקאות ממתינות

השתמשו בעסקאות שנרשמו בפועל לצורך הייבוא וההתאמה. השאירו עסקאות ממתינות מחוץ לאצווה המאושרת עד שיירשמו בפועל.

### 2. בדקו את היעד לפני ניסוח השורות

בקשו מ-Claude Code להשתמש תחילה בנקודת הקצה לקריאה:

```text
אני רוצה לייבא את ~/finances/checking-2026-07.csv.

השתמש רק ב-/v1/sql/query. אמת את מרחב העבודה שנבחר, בדוק את /v1/schema, הצג את
החשבונות הזמינים וזהה את החשבון היחיד שתואם לדף החשבון הזה. הרץ שאילתה על טווח התאריכים
של דף החשבון ב-ledger_entries וחפש חפיפה. הצג לי את החשבון, המטבע, גבולות התאריכים,
מספר השורות הקיימות וכל כפילות אפשרית. אל תכתוב.
```

נקודת הקצה הראשית לקריאה היא:

```text
POST https://api.expense-budget-tracker.com/v1/sql/query
```

היא מקבלת פקודת `SELECT` אחת לקריאה בלבד, או `WITH ... SELECT`. גוף הבקשה משתמש ב-SQL עדכני שנוצר מתוך `/schema`:

```json
{
  "sql": "SELECT * FROM accounts LIMIT 100"
}
```

Claude Code צריך לחשב סכומים ותוצאות מקובצות ב-SQL, במקום למשוך את ספר החשבונות כולו לתוך השיחה. תוצאות השאילתה מוגבלות ל-100 שורות.

### 3. בדקו תצוגה מקדימה — לא רק הבטחה

בקשו מ-Claude Code לנתח את דף החשבון ולהכין טבלת תצוגה מקדימה לפני שהוא יוצר פקודת `INSERT`. לכל הפחות, התצוגה המקדימה צריכה לכלול את שורת המקור, התאריך, הסכום, המטבע, חשבון היעד, סוג העסקה המוצע, הקטגוריה המוצעת והאם מדובר בכפילות.

בדקו היטב את השורות הבאות:

- העברות בין החשבונות שלכם
- החזרים כספיים והחזרים על הוצאות
- משיכות מזומן ועמלות בנק
- צדדים נגדיים שאינם מוכרים
- עסקאות במטבע זר
- שורות הסמוכות לתחילת תקופת דף החשבון ולסופה
- כל שורה שעשויה להתאים לרשומה קיימת בספר החשבונות

תאריך וסכום תואמים עשויים להצביע על כפילות, אך אינם הוכחה. לשתי עסקאות אמיתיות יכולים להיות אותו תאריך ואותו סכום. אם המקור כולל מזהה קבוע של הבנק, השתמשו בו כראיה כאשר בסכימה הפעילה יש שדה מתאים; אחרת, השאירו אותו בתצוגה המקדימה במקום לאלץ אותו להיכנס למסד הנתונים.

לאחר מכן בקשו סיכום אישור תמציתי:

```text
הכן את התצוגה המקדימה של הייבוא בלי לכתוב. הצג:

1. את מרחב העבודה והחשבון שאומתו
2. את טווח התאריכים והמטבע של המקור
3. את מספר השורות במקור ואת הסכום הכולל שלהן, כולל סימן
4. כל רשומה שמוצעת לספר החשבונות
5. כפילויות אפשריות וסיווגים שאינם ודאיים
6. את פקודת ה-INSERT המדויקת או את הפקודות המדויקות שתשלח
7. את מספר השורות שצפויות להיות מושפעות

עצור והמתן לאישור שלי.
```

### 4. שלחו רק את קבוצת השינויים שאושרה

נקודת הקצה הראשית לכתיבה היא:

```text
POST https://api.expense-budget-tracker.com/v1/sql/execute
```

היא מקבלת פקודת `INSERT`, `UPDATE` או `DELETE` אחת שאושרה, כולל צורות `WITH` נתמכות. היא מופרדת בכוונה מנקודת הקצה לקריאה.

כל פעולת שינוי מוגבלת ל-100 שורות מושפעות. בייבוא ארוך, אשרו את כל קבוצת השינויים המוצעת לפני הביצוע. Claude Code צריך לשלוח תחילה אצוות ניסיון של 1–3 שורות מייצגות באותו מבנה SQL. אם היא מצליחה, עליו להמשיך מיד עם יתר השורות שאושרו, באצוות עוקבות של עד 100 שורות. עליו לעקוב אחר כל אצווה ולאמת אותה, אך לא לעצור רק כדי לבקש מכם להמשיך או לאשר מחדש. שינוי בהיקף, עמימות חדשה או כשל בביצוע יוצרים נקודת בקרה חדשה.

ממשק ה-SQL אינו תומך ב-`ON CONFLICT`, ולכן הטיפול בכפילויות חייב להיות מפורש ולא מוסתר מאחורי `upsert`.

`POST /v1/sql` עדיין קיים לצורכי תאימות ולסקריפטים אטומיים מוגבלים הכוללים כמה פקודות. זו אינה נקודת הקצה הרגילה לשאילתות על דפי חשבון או לכתיבות שגרתיות.

### 5. קראו מחדש את השורות שנכתבו

תגובת הצלחה מה-API אינה סוף הייבוא. בקשו מ-Claude Code להריץ שוב שאילתה על החשבון והתקופה הרלוונטיים דרך `/v1/sql/query`, ולהשוות את הרשומות שנשמרו לתצוגה המקדימה שאושרה:

- מספר השורות שהושפעו
- תאריכים וסכומים
- המטבע המקורי
- שיוך החשבון
- סוגי עסקאות וקטגוריות
- מספר הכפילויות

אל תבקשו מ-Claude Code "לתקן כל דבר שנראה שגוי". אם באימות נמצא הבדל, חזרו לאבחון לקריאה בלבד, הכינו תיקון נקודתי אחד ואשרו אותו בנפרד.

[המדריך המקיף לייבוא דפי חשבון בנק](/blog/how-to-import-bank-statements-into-an-expense-tracker/) עוסק בהעברות, החזרים, תקופות חופפות ובשורות אחרות שעלולות לגרום לייבוא להיראות תקין אף שאינו כזה.

## בצעו התאמה לחשבון אחד לפני ייבוא חשבון נוסף

התאמה מוכיחה שהתנועות בספר החשבונות מסבירות את דף חשבון הבנק. השוו חשבון בנק אחד לחשבון התואם לו במערכת, באותו מטבע ובאותו טווח תאריכים של עסקאות שנרשמו בפועל.

עבור חשבון פיקדון רגיל, הבדיקה הבסיסית היא:

**יתרת סגירה צפויה = יתרת פתיחה + תקבולים שנרשמו − תשלומים שנרשמו**

אם המערכת משתמשת בתנועות עם סימן, הנוסחה המקבילה היא:

**יתרת סגירה צפויה = יתרת פתיחה + סכום התנועות שנרשמו עם סימן**

חשבונות התחייבות, כגון כרטיסי אשראי, עשויים להשתמש במוסכמות סימנים אחרות. ודאו ש-Claude Code מציין את המוסכמה שמצא לפני השוואת המספרים.

השתמשו בהנחיה שמשאירה את האבחון במצב קריאה בלבד:

```text
השתמש רק ב-/v1/sql/query. התאם את חשבון העו"ש לאחר הייבוא מול יתרת הסגירה של דף
החשבון בסך [סכום ומטבע]. ציין את נקודת הפתיחה ואת מוסכמת הסימנים. אם היתרות שונות,
הצג את ההפרש המדויק ורשום אילו שורות עשויות להיות חסרות, כפולות או בעלות סימן שגוי.
אל תוסיף עסקת איזון ואל תשנה נתונים קיימים.
```

אם ההפרש אינו אפס, בדקו את יתרת הפתיחה, עסקאות חסרות או כפולות, העברות, פריטים ממתינים, סימנים, תאריכים ומטבעות. עסקת איזון מלאכותית תגרום ליתרה המוצגת להתאים, אך תסתיר את הסיבה.

הפרש אפס מוכיח שהתנועות בחשבון מסתכמות נכון. הוא אינו מוכיח שהקטגוריות נכונות. בדקו את סכומי הקטגוריות בנפרד לפני המעבר לחשבון הבא. [המדריך להתאמת תקציב ליתרת הבנק](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) מעמיק בהבחנה הזו.

## ניתוח הוצאות דרך נקודת הקצה לקריאה

לאחר אימות הייבוא, Claude Code יכול להשתמש ב-`ledger_entries` לניתוח הוצאות לקריאה בלבד. הגדירו את השאלה במדויק ובקשו את ה-SQL, כדי שתוכלו לבדוק את ההגדרה שעליה מבוססת התשובה.

```text
בדוק את /v1/schema, ולאחר מכן השתמש ב-/v1/sql/query כדי להשוות הוצאות לפי קטגוריה
בשלושת החודשים הקלנדריים המלאים האחרונים. קבע תאריכי התחלה וסיום מפורשים לפני
כתיבת ה-SQL. החרג העברות לפי סוג העסקה השמור. בצע צבירה ב-SQL, הצג את השאילתה
והסבר אילו שורות הוחרגו או אינן ודאיות. אל תשנה נתונים.
```

זה חשוב מפני שהמונח "הוצאות" אינו עמודה אחידה בכל מערכת. תשובה שימושית תלויה בסכימה העדכנית, בסוגי העסקאות, במטבע החשבון, בהחזרים ובגבולות התאריכים המדויקים. Claude Code יכול לכתוב את השאילתה, אך עדיין צריך להיות ברור לכם מה נכלל בחישוב.

לבדיקה חד-פעמית, שאלו שאלות ממוקדות כגון:

- אילו קטגוריות השתנו הכי הרבה בין שני חודשים מלאים?
- אילו צדדים לעסקה מרכיבים את הסכום הכולל בקטגוריה מסוימת?
- האם יש כפילויות אפשריות בתקופה האחרונה שיובאה?
- לאילו קטגוריות בפועל אין סעיף תקציב תואם?

מגבלת 100 השורות בתוצאות מספיקה בדרך כלל כאשר Claude Code מקבץ ומסנן ברמת מסד הנתונים.

## עדכון תקציב בעזרת Claude Code בלי למסור לו את ההחלטה

שינויים בתקציב משתמשים באותו תהליך בדיקה כמו ייבוא דפי חשבון. Claude Code יכול לקרוא את `budget_lines`, להשוות את התוכנית לפעילות בפועל בספר החשבונות ולהכין פקודת `INSERT`, `UPDATE` או `DELETE` מוצעת. אתם מחליטים אם הסכומים החדשים משקפים את התוכניות שלכם.

```text
השתמש ב-/v1/sql/query כדי להשוות את ההכנסות וההוצאות בפועל החודש ל-budget_lines.
לאחר מכן הכן טיוטת תקציב לחודש הבא באמצעות הקטגוריות הקיימות והסכימה הנוכחית.

הצג את הסכום הנוכחי, הסכום המוצע, ההפרש והסיבה לכל שורה שהשתנתה. הצג את ה-SQL
המדויק ואת מספר השורות שצפויות להיות מושפעות. אל תקרא ל-/v1/sql/execute עד שאאשר
שורות מסוימות. לאחר כתיבה שאושרה, הרץ עליהן שאילתה נוספת כדי לאמת אותן.
```

אל תאפשרו לחודש עם הוצאות גבוהות להפוך בשקט לתוכנית החדשה. הוצאה גדולה עשויה להיות חריגה; קטגוריה חסרה עשויה להעיד על בעיית נתונים; העברה אולי סווגה באופן שגוי. Claude Code יכול להציג את ההבדלים, אבל גם תקציב עם Claude Code עדיין דורש את שיקול דעתכם לגבי מה נכון לעשות בהמשך.

## הכירו את הגבולות העדכניים של Agent API

ה-API חושף קבוצה קטנה של יחסים. התייחסו תמיד ל-`/v1/schema` כמקור האמת העדכני, אך החלוקה הנוכחית בין קריאה לכתיבה היא:

| יחס | גישה |
|---|---|
| `ledger_entries` | קריאה וכתיבה מאושרת |
| `budget_lines` | קריאה וכתיבה מאושרת |
| `workspace_settings` | קריאה וכתיבה מאושרת |
| `account_metadata` | קריאה וכתיבה מאושרת |
| `accounts` | קריאה בלבד |
| `fx_rates_raw` | קריאה בלבד |
| `fx_rates_daily` | קריאה בלבד |

המגבלות הנוכחיות של Agent API הן:

- 100 שורות מוחזרות לכל שאילתה
- 100 שורות מושפעות לכל פקודת שינוי ולכל בקשה
- זמן כולל מרבי של 25 שניות לבקשת SQL
- 10 בקשות בשנייה ו-10,000 בקשות ביום לכל מפתח

מדיניות ה-SQL חוסמת DDL כגון `CREATE`, `DROP` ו-`ALTER`, מעטפות טרנזקציה, הערות SQL, מזהים מצוטטים, מחרוזות `dollar-quoted`, את `set_config()` ופונקציות שאינן מורשות. הפונקציות המותרות כעת הן `SUM`, `COUNT`, `MIN`, `MAX`, `AVG` ו-`COALESCE`. לחיפוש טקסט שאינו רגיש לאותיות גדולות וקטנות, השתמשו ב-`ILIKE` במקום `LOWER(...)`, והשתמשו בטווחי תאריכים מפורשים במקום `NOW()` או `DATE_TRUNC()`. נקודות הקצה הראשיות מקבלות פקודה אחת לכל בקשה. אין תמיכה ב-`ON CONFLICT`.

הבקרות האלה מצמצמות את ממשק ה-SQL, אך אינן מחליטות אם קטגוריה נכונה או אם שורה בדף החשבון היא באמת העברה. אבטחה ברמת השורה (Row Level Security) מבודדת מרחבי עבודה ברמת מסד הנתונים. מפתחות `ApiKey` נשמרים כגיבובי SHA-256 וניתנים לביטול מתוך המוצר. עדיין עליכם להגן על המפתח בצורתו הגלויה במחשב ולבדוק כל שינוי פיננסי.

ראו [מסמך העזר ל-API](/docs/api/) למפרט העדכני של נקודות הקצה ומגבלותיהן.

## Claude Code עם Agent API ו-Claude עם MCP הם מסלולים נפרדים

חיפושים אחר מעקב הוצאות ל-Claude מערבבים לעיתים קרובות בין שימוש במסוף לבין מחברים עבור Claude או Claude Desktop. Expense Budget Tracker תומך בשניהם, אך ההגדרות ופרטי ההזדהות אינם ניתנים להחלפה.

| | Claude Code עם Agent API | Claude או Claude Desktop עם MCP |
|---|---|---|
| ההתאמה הטובה ביותר | קבצים מקומיים, תהליכי עבודה במסוף, סקריפטים ו-HTTP ישיר | שיחות בלקוח Claude שתומך ב-MCP |
| התחילו כאן | `https://api.expense-budget-tracker.com/v1/` | `https://mcp.expense-budget-tracker.com/mcp` |
| אימות | קוד חד-פעמי באימייל ולאחריו `ApiKey` ארוך-טווח | OAuth בדפדפן |
| ממשק קריאה/כתיבה | `/v1/sql/query` ו-`/v1/sql/execute` | הכלי `sql_query` והכלי האופציונלי `sql_execute` |
| גישה לקבצים מקומיים | תלויה בקבצים ובהרשאות שזמינים ל-Claude Code | המחבר המרוחק עצמו אינו מספק אותה |

השתמשו ב[תיעוד מחבר MCP](/docs/mcp-connector/) או ב[מדריך המלא למעקב הוצאות ל-Claude דרך MCP](/blog/claude-expense-tracker-mcp-connector/) כאשר המטרה היא לחבר את Claude או Claude Desktop. המשיכו להשתמש בתהליך העבודה הזה עם Agent API כאשר המשימה מתחילה בדף חשבון מקומי ובמסוף.

## הנחיה לשימוש חוזר עבור תהליך העבודה כולו

ההנחיה הזו שומרת את הגילוי, התצוגה המקדימה, האישור והאימות ברצף אחד:

```text
התחבר ל-Expense Budget Tracker דרך https://api.expense-budget-tracker.com/v1/
ופעל לפי תגובת הגילוי. השתמש ב-ApiKey ששמור מחוץ לזיכרון הצ'אט. קרא ל-/me,
הצג את מרחבי העבודה, אשר איתי את מרחב העבודה המיועד, בחר בו ובדוק את /schema.

אני רוצה לייבא את [נתיב ה-CSV המקומי] אל [חשבון] עבור [טווח תאריכים סגור] ב-[מטבע].
השתמש תחילה ב-/v1/sql/query כדי לבדוק את החשבון, הקטגוריות הקיימות ורשומות חופפות
ב-ledger_entries. נתח את הקובץ והכן תצוגה מקדימה מלאה. סמן כפילויות אפשריות,
העברות, החזרים כספיים, החזרים על הוצאות, עמלות, צדדים חריגים לעסקה וקטגוריות לא ודאיות.

הצג את הסכומים במקור, השורות המוצעות, ה-SQL המדויק ומספר השורות שצפויות להיות מושפעות.
אל תכתוב עד שאאשר את קבוצת השינויים המלאה. השתמש ב-/v1/sql/execute רק לכתיבה
שאושרה. עבור ייבוא ארוך, שלח תחילה אצוות ניסיון של 1–3 שורות מייצגות. אם היא מצליחה,
המשך מיד עם יתר השורות שאושרו באצוות עוקבות של עד 100. אמת כל אצווה באמצעות
/v1/sql/query, אך אל תבקש ממני לאשר מחדש אלא אם ההיקף משתנה, מופיעה עמימות חדשה
או שהביצוע נכשל.

לבסוף, התאם את החשבון היחיד הזה ליתרת הסגירה של דף החשבון. אם היתרה אינה תואמת,
הסבר את ההפרש בלי ליצור עסקת איזון או לשנות נתונים.
```

התחילו בחשבון אחד ובתקופה סגורה אחת. אם התצוגה המקדימה מובנת, השורות שאושרו מופיעות כראוי בקריאה החוזרת ויתרת הסגירה תואמת, יש לכם תהליך ניהול כספים אישי עם Claude שאפשר לבדוק — ולא צ'אטבוט עם הרשאה עמומה לשנות את ספרי החשבונות שלכם.
