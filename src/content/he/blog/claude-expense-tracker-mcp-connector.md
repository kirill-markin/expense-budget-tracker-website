השיחה הראשונה והבטוחה ביותר בין Claude למערכת שלכם למעקב אחר הוצאות כמעט משעממת: Claude מציג את סביבות העבודה, בודק את הסכמה העדכנית ומריץ שאילתה אחת לקריאה בלבד. שום דבר בספר החשבונות לא משתנה.

דווקא ההתחלה השקטה הזאת חשובה, כי בהמשך אותו מחבר עשוי לקבל הרשאה לשנות נתונים פיננסיים. לכן כדאי להפריד בין הרשאות קריאה לכתיבה, לבחור במפורש את סביבת העבודה ולבדוק כל שינוי מיד אחרי שבוצע.

ל-Expense Budget Tracker יש מחבר MCP מרוחק ומתארח שנועד בדיוק לתהליך הזה:

```text
https://mcp.expense-budget-tracker.com/mcp
```

הוסיפו את הכתובת ל-Claude, השלימו את תהליך ה-OAuth בדפדפן, ו-Claude יוכל לעבוד עם מערכת המעקב באמצעות ארבעה כלים מוגדרים היטב. אין צורך בטרמינל, במפתח API או בקובץ תצורה מקומי של MCP.

![אמנית הדפס משווה הדפסת ייחוס מוגנת להגהה חדשה שנוצרה מלוח נחושת יחיד שנבחר](/blog/claude-expense-tracker-mcp-connector.png)

## זהו מסלול המחבר, לא מסלול ה-API של Claude Code

Expense Budget Tracker תומך בשתי דרכים לגישה ממוכנת, וקל להתבלבל בין פרטי האימות שלהן.

| | מחבר MCP מרוחק | Agent API ישיר |
|---|---|---|
| מתאים במיוחד ל- | שיחות ב-Claude וב-Claude Desktop | Claude Code, ‏Codex, סקריפטים וסוכני טרמינל אחרים |
| כתובת התחלה | `https://mcp.expense-budget-tracker.com/mcp` | `https://api.expense-budget-tracker.com/v1/` |
| אימות | OAuth בדפדפן | `ApiKey` ארוך-טווח |
| ממשק | כלי MCP | נקודות קצה של HTTP |
| פרטי אימות | אסימוני גישה ורענון של OAuth שנשמרים בלקוח ה-MCP | `ApiKey` שנשמר מחוץ לזיכרון הצ'אט |

נקודת הקצה של MCP אינה מקבלת את ה-`ApiKey` שמשמש את ה-API הישיר, וה-API אינו הופך את המפתח הזה למחבר מותאם אישית ב-Claude. אלה שתי אינטגרציות נפרדות, ולכל אחת תהליך אימות משלה.

המדריך הזה מיועד למי שרוצה לחבר את Claude למערכת למעקב אחר הוצאות דרך אפליקציית האינטרנט או שולחן העבודה של Claude. אם המשימה שלכם מתחילה ב"קרא את קובץ ה-CSV הזה מהמחשב הנייד שלי", השתמשו במקום זאת בתהליך העבודה מהטרמינל שבמדריך [איך לעקוב אחר הוצאות ולנהל תקציב עם Claude Code](/blog/how-to-track-expenses-and-manage-your-budget-with-claude-code/). [המדריך המלא להגדרת מעקב הוצאות עם בינה מלאכותית](/blog/ai-agent-expense-tracker-claude-code-codex-openclaw/) מכסה את Claude Code, את Codex ואת OpenClaw דרך ה-API הישיר.

## הוסיפו את המחבר של Expense Budget Tracker ל-Claude

בחשבונות אישיים, הנתיב הנוכחי ב-Claude הוא **Customize > Connectors > Add custom connector**. ‏Anthropic מפרסמת את פרטי הממשק וסוגי החשבונות העדכניים ב[מדריך למחברים מותאמים אישית באמצעות MCP מרוחק](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### 1. הוסיפו את כתובת ה-MCP המרוחק

פתחו את Claude או את Claude Desktop, ואז:

1. עברו אל **Customize > Connectors**.
2. לחצו על הכפתור **+** ובחרו **Add custom connector**.
3. תנו למחבר את השם `Expense Budget Tracker`.
4. הזינו את `https://mcp.expense-budget-tracker.com/mcp` ככתובת שרת ה-MCP המרוחק.
5. לחצו על **Add**.

אין צורך להזין OAuth Client ID או Client Secret בהגדרות המתקדמות. שרת ההרשאה של Expense Budget Tracker תומך ברישום דינמי של לקוח OAuth ציבורי, ולכן לא נעשה שימוש בסוד לקוח.

בחשבונות Team ו-Enterprise, ‏Owner או Primary Owner צריכים תחילה להוסיף את המחבר המותאם אישית לארגון. לאחר מכן כל חבר מתחבר באמצעות החשבון שלו ויכול לגשת רק לסביבות העבודה שזמינות למשתמש המחובר.

### 2. התחברו ואשרו את הרשאות ה-OAuth

לחצו על **Connect** לצד המחבר החדש. Claude עוקב אחר תהליך גילוי ההרשאות של MCP ופותח בדפדפן את מסך האימות של Expense Budget Tracker. התחברו ובדקו אילו הרשאות התבקשתם לאשר.

לשני היקפי ההרשאה יש תפקידים שונים:

- `expenses:read` הוא חובה. הוא מאפשר לגלות סביבות עבודה, לבדוק את הסכמה ולהריץ שאילתות לקריאה בלבד.
- `expenses:write` הוא אופציונלי. הוא מאפשר להשתמש ב-`sql_execute`, כלי שיכול לשנות נתונים.

לסקירת הוצאות, דוחות, התאמה חשבונאית וניתוח תקציב, העניקו רק `expenses:read`. הוסיפו `expenses:write` רק כש-Claude צריך להוסיף, לעדכן או למחוק נתונים מסוימים. אין סיבה להעניק אותו "ליתר ביטחון".

אל תדביקו אסימון OAuth בתוך הנחיה. הדפדפן ומנגנון אחסון פרטי האימות של המחברים ב-Claude מטפלים באסימוני הגישה והרענון.

### 3. הפעילו את המחבר בשיחה

הוספת המחבר אינה מחייבת את Claude להשתמש בו בכל צ'אט. בתוך שיחה, פתחו את התפריט **+**, בחרו **Connectors** והפעילו את Expense Budget Tracker בצ'אט הזה.

המתג הנפרד לכל שיחה שימושי במיוחד כשעובדים עם נתונים פיננסיים. השאירו את המחבר כבוי בשיחות שאינן זקוקות לו, והפעילו אותו רק לשיחה ממוקדת על התקציב.

## מה Claude עושה במהלך תהליך ה-OAuth

אין צורך לבצע את השלבים הבאים ידנית, אבל היכרות עם מבנה התהליך מקלה על פתרון תקלות.

המחבר המתארח מפרסם מטא-נתונים של משאב מוגן ב-`https://mcp.expense-budget-tracker.com/.well-known/oauth-protected-resource/mcp`. המסמך מפנה את Claude למטא-נתונים של שרת ההרשאה ב-`https://auth.expense-budget-tracker.com/.well-known/oauth-authorization-server`.

Claude נרשם כלקוח OAuth ציבורי, פותח בדפדפן תהליך Authorization Code ומשתמש ב-PKCE עם שיטת האתגר `S256`. אחרי האישור הוא מחליף את הקוד באסימונים ומרענן את הגישה לפי הצורך. התהליך תואם את [מודל ההרשאה של MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization), לרבות גילוי המשאב המוגן והגנת PKCE על קודי ההרשאה.

פרט אחד עשוי להפתיע משתמשים ב-Claude Desktop: תעבורת המחבר המרוחק אינה יוצאת מממשק הרשת המקומי של אפליקציית שולחן העבודה. [לפי Anthropic, חיבורים למחברי MCP מרוחקים ומותאמים אישית יוצאים מתשתית הענן שלה](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), גם כשמשתמשים ב-Claude Desktop. המחבר המתארח כבר נגיש דרך האינטרנט. כדי ש-Claude יגיע לשרת MCP פרטי באירוח עצמי, השרת יצטרך לקבל חיבורים מהתשתית של Anthropic.

## ארבעת הכלים שזמינים ל-Claude

במקום לתת ל-Claude חיבור בלתי מוגבל למסד הנתונים, המחבר חושף רצף מצומצם של פעולות.

| כלי | מה הוא עושה | הרשאה |
|---|---|---|
| `list_workspaces` | מציג את סביבות העבודה שזמינות למשתמש המחובר | `expenses:read` |
| `get_schema` | מחזיר את היחסים והעמודות שנחשפים עבור סביבת העבודה שנבחרה | `expenses:read` |
| `sql_query` | מריץ שאילתת SQL מוגבלת אחת לקריאה בלבד | `expenses:read` |
| `sql_execute` | מריץ פקודת SQL מוגבלת שמשנה נתונים | `expenses:read` ו-`expenses:write` |

`sql_query` מוגן באמצעות גבול קריאה בלבד במסד הנתונים. כל תוצאה מוגבלת ל-100 שורות, ולביצוע מוקצות לכל היותר 20 שניות. המחבר בכללותו אינו מוגבל לקריאה בלבד כאשר `sql_execute` זמין, ולכן חשוב להתייחס בנפרד להיקף הרשאת הכתיבה האופציונלי.

בודקים את הסכמה העדכנית לפני שכותבים SQL. שמות הטבלאות, העמודות והיחסים המותרים צריכים להגיע מ-`get_schema`, ולא מהנחיה ישנה, מדוגמה שהועתקה או מהזיכרון של Claude מאפליקציה פיננסית אחרת.

## התחילו את השיחה הראשונה בסדר בטוח

ההנחיה הראשונה צריכה לגרום ל-Claude לבסס את ההקשר לפני שהוא מנתח נתונים:

```text
השתמש במחבר של Expense Budget Tracker במצב קריאה בלבד.

תחילה קרא ל-list_workspaces והצג לי את השמות והמזהים של סביבות העבודה הזמינות.
בקש ממני לאשר באיזו סביבת עבודה להשתמש, גם אם יש רק אחת. לאחר מכן קרא
ל-get_schema עבור סביבת העבודה שאישרתי. השתמש רק ב-sql_query. אל תקרא ל-sql_execute
ואל תציע עדיין שום שינוי.

אחרי שתקבל את הסכמה, סכם את ההוצאות שלי לפי קטגוריה עבור החודש הקלנדרי הנוכחי
והשווה אותן לחודש הקלנדרי הקודם. השתמש בשאילתות צבירה במקום להחזיר כל שורה
מתוך ספר החשבונות. הצג את השאילתה והסבר כל מגבלה שמשפיעה על התוצאה.
```

לסדר הזה יש חשיבות: בוחרים סביבת עבודה, בודקים את הסכמה העדכנית שלה ורק אז כותבים את השאילתה. אם שאילתה אחת עלולה להחזיר יותר מ-100 רשומות, בקשו מ-Claude לצבור את הנתונים ב-SQL או לחלק את השאלה לתקופות הגיוניות. המטרה אינה לדחוס ספר חשבונות שלם לתוך הצ'אט, אלא לחשב את התשובה בגבול מסד הנתונים ולהחזיר רק את התוצאה השימושית.

## הנחיות שימושיות לשיחה הראשונה במצב קריאה בלבד

אחרי ש-Claude אישר את סביבת העבודה ובדק את הסכמה, הוא יכול לעשות הרבה יותר מאשר להציג את הרכישות האחרונות.

### הריצו סקירת תקציב חודשית

```text
השתמש רק ב-sql_query כדי להשוות את ההכנסות וההוצאות בפועל לתקציב של החודש.
קבץ את ההפרשים לפי קטגוריה, הצב קודם את ההפרשים המוחלטים הגדולים ביותר,
והפרד בין נתוני תקציב חסרים לבין חריגה אמיתית. אל תשנה שום סעיף תקציב.
הצג את ה-SQL שבו השתמשת.
```

זאת הגרסה השיחתית של [סקירת תקציב חודשית](/blog/how-to-do-a-monthly-budget-review/): קודם מוצאים את הפער, ואז מחליטים מה צריך להשתנות.

### חפשו הוצאות כפולות אפשריות

```text
השתמש בסכמה העדכנית וב-sql_query כדי למצוא רשומות הוצאה כפולות אפשריות מ-45 הימים
האחרונים. השווה תאריכים, סכומים, מטבעות, חשבונות וצדדים נגדיים במקומות שבהם
השדות האלה קיימים. התייחס לתוצאות כאל מועמדות לבדיקה, ולא כאל כפילויות מאושרות.
אל תמחק או תעדכן דבר.
```

הניסוח "מועמדות לבדיקה, ולא כפילויות מאושרות" חשוב. שתי רכישות קפה זהות אינן בהכרח אותה עסקה שיובאה בטעות פעמיים.

### הכינו בדיקת התאמה חשבונאית

```text
השתמש ב-list_workspaces, אשר איתי את סביבת העבודה האישית שלי, בדוק את הסכמה
והרץ שאילתה על היתרות שזמינות דרך המחבר. הסבר אילו רשומות בספר החשבונות
מסבירות את היתרה העדכנית ביותר. אל תבצע תיקונים. אשווה את התוצאה בעצמי
לדף החשבון מהבנק.
```

כאשר יתרה אינה תואמת לדף החשבון המקורי, עצרו בנקודת הפער ובדקו את הסיבה. [תהליך התאמת התקציב ליתרת הבנק](/blog/how-to-reconcile-your-budget-with-your-bank-balance/) מסביר איך להפריד בין עסקאות חסרות, כפילויות, בעיות ביתרת הפתיחה והעברות לפני שמשנים את ספר החשבונות.

## התייחסו לכל פעולת כתיבה כאל משימה נפרדת

הרשאת כתיבה שימושית כשהיעד והתוצאה הרצויה ברורים: צריך לתקן קטגוריה של עסקה אחת, לרשום הוצאה שאושרה או לעדכן סעיף תקציב כפי שסוכם. שמרו על שינוי קטן שאפשר לבדוק, במקום לתת הוראה מעורפלת "לנקות הכול".

הנה הנחיה זהירה לשינוי הקטגוריה של עסקה אחת:

```text
אני צריך לתקן את הקטגוריה של רשומה אחת בספר החשבונות.

1. קרא ל-list_workspaces ואשר איתי את סביבת העבודה המיועדת.
2. קרא ל-get_schema במקום להניח מהם שמות העמודות.
3. השתמש ב-sql_query כדי למצוא את הרשומה המדויקת על סמך התאריך, הסכום, המטבע,
   החשבון ופרטי הצד הנגדי שאמסור לך.
4. אם אין בדיוק התאמה חד-משמעית אחת, עצור ושאל אותי מה לעשות.
5. הצג את משפט ה-SQL המדויק שאתה מציע עבור sql_execute, את מזהה סביבת העבודה,
   את הרשומה שנמצאה ואת ההשפעה הצפויה. אל תבצע אותו עדיין.
6. המתן לאישור מפורש ממני.
7. לאחר האישור, קרא ל-sql_execute פעם אחת. אחר כך הרץ sql_query חדש כדי לאמת
   את הערך שנשמר ודווח לי עליו.
```

כך שלוש ההחלטות נשארות גלויות: איזו סביבת עבודה, איזו רשומה ואיזה שינוי מדויק. האימות נעשה באמצעות קריאה חדשה אחרי השינוי, ולא באמצעות אמירה של Claude שהכתיבה כנראה הצליחה.

אותו מבנה מתאים גם לייבוא. בקשו מ-Claude לבדוק את הקטגוריות הקיימות ולחפש כפילויות אפשריות, להציג מראש את הרשומות שהוא מתכוון להוסיף ולהמתין לאישור מפורש. אחרי פעולות הכתיבה שאושרו, אמתו את הרשומות שנוספו ובצעו התאמה חשבונאית ליתרה שהתקבלה. אם הקלט הוא קובץ ייצוא מהבנק, המדריך [איך לייבא דפי חשבון למעקב הוצאות](/blog/how-to-import-bank-statements-into-an-expense-tracker/) מכסה את שלבי הבדיקה הנדרשים סביב קובץ המקור.

## צמצמו את הרשאות המחבר סביב נתונים פיננסיים

MCP מבטל את הצורך להעתיק מפתח לתוך הצ'אט, אבל אינו מבטל את הצורך בשיקול דעת. [הנחיות האבטחה למחברים של Anthropic](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) ממליצות להתחבר רק לשרתים מהימנים, לבדוק את ההרשאות המבוקשות ולשים לב לקלט ולפלט של הכלים.

במחבר הזה, ההמלצה מתורגמת לכללי פעולה קצרים:

1. ודאו שהכתובת היא בדיוק `https://mcp.expense-budget-tracker.com/mcp`.
2. התחילו עם `expenses:read`, אלא אם משימה מתוכננת מחייבת שינוי נתונים.
3. אשרו את סביבת העבודה לפני כל שיחה שכוללת כתיבה.
4. בדקו את הסכמה העדכנית לפני יצירת SQL.
5. עברו על המשפט המדויק ועל ההשפעה הצפויה לפני `sql_execute`.
6. אמתו את התוצאה באמצעות `sql_query` מיד לאחר מכן.
7. השביתו את `sql_execute` בבקרות הכלים של Claude, או השביתו את המחבר באותה שיחה, כשאינכם זקוקים לו עוד.

אל תבחרו ב-**Always allow** עבור `sql_execute`. הצגה של כל בקשת כתיבה בנפרד יוצרת נקודת עצירה מועילה לפני שהכלי משנה רשומות פיננסיות.

גם הערות פיננסיות ותיאורים שיובאו צריכים להישאר נתונים, ולא להפוך להוראות. אם טקסט שנשמר בעסקה מבקש מ-Claude להתעלם מהכללים שלכם או לקרוא לכלי אחר, אל תפעלו לפיו. זאת סיבה נוספת להשאיר את הרשאת הכתיבה כבויה במהלך שיחות רחבות של מחקר או ניתוח.

לפני ההתחברות, עיינו ב[מדיניות הפרטיות של Expense Budget Tracker](/privacy/) ובתנאים של Anthropic לטיפול בנתונים. שיחת Claude מורשית יכולה לקרוא את הנתונים הפיננסיים שזמינים לחשבון שלכם, ועם `expenses:write` גם לשנות אותם. החיבור המרוחק עובר דרך הענן של Anthropic והשירות המתארח של Expense Budget Tracker; ‏Claude Desktop אינו הופך אותו למסלול נתונים מקומי בלבד.

## פתרון תקלות בחיבור בלי לנחש

### המחבר המותאם אישית לא מתחבר

בדקו תחילה את נקודת הקצה. היא חייבת להיות:

```text
https://mcp.expense-budget-tracker.com/mcp
```

אל תחליפו אותה בכתובת האתר או בכתובת ה-API הישיר. השאירו את השדות Advanced OAuth Client ID ו-Client Secret ריקים עבור המחבר הזה. ודאו שיש לכם חשבון פעיל ב-Expense Budget Tracker. אם האימות עדיין נכשל, נתקו את השירות וחברו אותו מחדש דרך **Customize > Connectors**.

בחשבון Claude מסוג Team או Enterprise, שאלו Owner או Primary Owner אם המחבר המותאם אישית נוסף לארגון והותר לשימוש. חברים אחרים בארגון אינם יכולים לבצע בעצמם את ההגדרה הזאת ברמת הארגון.

### Claude אומר שהמחבר קיים, אבל אינו משתמש בו

הפעילו את Expense Budget Tracker עבור הצ'אט הנוכחי דרך התפריט **+ > Connectors**. לאחר מכן ציינו את שם המחבר בהנחיה ובקשו מ-Claude להתחיל ב-`list_workspaces`. מחבר שכבר הוגדר עדיין יכול להיות מושבת בשיחה מסוימת.

### `sql_execute` אינו זמין או שההרשאה נדחית

סביר שהרשאת ה-OAuth כוללת את `expenses:read` בלי היקף ההרשאה האופציונלי `expenses:write`. אם המשימה היא ניתוח, השאירו את ההרשאה כפי שהיא. אם משימה מסוימת שאושרה מחייבת שינוי נתונים, התחברו מחדש ובדקו את הרשאת הכתיבה המבוקשת לפני שתאשרו אותה.

### שאילתה נכשלת או מחזירה יותר מדי נתונים

קראו שוב ל-`get_schema` וצרו SQL על סמך היחסים והעמודות שהוחזרו. הקפידו שהבקשה תישאר בגבולות ממשק ה-SQL המוגבל של המחבר. בספרי חשבונות גדולים, חשבו סכומים, ספירות ותוצאות מקובצות ב-SQL במקום לבקש יותר ממגבלת 100 השורות. שאילתה שחורגת ממגבלת 20 השניות דורשת שאלה מצומצמת יותר.

### Claude בודק את הנתונים הפיננסיים הלא נכונים

עצרו לפני הכתיבה. קראו ל-`list_workspaces`, השוו בין השמות והמזהים שהוחזרו ואשרו במפורש את היעד. לאחר מכן קראו ל-`get_schema` עבור אותה סביבת עבודה וחזרו על הקריאה. הגישה מוגבלת לסביבות העבודה שזמינות למשתמש המחובר, אבל Claude עדיין צריך להשתמש בסביבה שהתכוונתם אליה.

### Claude מבקש `ApiKey`

הוא פועל לפי אינטגרציית ה-HTTP הישירה במקום לפי מחבר ה-MCP המרוחק. עבור ההגדרה הזאת, חזרו לכתובת המחבר ולתהליך ה-OAuth בדפדפן. אם אתם רוצים במכוון אוטומציה מהטרמינל או בקשות HTTP ישירות, השתמשו במקום זאת ב[מסמך העזר של Agent API](/docs/api/).

## ההגדרה קצרה; שגרת הבדיקה היא החלק החשוב

כדי לחבר את Claude ל-Expense Budget Tracker צריך כתובת אחת והתחברות בדפדפן. מה שחשוב לאורך זמן הוא השגרה שאחר כך: מציגים את סביבות העבודה, בודקים את הסכמה, קוראים לפני שכותבים, מעניקים את היקף ההרשאה המצומצם ביותר ומגדירים כל כתיבה באופן שאפשר לבדוק שורה אחר שורה.

התחילו עם [התיעוד המלא של מחבר MCP](/docs/mcp-connector/), הוסיפו את `https://mcp.expense-budget-tracker.com/mcp` תחת **Customize > Connectors** והריצו סקירה חודשית לקריאה בלבד. כשתצטרכו לבצע שינוי, בקשו מ-Claude להציג את סביבת העבודה, הרשומה, ה-SQL וההשפעה הצפויה לפני שתאשרו. כך מעקב הוצאות ב-Claude הופך מהדגמה נוחה לתהליך פיננסי שאפשר באמת לסמוך עליו.
